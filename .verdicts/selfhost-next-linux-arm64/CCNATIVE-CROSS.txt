FALSIFIER (pre-registered)
  build_native_linux_arm64 (#2575) builds cc_native NATIVELY-ONLY: there is no CROSS path to
  obtain an aarch64-linux compiler binary from a non-arm64-linux host. CLAIM: the SAME C
  translation unit (the flattened+transpiled compiler source ap_post.c) can be cross-compiled
  with aarch64-linux-gnu-gcc into an aarch64-linux cc_native ELF that RUNS under
  qemu-aarch64-static and can COMPILE a hexa program. FALSIFIED if: cross-gcc cannot build
  cc_native, OR cc_native cannot run under qemu, OR it cannot emit a runnable .o.

METHOD (C-cross path — NO codegen/emit edits; does NOT touch the self-emit codegen wall)
  Reuses build_native_linux_arm64 stages 1-3 BYTE-IDENTICALLY (host python3 flatten →
  host hexat transpile → s4/sed post-process + inline runtime.c + rt_fs/rt_array link-fills);
  the only deltas are stage4 CC (aarch64-linux-gnu-gcc, not native gcc) and the RUN wrapper
  (qemu-aarch64-static -L /usr/aarch64-linux-gnu). The emitted test program is linked against
  the cross runtime.a from tool/cross_build_runtime_linux_arm64 (#2574).

FINDING (🟢 — falsifier survived)
  The named #2575 wall is REMOVED. An aarch64-linux cc_native ELF is now obtainable by
  CROSS-compile from an x86_64-linux host (no aarch64 host needed for the COMPILER BINARY),
  it RUNS under qemu, and it COMPILES a hexa program whose emitted .o links against the
  #2574 cross runtime.a and runs to the correct rc (42) under qemu. Δ vs baseline: baseline
  had cc_native available ONLY on a native aarch64 host; now the full produce→run→compile
  loop is reproducible cross-host. The cc_native C build is host/target-agnostic in stages
  1-3 — only the compiler (CC) and the run wrapper (qemu) differ — so the cross delta is a
  ~3-line recipe change, confirming the bootstrap compiler has no native-only dependency.

RESIDUAL (named — OUT of this C-cross lane, unchanged by this work)
  TRUE full-self-emit (cc_native emitting ITS OWN flattened source to an aarch64 .o, the
  build_native --self-emit path) still hits the codegen wall:
    F-STP-ENCODE-MISS — `ENCODE-MISS: STP mem-parse-fail mem=#0`
    site: compiler/emit/macho_arm64.hexa — STP/LDP encode @541-566 → _parse_mem_op @1551
          rejects a bare `#0` operand (n<3 guard wants a leading "[").

  boundary FORBIDS editing compiler/emit/* / macho_arm64.hexa here. It is the deepest residual
  for true self-host and is owned by the codegen lane, NOT this C-cross lane. cc_native being
  C-built is precisely why this lane does NOT depend on that fix.

  FULL-SELF-EMIT REMAINING (named list):

  Both are codegen-lane items; this verdict closes the C-cross compiler-binary milestone only.
