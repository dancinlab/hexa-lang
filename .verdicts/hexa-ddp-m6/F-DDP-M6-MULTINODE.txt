The FP64 bytes cross the wire and must arrive bit-identical (TCP reliable +

Method: stdlib/ddp/m6_multinode/ring_tcp_m6.c — the EXACT M1/M3/M5 canonical
ring schedule (2(N-1) steps, chunk_start partition), per-step transport swapped
from cudaMemcpyPeer (intra-node GPU, M5) to host-to-host TCP sendall/recvall on
a ring socket. Each rank is a SEPARATE PROCESS ON A SEPARATE HOST; rank r
listens for predecessor and connects to successor. Parity ordering (even
send-then-recv / odd recv-then-send) makes the 2-cycle deadlock-free w/o threads.
M6 is a HOST-MEMORY FP64 ring (no CUDA) — it isolates the cross-node TRANSPORT
correctness; the GPU buffers are M3/M5's concern. If a byte flips crossing the
node boundary, max|delta| != 0.

FINDING: The hexa-native ring all-reduce DOES cross a real node boundary
byte-exact. The same 2(N-1)-step chunk-partition schedule proven on a single
node in M1 (in-process sim) -> M3 (cudaMemcpyPeer 2-GPU) -> M5 (4-GPU) holds
bit-for-bit when the per-step transport becomes a host-to-host TCP send/recv
between two datacenters in different countries. FP64 bytes crossing the public
Internet arrive bit-identical (TCP reliable+ordered), so max|delta| = 0 on

networking is NOT a wall for the collective's correctness — only its latency

small messages, but byte-eq is independent of latency). This closes DDP-M6.
