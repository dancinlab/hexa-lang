GATE (1) CORRECTNESS — 1-GPU W_ref == 4-GPU DDP W_ddp byte-eq (verbatim):
================= N=4 BYTE-EQ GATE (H=64) =================
loss_ref (mean)            = 317.98567392575933
grad  g_ddp vs g_ref  max|delta| = 0  BYTE-EQ
rank-agreement (Wr==W0) max|delta| = 0  ALL RANKS IDENTICAL
WEIGHTS W_ddp vs W_ref  max|delta| = 0  BYTE-EQ PASS

  -> max|delta| = 0 on the SUMMED grad, on every post-step WEIGHT, and across
     all 4 ranks (every rank holds the identical reduced grad). This is the M4
     DDP invariant (mean-loss grad = SUM of per-sample grads / B; split B over
     W ranks, all-reduce-SUM the per-rank partials, /B on every rank => the
     exact 1-GPU grad) extended from N=2 to N=4.

  FP-ASSOCIATIVITY NOTE (the real engineering content of the N=4 gate): FP add
  is NOT associative, and the ring reduce-scatter sums each chunk's 4 rank-
  partials in a CHUNK-DEPENDENT RIGHT-NESTED tree, NOT a flat left fold. A 4-rank
  simulation of the DDP-M1 ring schedule's actual `d += staging` parenthesization
  gives, for chunk c (sequence s[j]=(c-1-j+2N)%N):
        chunk 0 = (3+(2+(1+0)))   chunk 1 = (0+(3+(2+1)))
        chunk 2 = (1+(0+(3+2)))   chunk 3 = (2+(1+(0+3)))
  A naive left-to-right reference (((g0+g1)+g2)+g3) differs from this at the ULP
  (measured residual 1.42e-14 then 3.55e-15 on this node before the fix) — that
  residual was PURE associativity, not a transport error. Reducing the 1-GPU
  reference with the SAME per-chunk right-nested tree drives the gate to a TRUE
  max|delta|=0 (this is the honest DDP-equivalence definition: same partials,
  same reduction tree). N=2 has a single add so M4 was trivially order-invariant;
  the tree only bites at N>=3, which is why this gate is the genuine N=4 content.

CROSSOVER: 4-GPU speedup never exceeded 1.0x across the swept H (still comm-bound
  on this host-staged transport). BUT the efficiency rises MONOTONICALLY with
  model size — 4-GPU eff 15.2% -> 15.5% -> 17.2% -> 18.1% as H 64 -> 2048, and
  2-GPU eff 40-45% trending up. The compute-per-step (~H^2 FLOPs) is amortizing
  the fixed comm tax; extrapolating the trend, 4-GPU would cross 1.0x only once
  per-step compute >> the host-staged all-reduce of NPARAM FP64 words — which on
  THIS node needs a much larger model and/or a real P2P/NVLink fabric (see
  transport). The DIRECTION is measured and correct; the absolute crossover is
  out of reach on a host-staged GeForce node at B=64.

HONEST FINDING (g5/g83): On a 4x RTX 3090 GeForce node with NO NVLink (all P2P
host-staged), 4-GPU data-parallel TRAINING is CORRECT to the last bit (max|delta|
=0, N=4) but does NOT yet speed up a small model — 4-GPU is 0.61x-0.73x of 1-GPU
(eff 15-18%), i.e. SLOWER, because the host-staged all-reduce of the FP64 grad
costs more than the per-step compute saved by sharding B=64. This is the expected
Amdahl/comm reality, NOT a failure: N-GPU speedup is always < N x, and on a
host-staged transport with a small model comm > compute. The efficiency rises
monotonically with model size (15.2% -> 18.1% as H 64 -> 2048), so the crossover
where 4-GPU wins requires (a) a substantially bigger model (more compute/step to
amortize the fixed comm) and/or (b) NVLink/direct-P2P (cheaper comm). Both are
measured directions here, not asserted. The CORRECTNESS leg is the durable
result: the M4 DDP invariant holds byte-exact at N=4 (with the correct ring
right-nested reduction tree), which is what makes 4-GPU DDP training "correct" at
any scale.
