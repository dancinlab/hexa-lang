DRIVER (self/native/hxqwen14b_llmstep_driver.cu — committed)
------------------------------------------------------------
Standalone driver that #include's the shipped self/native/hxqwen14b_cuda.cu (so the
EXACT main-branch WMMA2 kernel _hx_k_sgemm_cm_wmma2 + the env-gated dispatch shim
hxqwen_sgemm_base + the v53/v54 glue kernels are measured, no drift). A "full LoRA
step" = LoRA fwd (2 GEMMs, = hxqwen14b_lora_fwd_single device path) + LoRA bwd (5
GEMMs, = lora_bwd_single) + the transformer GLUE that wraps a LoRA-adapted projection
in a real Qwen block: v53_rmsnorm (pre-norm) + v53_swiglu (FFN activation) +
v54_residual_add + a softmax-CE loss head. All GEMMs route through hxqwen_sgemm_base,
which reads HEXA_OWN_GEMM[/_WMMA2] EXACTLY as the shipped trainer does. cuBLAS arm runs
CUBLAS_TF32_TENSOR_OP_MATH so the compare is cuBLAS-TF32 vs WMMA2-TF32 (fair precision).

(3) PROMOTION + CI REGRESSION GATE
--------------------------------------------------------------------------------
PROMOTION: WMMA2 is documented as the RECOMMENDED own LLM GEMM via the existing
env gate (NO silent global default flip — convergence is within tol but the GPU is
billable + Blackwell-only-tested, so we keep cuBLAS as the zero-config default and
make WMMA2 an opt-in documented flag):
    HEXA_OWN_GEMM=1 HEXA_OWN_GEMM_WMMA2=1   -> CUTLASS-grade WMMA2 own-GEMM (TF32)
    (unset)                                 -> cuBLAS Sgemm (default, byte-identical)
TF32 TRADEOFF (documented): WMMA2 uses TF32 Tensor-Core accumulation (~10-bit
mantissa input rounding) -> rel-RMS ~4e-4 vs cuBLAS FP32, descent identical to 1e-4.
This is the approved precision tradeoff; the cuBLAS fallback stays bit-for-bit FP32.

CI GATE: tool/hexa-fusion/llm_own_gemm_gate.sh (committed, standalone). Builds the
driver, runs ONE process computing y/dA/dB/dx under cuBLAS (oracle) AND WMMA2 (own),
fails (exit 1) if any output's rel-RMS exceeds tol (default 3e-3, HEXA_GATE_TOL
overrides). SKIP (exit 0) on a host with no nvcc/GPU so a CPU CI lane is not broken.
