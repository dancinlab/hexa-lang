ROOT CAUSE (definitive, device-queried):
  WMMA2 kernel STATIC __shared__ = 57344 B (56 KB)   [As[2][128*32] + Bs[2][32*64], padded]
  sm_90 device sharedMemPerBlock (STATIC cap)        = 49152 B (48 KB)
  sm_90 device sharedMemPerBlockOptin (DYNAMIC cap)  = 232448 B (227 KB)
  56 KB static > 48 KB static cap  =>  CUDA rejects the launch with cudaErrorInvalidValue.
  The kernel uses STATIC __shared__ and does NOT call cudaFuncSetAttribute(
  cudaFuncAttributeMaxDynamicSharedMemorySize, ...), so it cannot opt into the 227 KB dynamic
  pool. On Blackwell sm_120 (where the 1.13× was measured) the static cap is larger / the
  PTX-JIT path admitted it, so it launched there — on native sm_90 it is un-launchable as shipped.

TENSOR-CORE SASS (the kernel CODE is correct; only the launch config is rejected):
  cuobjdump -sass of _Z20_hx_k_sgemm_cm_wmma2... : 64 HMMA (Tensor-Core MMA) + 116 FFMA.
  → The WMMA2 kernel DOES compile Tensor-Core MMA ops into native sm_90 SASS. The TC path is
    present in the binary; it simply never runs because the block can't be launched.
