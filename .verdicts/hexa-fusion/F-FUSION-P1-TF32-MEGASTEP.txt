This work AUTHORS the launcher (self/cuda/runtime_cuda_emit.hexa, the emitter SSOT):
  · _hx_k_clm_megafwd — ONE cudaLaunchCooperativeKernel persistent grid running the
    whole fwd DAG: conv(xe→xec) → conv(xec→h0) → [groupnorm#1→gelu→residual] →
    conv-router(xt→logits_r) → conv-experts×2(xt→eo0,eo1) → [gelu2→pack→softmax-
    combine] → groupnorm#2. ALL 4 conv GEMMs PULLED INSIDE as TF32 own-GEMM
    (_hx_dev_conv_tf32: operands rounded f64→TF32 via the 13-low-mantissa-bit mask,
    f32 FMA accumulation — the authorized precision); im2col folded into the inner
    loop (causal-dilated). Glue blocks + both groupnorms keep the host SEQUENTIAL
    reduction order (groupnorm = G=1 whole-[T,D] reduction in thread 0 then grid.sync
    + parallel apply), so the ONLY precision delta vs eager FP64 is the GEMM
    accumulation. Intermediates device-resident across grid.sync() — no relaunch gap.
    Bwd intermediates (hn0/xhat0/inv0/eo0/eo1/probs/ex_out/yn/xhatN/invN) written
    byte-for-byte so clm_prod_bwd is UNCHANGED; only conv(yn→out_logits) stays eager.
  · _hx_cuda_farr_clm_megafwd_gpu — the launcher: checks cudaDevAttrCooperativeLaunch,
    H2Ds inputs, dev-allocs outputs, sizes the grid to fill the SMs
    (cudaOccupancyMaxActiveBlocksPerMultiprocessor × SM count), cudaLaunchCooperative
    Kernel, marks outputs FARR_DEVICE. Returns -1 (→ eager FP64 fallback) if no coop
    launch. assert_eq ignored (TF32 path — the precision relaxation IS the point).
  · build: nvcc -x cu -DHEXA_CUDA -rdc=true -arch=sm_90 (rdc REQUIRED for
    cooperative_groups grid.sync) + -dlink + -lcudadevrt.
