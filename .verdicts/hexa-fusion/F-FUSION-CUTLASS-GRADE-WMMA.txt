TECHNIQUES APPLIED (the standard GEMM optimizations the naive WMMA lacked):
  • Block tile BM=128 × BN=64 × BK=32, computed by an 8-warp (256-thread) block.
  • Warp tiling: warps laid out 4(row)×2(col); each warp owns a 32×32 warp-tile = a 2×2 grid
    of 16×16 WMMA frag ops → 4 register accumulator fragments held across the WHOLE K loop
    (no shared round-trip of partial sums; the naive kernel re-stored C every K-step).
  • Per-warp A/B fragments: 2×4 (FM×FK) and 4×2 (FK×FN), TF32 frag K-dim = 8 (HXG_FK = BK/8 = 4).
  • Double-buffered shared-memory pipeline: while WMMA computes on buffer p the next BK-slice is
    staged into buffer 1-p; on sm_80+ the global→shared copies use cp.async (cp.async.ca + commit/
    wait_group) to overlap global load with WMMA compute; manual double-buffer fallback otherwise.
  • op(A)/op(B) transpose (tA/tB) + edge zero-pad handled while STAGING into __shared__ as a fixed
    row_major layout → one WMMA load path (no 4-variant template), bounds-guarded.
  • Register accumulators; epilogue applies alpha/beta + COL-MAJOR store (cublasSgemm semantics
    C[i+j·ldc]=α·Σ op(A)·op(B)+β·C preserved). fp32→tf32 rounding (~10-bit mantissa).
