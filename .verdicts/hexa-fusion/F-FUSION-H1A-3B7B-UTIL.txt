FINDING (Δ vs baseline — supersedes the premise of the question):
  The ~13% idle-H100 baseline (F-FUSION-OCCUPANCY-WALL / handoff 80d47ccc) is NOT a
  property of the D1536 GEMM WORKLOAD — it is a property of clm_prod's per-kernel
  SYNCHRONIZED serial DAG. The SAME byte-identical own-GEMM(WMMA2) + glue step, run
  back-to-back with a sync only every 16 iters, saturates an idle H100 to MEDIAN
  100% util at D=1536 — the very shape D2 framed as "too small for the H100".
  So the size axis is NOT the lever: bigger D does not change a saturated-already
  picture (it only lowers steps/s as the GEMMs get more expensive: 8307→477 own).
  The util ceiling for the anima forge is therefore the DAG-SCHEDULING / per-kernel
  sync structure inside clm_prod, NOT model size and NOT a right-sized-GPU question.

  IMPLICATION FOR ANIMA 3B/7B:
