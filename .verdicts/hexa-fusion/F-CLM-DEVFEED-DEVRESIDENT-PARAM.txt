HEXA-FUSION L1 (PARAM half) — device-resident int4-quant weight lifetime (W).

Stacked on PR #2559 (db bias-grad device-resident, itself on #2555 m,v). This is
the CRUX slice of full device-residency: param W was int4-quantized on the HOST
every forward (clm_prod._fq → nn_int4_quant_fwd), which forced W D2H every step,
and the STE mask-multiply backward (nn_int4_quant_bwd) read the grad on host —
so W and dW could not stay device-resident. This slice moves both onto device:

  · forge_dispatch_int4_quant(w, wq, sc, ql, mask, Cout, rest) → device kernel
    _hx_cuda_farr_int4_quant_gpu: one thread per output channel computes the
    per-channel int4-sym[-7,+7] QAT forward (s=max|W|/7, q=clamp(round(W/s),±7),
    Wq=q·s, mask=in-range). The per-channel max scan + integer round/clamp are
    SEQUENTIAL — NO fp reduction re-association, and int4 is INTEGER, so the
    device quant is BIT-EXACT to nn_int4_quant_fwd (max|Δ| MUST be exactly 0, no
    FMA-drift excuse). Keeps W loc=FARR_DEVICE (no per-step W D2H) and
    wq/sc/ql/mask FARR_DEVICE / dirty_host=0 (the GEMM reads Wq on device; mask
    feeds the device STE bwd).
  · forge_dispatch_int4_quant_bwd(dy, mask, dW, n) → _hx_cuda_farr_int4_quant_
    bwd_gpu: dW[i] = dy[i]·mask[i] (clipped STE), a pure elementwise multiply
    with NO reduction → bit-exact, and keeps dW FARR_DEVICE so the next _adam
    H2D-skips the grad (the int4 W grads escape only into _adam).

Same residence convention as the keepmv moments / db colsum. Env CLM_PROD_DEV-
RESIDENT (default off → host fake-quant, byte-identical). NO raw-GEMM-win claim
— strictly host-roundtrip removal (W stays resident); cuBLAS GEMM = roofline.
