METHOD

  Deltas vs _hx_k_sgemm_cm_wmma2 (BM=128 BN=64 BK=32, 8 warps, 2x2 warp-tile, register

  + shared layout, not the tiling):
    (1) N-STAGE cp.async RING (HXG_MS_STAGES=3): prefetch STAGES-1 slices ahead, each its
        own cp.async group; consume via cp.async.wait_group STAGES-2 (=1 for 3 stages) so
        the oldest in-flight slice has landed while STAGES-2 newer DRAM->shared copies stay
        in flight, hidden behind Tensor-Core compute. Ring buffer in DYNAMIC shared
        (extern __shared__) so STAGES x (As+Bs) can exceed the 48KB static cap; launcher
        opt-ins cudaFuncAttributeMaxDynamicSharedMemorySize (87KB/block @ stages=3).
    (2) BANK-CONFLICT-FREE SKEWED SHARED: pad the shared row stride by HXG_SKEW=8 floats
        (As 32->40, Bs 64->72) so the 16-row WMMA load_matrix_sync spreads across all 32
        banks instead of aliasing the same banks each row. This is a UNIFORM leading-dim
        stride, so it stays load_matrix_sync-compatible (an XOR per-row swizzle is NOT —
        the nvcuda::wmma API takes a single base ptr + constant ldm and cannot express a
        per-row column permutation; the skew achieves the same bank-spread legally). Math
        is identical — only the shared address map changes.
