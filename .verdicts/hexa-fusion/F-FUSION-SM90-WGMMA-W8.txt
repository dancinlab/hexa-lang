THE W7 DIAGNOSIS (F-FUSION-SM90-WGMMA-W7): MODE 3 regressed 50.7->32.0 because its PRODUCER
is a full 128-thread cp.async warpgroup. That 384-thread CTA is REGISTER-BOUND to 1 block/SM

compute-thr/SM vs the simple async-pipe's 512 (4 CTAs * 128). HALF the compute occupancy.

THE W8 FIX (diagnosed-correct lever): replace the thread-heavy cp.async producer warpgroup
with a HARDWARE TMA producer driven by a SINGLE ELECTED THREAD.
  GEOMETRY: TM=128, TN=128, TK=8. 256 threads = 2 warpgroups, BOTH consumers (NO dedicated
    producer WG). thread 0 (elected) issues cp.async.bulk.tensor.2d for the A-band (128x8) +
    B (8x128) into an NST-deep ring; mbarrier.arrive.expect_tx tracks the TMA byte count;
    the TMA HW engine does the global->shared copy with ~0 consumer threads spent on the load.
  All 256 threads then mbar_wait(full[stage]) on TMA arrival, cooperatively permute the TMA-
    landed row-major Araw/Braw -> gmma INTER 8x4 layout (the W1/W2-proven bit-exact layout —
    same mk/gmma_phys/WG descriptors as MODE 0..3, ONLY the production engine changed), then
    each warpgroup issues its 2 wgmma.mma_async over its 64-row A band x the SHARED B tile.
  empty[] mbarrier (arrive count 256) lets the elected thread re-arm each ring stage's next
    TMA load after both WGs finished the wgmma.
