🔴 BUG (parse_query) — DIFFERENTIAL vs urllib.parse.parse_qsl(keep_blank_values=True)
--------------------------------------------------------------------------------
UNFIXED body (origin/main stdlib/net/http_request.hexa):
    let kv = pairs[i].split("=")
    if len(kv) >= 2 { result[kv[0]] = kv[1] }      // takes ONLY the first value seg
    else { if len(kv) == 1 { result[kv[0]] = "" } }// empty pair -> spurious "" key

hexa split semantics confirmed on the SHIPPING `hexa run` (summer pool, 0.1.0-dispatch):
    "a=b=c".split("=")   -> ["a","b","c"]   (len 3)
    "a=1&&b=2".split("&")-> ["a=1","","b=2"] (len 3, empty middle)

VERBATIM differential (faithful Python port of the UNFIXED body vs CPython parse_qsl,
dict form last-write-wins to match map assignment):
    input        hexa(unfixed)                cpython                      match
    'a=1&b=2'    {'a':'1','b':'2'}            {'a':'1','b':'2'}            OK
    'a=b=c'      {'a':'b'}                    {'a':'b=c'}                  MISMATCH  <-- BUG 1
    'a==b'       {'a':''}                     {'a':'=b'}                   MISMATCH  <-- BUG 1
    'key'        {'key':''}                   {'key':''}                   OK
    'key='       {'key':''}                   {'key':''}                   OK
    '=val'       {'':'val'}                   {'':'val'}                   OK
    'a=1&a=2'    {'a':'2'}                    {'a':'2'}                    OK
    'a=1&&b=2'   {'a':'1','':'','b':'2'}      {'a':'1','b':'2'}            MISMATCH  <-- BUG 2
    'flag&x=1'   {'flag':'','x':'1'}          {'flag':'','x':'1'}          OK

And VERBATIM on the SHIPPING `hexa run` (summer), the UNFIXED body:
    a=b=c    -> a=[b]               (CPython: 'b=c')
    a==b     -> a=[]               (CPython: '=b')
    a=1&&b=2 -> keycount=3         (CPython: 2 keys — empty pair skipped)
    a=1&     -> keycount=2         (CPython: 1 key — trailing & = empty pair, skipped)

ROOT CAUSE:
  BUG 1 — value truncation: `.split("=")` shatters the whole pair on EVERY "=", and the
          code keeps only kv[1], dropping any "=" that legitimately belongs INSIDE the value.
  BUG 2 — spurious blank key: an empty pair (from "&&" or a trailing/leading "&") yields a
          "" segment whose `"".split("=")` has len 1, so the code inserts result[""]="" —
          a key CPython never produces (it skips empty pairs).

--------------------------------------------------------------------------------
FIX (minimal, provably-correct — matches parse_qsl(keep_blank_values=True); 0 deletions)
--------------------------------------------------------------------------------
    let pair = pairs[i]
    if len(pair) > 0 {                         // skip empty pair  -> closes BUG 2
        let eq = pair.index_of("=")
        if eq >= 0 {
            // split on the FIRST "=" only      -> closes BUG 1
            result[pair.substring(0, eq)] = pair.substring(eq + 1, len(pair))
        } else {
            result[pair] = ""
        }
    }
