THE GAP (OP-16 #2995 family, the remaining 2 dispatchers)
────────────────────────────────────────────────────────────────────────────
The L3 fused-dispatch FAMILY — forge_dispatch_gelu2 (L3-b), groupnorm_gelu
(L3-a), moe_block2 (L3-d) — is supplied ONLY by the GPU build's fusion_dispatch.c
glue (launcher + `#ifdef HEXA_CUDA`, see
.verdicts/hexa-fusion/p1b-aprime2-build/fusion_dispatch.c). Off-CUDA those bare
symbols are UNDEFINED, so a `hexa run` harness that drives the fused paths
(clm_prod.hexa _gelu2 / _moe_block2, which emit the bare symbol unconditionally
via codegen) FAILS TO LINK before any code runs:
    Undefined symbols for architecture arm64:
      "_forge_dispatch_gelu2", referenced from: …
      "_forge_dispatch_moe_block2", referenced from: …
OP-16 added the host twin for groupnorm_gelu ONLY; gelu2 + moe_block2 were still
host-undefined → still 0-GPU blind spots. OP-18 closes them, completing the family.

────────────────────────────────────────────────────────────────────────────
THE FIX — HOST BODY LOCATION + IDIOM
────────────────────────────────────────────────────────────────────────────
LOCATION: self/runtime.c, as `#ifndef HEXA_CUDA` definitions of the BARE symbols,
immediately after OP-16's forge_dispatch_groupnorm_gelu host block (same TU, same
bare-wrapper-seam idiom — extract farr ids via hexa_as_num, reject bad ids/dims,
read _hx_farr_table[id].buf, return hexa_int(0)/(-1)). `#ifndef HEXA_CUDA` is
deliberate: under HEXA_CUDA fusion_dispatch.c supplies the symbol, so guarding the
host body off-CUDA avoids a duplicate symbol AND leaves the GPU dispatch path
byte-identical to today (GPU path UNCHANGED).

SEMANTICS = the UNFUSED reference each fused helper falls through to in
clm_prod.hexa, character-for-character:

  gelu2(g0,a0,g1,a1,n)  — two erf-GELU passes:
     a0[i] = GELU(g0[i]),  a1[i] = GELU(g1[i]),   i in 0..n
     GELU(x) = x · 0.5·(1 + erf(x · (1/√2))),  1/√2 = 0.70710678118654752440
     == two nn_gelu_fwd (the clm_prod.hexa _gelu2 off-CUDA fall-through).

  moe_block2(eo0,eo1,logits,ex0,ex1,ex_out,probs,y,T,E,C) — the 3-helper chain:
     (1) gelu2 : ex0 = GELU(eo0), ex1 = GELU(eo1)   (n = T·C)
     (2) expert_pack2 : ex_out[0·n+j]=ex0[j], ex_out[1·n+j]=ex1[j]   (E=2 stack)
     (3) moe_router : softmax over E experts replaying moe_lib _moe_exp
         (scaled-Taylor range reduction x=n·ln2+r, 14-term, 2^n by mul/div —
         NOT libm exp) with PER-POSITION MAX-SUBTRACTION + SEQUENTIALLY-SUMMED
         denom, then y[t,c] = Σ_e probs[t,e]·ex_out[e·T·C+t·C+c] in e-ASCENDING
         order. == nn_moe_router_fwd. This is OP-8's (#2993) PROVEN canonical
         order; the host body reuses it verbatim. E!=2 → returns -1 (caller falls
         through to its own E-generic host helpers, also byte-eq).

BYTE-EQ CURE (OP-16's lesson, applied): both bodies are wrapped in
    #pragma STDC FP_CONTRACT OFF … #pragma STDC FP_CONTRACT DEFAULT
because hexa codegen emits NON-contracted sequential rounding (no a·b+c fused into
one fma) but clang -O2 FMA-contracts (the affine gamma·xhat+beta in groupnorm_gelu,
the GELU x·0.5·(1+erf), the router combine acc+p·x). Without it the low bit can
diverge ~1 ULP from the hexa unfused reference; with it, max|Δ| = EXACTLY 0. The
shared helpers _op18_gelu / _op18_moe_exp / _op18_gn_sqrt live inside the same
FP_CONTRACT-OFF region.
