🔴 BUG (REAL, SHIPPING) — stdlib/alloc/path.hexa :: path_dirname
--------------------------------------------------------------------------------
path_basename strips trailing slashes (matches GNU `basename`), but
path_dirname did NOT collapse the consecutive *separator* slashes before the
final path component, leaking a stray trailing "/" into its result.

VERBATIM repro (faithful Python port of the UNFIXED body vs GNU `dirname`):
    dirname('a//b')            = 'a/'           (GNU: 'a')            BUG
    dirname('/foo//bar///baz') = '/foo//bar//'  (GNU: '/foo//bar')   BUG
    dirname('x///y')           = 'x//'          (GNU: 'x')           BUG
    dirname('/a//b//c')        = '/a//b/'       (GNU: '/a//b')       BUG

ROOT CAUSE: on finding the boundary '/' at index i, the body returned
`p.substring(0, i)` directly without skipping back over any additional
consecutive '/' separators, so repeated internal slashes left a dangling
separator in the dir portion. Internally inconsistent: path_basename DOES strip
them (it is GNU-correct on all 13 probed cases).

CROSS-CHECK (g5): differential vs GNU coreutils `dirname` over 24 inputs — the
unfixed body diverged on the 4 repeated-internal-slash cases above; everywhere
else (single-slash, trailing-slash, root, relative) it already matched GNU.

FIX (minimal, behavior-correct — provably the bug, matches the module's own
basename + POSIX/GNU dirname): after locating the boundary '/', skip back over
consecutive separator slashes before returning.

    while i >= 0 {
        if p[i] == '/' {
            while i > 0 { if p[i - 1] != '/' { break } i = i - 1 }   // ADDED
            if i == 0 { return "/" }
            return p.substring(0, i)
        }
        i = i - 1
    }

POST-FIX: the fixed body matches GNU `dirname` on all 24 sweep inputs, and does
NOT regress any single-slash case — the seven self/test_path_module.hexa cases
(/a/b/c→/a/b, a/b/→a, a→., /a→/, /→/, ""→., a/b/c→a/b) all still pass.
No in-tree caller of the canonical alloc/path::path_dirname depends on the
buggy double-slash output (scoped grep, NO .git) — fix is regression-safe.
