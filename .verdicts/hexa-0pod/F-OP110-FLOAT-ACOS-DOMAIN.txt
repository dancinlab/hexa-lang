CLASS (FRESH — not previously swept)
------------------------------------
A float-DOMAIN error: an inverse-trig call acos(x)/asin(x) reached with |x|>1, or a log(0)/
sqrt(-x)/0.0-÷ producing Inf/NaN, that then PROPAGATES SILENTLY into a public result. Per
g5 a site is CLEAN if x is provably in-domain (clamped before the call, or bounded by exact
construction), and a real 🔴 only if a plausible input drives the argument out of domain and
the documented contract forbids the resulting NaN. Distinct from OP-103/106 (OOB/degenerate
INDEX-or-div-by-0 CRASH): here there is no crash — acos(>1) returns a silent NaN that
corrupts the answer.

THE BUG  🔴  stdlib/crystal/mod.hexa  lattice_angles
----------------------------------------------------
pymatgen-port lattice_angles(L) returns (α,β,γ) in degrees via the cosine law
  cos α = (b·c)/(|b||c|),  α = acos(cos α)·180/π   (and β,γ).
The cosine ratios were passed to acos with NO clamp and NO zero-denominator guard. Two
plausible inputs drive acos out of [-1,1] → NaN:
  (1) (near-)COLLINEAR lattice vectors: dot/(|u||v|) overflows 1.0 by ~1e-16 of fp roundoff.
      A random sweep of 2e6 collinear vector pairs (Python signed-64 ref) → cos up to
      1.0000000000000004, ~10% (215205/2e6) exceed 1.0.
  (2) a zero-LENGTH lattice vector (degenerate cell) → denom 0 → ratio Inf → acos(Inf) = NaN.
The sibling chem/md/bonded.hexa angle_energy computes the IDENTICAL cos θ = dot/(|u||v|) and
DOES clamp (`if c>1.0 {c=1.0}; if c<-1.0 {c=-1.0}` before acos); wgs84_kernel.hexa haversine
likewise clamps √a∈[0,1] before asin with the documented "antipodal-roundoff clamp so asin
doesn't NaN". lattice_angles was the one inverse-trig site missing the guard.

VERBATIM REPRO (shipping `hexa run` 0.1.0-dispatch, hermetic verbatim-inlined UNFIXED body)
------------------------------------------------------------------------------------------
Input: collinear lattice a=[1,0,0], b=[-0.4969649763063986,-0.4664928284510319,4.548027195441373],
       c = 0.9525597121912246·b  (b∥c ⇒ true α = 0°).

libm acos hexa binds to returns NaN on exactly this argument. (Hexa's stdlib SOFTWARE
rt_acos in runtime/math.hexa DOES clamp |x|>1 → ±π/2, but per governance @D stdlib_trig_libm
stdlib trig = the libm BUILTIN acos, which is what lattice_angles binds — NaN, confirmed.)

FIX (minimal, net-additive; clamp the cosine to [-1,1] before acos)
-------------------------------------------------------------------
Added a leaf helper + 3 call-site rewrites in stdlib/crystal/mod.hexa:
  fn _crystal_clamp_unit(dot, denom) -> float {
      if denom == 0.0 { return 1.0 }        // degenerate zero-length vector → cos 1 (angle 0)
      let cos = dot / denom
      if cos > 1.0 { return 1.0 }
      if cos < 0.0 - 1.0 { return 0.0 - 1.0 }
      return cos
  }
  let alpha = acos(_crystal_clamp_unit(bc, nb*nc)) * 180.0 / pi   (and β,γ)
RATIONALE: clamp to [-1,1] is the standard cosine-law numerical guard (matches the sibling
angle_energy + wgs84 haversine); denom==0 → cos 1.0 (angle 0°) is the collinear limit the
roundoff overflow approaches — least-surprising saturation. OUTPUT shape (3 angles) preserved.
