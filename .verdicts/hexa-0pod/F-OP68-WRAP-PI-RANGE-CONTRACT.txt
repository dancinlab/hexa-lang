THE BUG (verbatim)
------------------
wrap_pi(x) reduces an angle into the CLOSED interval [−π, π], preserving BOTH
boundaries (fast-path guard returns ±π unchanged; the +π/−π boundary value is
sign-selected). The body comment + the passing self-test agree:

  src body  : "// ── reduce angle (rad) into [−π, π] ──"  "preserving BOTH boundaries
              ... a literal +π input returns +π, a literal −π input returns −π."
  src guard : `if x >= 0.0 - p && x <= p { return x }`   // returns −π unchanged
  test      : check_exact("wrap_pi(-π) == -π (boundary)", wrap_pi(0.0 - p), 0.0 - p)
              → PASS (full suite 12/12 PASS pre-fix)

But the SURFACE doc (the contract a consumer reads) claimed a HALF-OPEN codomain
(−π, π] that EXCLUDES −π, with an explicit false negation:

  L13 : "//   pub fn wrap_pi(x: float) -> float    // (−π, π]"
  L16 : "//   Maps any real x to the unique representative in (−π, π], i.e. +π
  L17 :  //   stays at +π (NOT at −π)."        ← FALSE: −π IS preserved, IS reachable

The (−π, π] form is the FLOORED-MODULO convention, which lines 21–23 themselves say
this primitive does NOT use ("would map +π → −π ... we instead reduce to [0,2π) and
shift only if > π"). So the surface doc described the WRONG algorithm's codomain. A
consumer trusting "(−π, π], NOT −π" could write a downstream branch assuming wrap_pi
never returns −π — a latent correctness trap at the lower boundary.

FIX (doc + test only — NO behavior change)
------------------------------------------
1. stdlib/core/math/wrap_pi.hexa — corrected the 3 surface/convention lines (L13,
   L16–17) from the half-open (−π, π] "NOT −π" claim to the true CLOSED interval
   [−π, π], stating both boundaries are preserved and sign-selected, and noting the
   floored-modulo form (which WOULD collapse −π→+π) is explicitly NOT used. Line 34's
   "(−π, π)" (the open INTERIOR for non-boundary inputs) is correct and untouched.

2. stdlib/core/math/wrap_pi_test.hexa — fixed the stale "(−π, π]" comment on the
   idempotence check, and ADDED a machine-lock of the corrected contract:
     · a 400-point sweep across many revolutions (both signs, non-grid stride)
       asserting every output ∈ [−π, π] (closed bound never escaped);
     · an explicit check_exact "wrap_pi(−π) ∈ codomain (closed [−π,π])" pinning the
       lower boundary that the old surface doc wrongly excluded.
