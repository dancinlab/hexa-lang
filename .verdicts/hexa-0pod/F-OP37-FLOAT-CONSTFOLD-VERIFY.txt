ROOT CAUSE (the smoking gun — verbatim emitted C, Jun-8 hexat)
────────────────────────────────────────────────────────────────────────────
The const-folder fires only when the expr is an INLINE call argument (not a
`let` binding). For `dump(L, 0.0 - 0.254829592)` the Jun-8 hexat emitted:
    dump(__hexa_sl_12, hexa_float(-0.25483));      ← TRUNCATED to 6 sig digits
    dump(__hexa_sl_14, hexa_float(-1.42141));
(while the `let nN = 0.0 - X` lines kept full precision: hexa_float((0.0)-(...))).

Two bugs in self/codegen.hexa's comptime_eval const-folder:
  BUG-1 (serialize). Folded floats were re-serialized via `to_string(<float>)`,
    which renders "%g" = 6 significant digits (runtime_core.c:6268, round-trip
    LOSSY). Sites: UnaryOp `-`, BinOp + - * /, abs, sqrt, min/max.
  BUG-2 (parse). The fold loaded operands via `_cf_as_float` → `to_float`
    (hxlcl_atof / rt_str_parse_float) — a NAIVE digit-accumulator
    (n=n*10+d; frac*=0.1), NOT a correctly-rounded strtod. PROVEN:
      lit  0.254829592 = [126 90 236 198 32 79 208 63]   (lexer, exact)
      atof 0.254829592 = [127 90 236 198 32 79 208 63]   (to_float, 1 ULP off)
    So even with full-precision serialization the operand was already 1 ULP
    wrong before any arithmetic.

────────────────────────────────────────────────────────────────────────────
THE FIX (self/codegen.hexa — additive, minimal, no deletions)
────────────────────────────────────────────────────────────────────────────
1. `_cf_float_node(f)` helper — serialize folded floats with
   format_float_sci(f, 17) ("%.17e", round-trippable for ALL magnitudes
   incl. subnormal/±0/1e308). Replaces every `_make_float_lit_node(to_string(
   <float>))` site (UnaryOp -, BinOp + - * /, abs, sqrt, min/max). Cures BUG-1.
2. `_cf_negate_float_text(s)` helper + additive-identity special-cases — for
   `-FloatLit`, `0.0 - X`, `X - 0.0`, `0.0 + X`, `X + 0.0` the result is the
   operand at the SAME magnitude (sign-flipped for negation), so we preserve
   the operand's EXACT source text and just toggle the leading "-". Zero parse,
   zero re-serialize → BYTE-EXACT. Cures BUG-2 for the dominant `0.0 - X` idiom
   (the exact form that triggered OP-36, A&S erf coefficients).
