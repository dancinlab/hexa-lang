CLASS
-----
Arithmetic that OVERFLOWS (a sum/product/shift/hash-mix exceeding i63 → wraps to a
wrong/NEGATIVE value) OR has a SIGNEDNESS bug (a `% n` of a negative dividend giving a
negative result where a non-negative index/range was intended; a right-shift sign-
extension). Hexa ints are 64-bit signed (i63 effective in the interp). The bug surface
is where a 32-bit-style mask/wrap is intended (hash/checksum/fixed-point/bit-packing) or
where a modulo of a possibly-negative operand must be normalized. Per g5: a value
INTENDED to be full-width (no mask needed, stays within i63) is CLEAN; a `% n` of
always-non-negative operands is CLEAN; only a plausible input driving an overflow-wrap or
a negative-modulo that the DOCUMENTED/INTENDED semantics forbid is a real 🔴.

🔴 BUG #1 — FNV-1a 32-bit unmasked overflow→negative  (core/trait_hash_fixture.hexa)
------------------------------------------------------------------------------------
INTENDED SEMANTICS (file header, verbatim):
  "a documentation of intended hash semantics per type (FNV-1a 32-bit variant …)"
  "FNV_PRIME_32 = 16777619 / for each byte b: hash = (hash ^ b) * FNV_PRIME_32"
  "returns 32-bit hash as int in [0, 0xFFFFFFFF]"  (sibling xxh32 doc, same contract)
The canonical FNV-1a 32-bit reduces the multiply mod 2^32 EACH step. The pre-fix code
omitted the mask → the i64 accumulator grows past 2^63 and wraps to a NEGATIVE value,
off the documented [0, 2^32) range and disagreeing with any FNV-1a 32-bit reference.

VERBATIM REPRO (`hexa run`, input = "hello world!!!" code-points):
  UNMASKED -2441261701466863720     ← overflowed i63, NEGATIVE
  MASKED32 3092072344               ← canonical FNV-1a 32-bit
PYTHON CROSS-CHECK (FNV-1a 32-bit reference):
  PY FNV-1a 32-bit:      3092072344            == hexa MASKED32  ✓
  PY unmasked signed64:  -2441261701466863720  == hexa UNMASKED  ✓ (confirms identical wrap)

FIX: `h = ((h ^ x) * 16777619) & 0xFFFFFFFF` in both hash_str and hash_array_int — exactly
the per-step mask the 5 akida FNV sites already carry. Result now in [0, 2^32), matches ref.
