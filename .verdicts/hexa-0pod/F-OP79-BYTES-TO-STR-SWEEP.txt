OP-75 (base64) and OP-77 (hex, utf8) each found a module calling `bytes_to_str`
— a `pub fn` LOCAL to stdlib/ckpt/format.hexa (NOT a registered codegen builtin),
which (i) breaks standalone build when the module does not import it, and
(ii) DOUBLE-ENCODES raw bytes: `to_string(from_char_code(b & 0xFF))` per byte
treats each raw byte as a Unicode codepoint and re-UTF-8-encodes it, so every
byte >=0x80 becomes mojibake. The registered builtin `bytes_to_str_raw`
(self/codegen.hexa:7209 → hexa_bytes_to_str_raw) is the correct raw-byte→string
primitive. OP-79 sweeps the WHOLE repo for any remaining `bytes_to_str(` misuse.

2. TRUE SEMANTICS + VERIFY (OP-77 method — installed Jun-1 seed is a stale-oracle;
   faithful Python port vs the authoritative byte semantics)
═══════════════════════════════════════════════════════════════════════════════
The CERT block is written by stdlib/ckpt/writer.hexa:81 as
  `let cert_bytes = str_to_bytes(cert_json)`
and str_to_bytes (format.hexa:168) is `char_code(s,i) & 0xFF` byte-wise = the
RAW UTF-8 bytes of the string. The correct inverse on read is therefore
raw-byte→string passthrough = `bytes_to_str_raw`, NOT the ckpt re-encoding
`bytes_to_str`. The verifier wants raw-byte→string, not a codepoint-list build.

Faithful Python port (str_to_bytes = utf-8 encode; ckpt bytes_to_str = per-byte
codepoint then re-utf8; bytes_to_str_raw = raw bytes preserved), CERT JSON with
a Korean field `{"issuer":"한국",...,"reason":"서명 OK"}`:
    OLD bytes_to_str (ckpt)  round-trips? False   (한 ED 95 9C → C3 AD C2 95 ... mojibake)
    NEW bytes_to_str_raw     round-trips? True    (raw UTF-8 bytes preserved)
