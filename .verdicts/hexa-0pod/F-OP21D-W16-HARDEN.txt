3) OP-29 FMA-REFERENCE CHECK (#3042 cross-cut) — the MODE-4 reference accumulation
----------------------------------------------------------------------------------
OP-29 found the C farr_matmul FMA-FUSED kernel DIVERGES across ISAs (arm64 single fused
multiply-add = one round; x86 mul+add = two rounds). The contract: a reference matmul that
must be byte-identical across hosts has to be an inline ascending `acc += a*b` reduction,
NOT fma()/fmaf()-fused, and not compiled with -ffp-contract=fast.

Applied to w16's gate references (tool/wgmma/w16_op29_ref_check.cpp, clang++, 0-pod, 4/4 PASS):

  D1 (MODE-1 reference, w16.cu L558):
     `for(kk) a += hA[m*K+kk]*hB[kk*N+n]`  — inline ASCENDING-k, mul and add are SEPARATE
     operations on `a` (no single `a*b+c` expression), so the compiler cannot legally contract
     it into one FMA even under -ffp-contract=on. It is OP-29-SAFE: deterministic re-run,
     reproducible cross-ISA, accumulation ORDER well-defined (ascending k). PASS (D1a).
     Even if a host DID contract it to one FMA, the addmul-vs-FMA Δ is << the MODE-1 gate
     tolerance (rel_rms <= 3e-3) -> the gate cannot be false-failed. PASS (D1b).

  D4 (MODE-4 reference, w16.cu L645-647):
     the FULL-GEMM gate's reference is NOT a CPU matmul at all — it is cuBLAS-TF32 ON DEVICE
     (cublasSgemm + CUBLAS_TF32_TENSOR_OP_MATH), compared at rel_rms <= 3e-3 (line 685, NOT
     bit-exact). Because there is NO host FMA reference in MODE 4, the OP-29 cross-ISA FMA
     divergence failure mode is STRUCTURALLY ABSENT from the MODE-4 gate. We additionally
     confirmed the device wgmma K-accumulation order is well-defined (TKSW=32 slabs, TK=8
     inner) and equals a canonical ascending-k reduction (slab-order == flat-order,
     16384/16384). PASS (D4). And the MODE-4 gate is correctly a TOLERANCE gate (TF32 vs
     TF32 tensor-core, each with its own internal reduction order), not a memcmp. PASS (D4b).

MODE 4 ref accumulation well-defined (OP-29 check):  YES — the MODE-4 reference is cuBLAS-TF32
ON DEVICE (no CPU FMA), so OP-29 cannot false-fail it; MODE-1's CPU reference is the
