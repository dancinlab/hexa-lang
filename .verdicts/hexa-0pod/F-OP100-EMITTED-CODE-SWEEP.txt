F-OP100-EMITTED-CODE-SWEEP — EMITTED-FOREIGN-CODE validity sweep (HEXA-0POD, 0-pod, LANE-2)
================================================================================================

GOAL
  OP-98 found stdlib/websocket.hexa's emitted python3 helper was 100% DEAD: a
  `nonlocal pre` at module scope → compile-time SyntaxError aborted the entire
  fallback before any line ran. This is a distinct, high-leverage CLASS: a hexa
  module BUILDS a foreign-language source STRING (python3/bash/awk/C/sql) and
  execs it, but the emitted code carries a latent SYNTAX/SCOPE/QUOTING bug that
  makes the path dead-on-arrival (never caught because the host fallback "just
  fails"). OP-100 censuses such emitters (infra/protocol lane — LANE-1 hunts the
  scientific/compute-numeric emitters) and VALIDATES each emitted program through
  its REAL interpreter (python3 / bash / awk / sqlite3), 0-pod, local toolchain.

METHOD
  1. CENSUS (scoped greps, NO .git): modules that BUILD a foreign-code string to
     exec — `s = s + "..."` multi-line program builders + heredoc emitters
     (`cat > x <<'EOF'`) + inline `python3 -c` one-liners across stdlib/* and
     non-closure self/*.
  2. EXTRACT the exact emitted source for representative inputs (a generic
     `s = s + "lit" + var` reconstructor + a heredoc-payload slicer) and VALIDATE
     each through its real interpreter WITHOUT needing hexa to run it:
       python3 → `python3 -c "import ast; ast.parse(...)"` + actual run on a sample
       bash/sh → `bash -n` + run on a sample
       awk     → `awk -f` (syntax) + functional pipeline run
       sql     → `sqlite3` (DDL/INSERT/SELECT round-trip)
  3. A SyntaxError / scope error / quoting bug / dead path = 🔴 → minimal fix +
     lock test. A valid emitter is 🟢 CLEAN, NOT a bug (honest g5 — no fabrication).
