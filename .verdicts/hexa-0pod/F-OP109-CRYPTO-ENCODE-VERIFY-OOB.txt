PART A — close the flag: ed25519_verify / p256_verify direct-call length guard

VERBATIM REPRO (shipping `hexa run`, the inlined verifier-loop shape):
  ed25519_verify(pubk, msg, sig) first reads sig[0..32], pubk[0..32], sig[32..64] with NO
  length guard. A malformed direct call with a SHORT signature (len 10):
      calling ed_shape with short sig...
      index 10 out of bounds (len 10)
  p256_verify(qx,qy,hash,r,s) calls _be32_to_limbs on each field, which reads b[30],b[31].
  A SHORT coordinate (qx len 4):
      calling p256 _be32_to_limbs shape with short qx (len 4)...
      index 30 out of bounds (len 4)
  → the OOB read is a RUNTIME PANIC (process abort = DoS), not silent garbage. All in-tree
    callers (x509_verify_self_ed25519/_p256) already guard, so this is defense-in-depth, not
    a forgery-acceptance bug — but a malformed direct call MUST return false, never OOB.

FIX (mirror the OP-104/105 alpn length-guard pattern):
  stdlib/crypto/ed25519.hexa  ed25519_verify prologue:
      if len(pubk) != 32 || len(sig) != 64 { return false }     # RFC 8032: 32B pub, 64B sig
  stdlib/crypto/p256.hexa     p256_verify prologue:
      if len(qx_be)!=32 || len(qy_be)!=32 || len(hash_be)!=32 { return false }
      if len(r_be)!=32 || len(s_be)!=32 { return false }        # every P-256 BE field = 32B
  Wrong length ⇒ false; correct length ⇒ the fixed 0..32/0..64 and b[30],b[31] reads are
  all in-bounds.

PART B — ENCODE-side length-field audit (length field == body? round-trip == identity?)
──────────────────────────────────────────────────────────────────────────────────────────

🔴 REAL BUG FOUND + FIXED — tls13 RECORD-AAD length (tls13_record_aad caller in
   stdlib/crypto/tls13_client_record_io.hexa).
   RFC 8446 §5.2: additional_data = opaque_type ‖ legacy_record_version ‖ TLSCiphertext.length,
   where TLSCiphertext.length = the encrypted_record length = |TLSInnerPlaintext| + 16 (AEAD tag).
   BUG: the SEAL caller passed tls13_record_aad(len(plain))  — 16 SHORT (no +tag).
        the OPEN caller passed tls13_record_aad(body_len-16) — also 16 short.
   SELF-CONSISTENT (seal==open) so a hexa↔hexa round-trip worked and no hexa-only test caught
   it — BUT WRONG ON THE WIRE. The outer record HEADER was already correct (len(ct_tag)); only
   the AEAD AAD length was short, so a CONFORMING peer (OpenSSL/BoringSSL) recomputes the
   correct AAD from the on-wire length → the AEAD tag verify FAILS = a real TLS-interop break.
   DIFFERENTIAL (RFC 8448 §3 documented server App-Data record header):
        wire:  17 03 03 02 a2     (TLSCiphertext.length = 0x02a2 = 674 = ciphertext+tag)
        hexa-correct AAD = 17 03 03 02 a2   (== wire)
        hexa-OLD     AAD = 17 03 03 02 92   (0x0292 = 658 = inner, 16 SHORT)   ← WRONG
   FIX: seal passes len(plain)+16 (AEAD tag is always 16B for ChaCha20-Poly1305 and AES-GCM);
        open passes body_len (the on-wire encrypted_record length). seal-AAD == open-AAD is
        PRESERVED (hexa↔hexa still round-trips) AND now == the on-wire record-header length ==
        the RFC 8448 value. (Reject body_len<16 on open — a body shorter than the tag.)

🟢 CLEAN encoders (emitted length field == actual emitted body length; round-trip == identity
   — a correct encoder is the SUCCESS, g5, no fabrication):
   - tls13_ext_build (Extension TLV): uint16 length == len(value); round-trips vs
     tls13_ext_length / tls13_ext_next; documented supported_versions client bytes
     00 2b 00 03 02 03 04 reproduced exactly.
   - tls13_client_hello_body: legacy_session_id uint8 == len(session_id); cipher_suites uint16
     == len(suites)*2; extensions uint16 == len(extensions_concat); total body length consistent.
   - _keyshare_entry + tls13_ext_key_share_client_x25519: uint16 key_len == len(key);
     client_shares-vector len; outer ext len each == body; X25519 32B key → key_len 0x0020.
   - tls13_cr_build (context uint8 + extensions uint16), tls13_ee_build (uint16),
     tls13_ext_key_share_hrr (hardcoded len 2 == body) — each length field == body.
   - tls13_record_header / tls13_hs_header: big-endian length field round-trips (build↔parse).

ASN.1 DER ENCODE / OID base-128 encode (the task-scoped short→long-form 128 boundary +
