THE RULE
--------
A BYTE-producing escape/codec (%XX · \xHH · base64 · octal · =XX quoted-
printable) decodes to a RAW BYTE 0-255. Such bytes MUST be accumulated into a
buffer then UTF-8-assembled ONCE via `bytes_to_str_raw` (the OP-135 byte-
faithful, NUL-clean SSOT). Emitting `from_char_code(byte)` PER byte re-UTF-8-
encodes every byte >= 0x80 as the code point U+00xx (2 bytes) → MOJIBAKE for
all multibyte UTF-8 (Korean / CJK / emoji). NOTE (runtime-DIVERGENT): the
interpreter's `chr(b)` is byte-faithful (1 byte) but `from_char_code(b)` is
codepoint (2 bytes for b>=0x80) — so a `chr`-based byte decoder is correct,
a `from_char_code`-based one is the bug.

A CODEPOINT-producing escape (\uXXXX · &#NNNN; · \u{...}) decodes to a CODE
POINT, so `from_char_code(cp)` is CORRECT (only surrogate-pair combination for
astral codepoints is a separate concern).
