(a) THE DISPATCH HOOK [QUOTED from source]:
================================================================================================
Every heavy GEMM in flame's CLMConvMoE step is issued through ONE builtin, forge_dispatch_matmul, e.g.
in stdlib/flame/clm_prod.hexa:
    let mm      = forge_dispatch_matmul(xcol, T, Kdim, Wt, Cout)    // :212 (fwd conv→GEMM)
    let dW_flat = forge_dispatch_matmul(xcolT, Kdim, T, dy, Cout)   // :250 (bwd dW)
    let dXcol   = forge_dispatch_matmul(dy, T, Cout, w, Kdim)       // :262 (bwd dX)
codegen.hexa:7525 lowers that 5-arg builtin to a DIRECT hexa_forge_dispatch_matmul(a,m,k,b,n) call,
whose body (self/runtime.c) packs a ForgeShapeInfo + ForgeArgs and routes through forge_tier_dispatch_v1
(RFC 050 §6.1; emitted by self/forge/forge_tier_v1_emit.hexa:306). On a CUDA host the tier dispatcher
today calls cuBLAS (_hx_cuda_farr_matmul_gpu, forge_tier_v1_emit.hexa:169); the route-(a) own-GEMM wgmma
kernel (wgmma_tf32_b14.cu, MODE 8 128x128 NST=3) is the measured-winner alternative path.

=> THE HOOK IS forge_tier_dispatch_v1 (NOT a clm_prod edit). It already receives ForgeShapeInfo carrying
   (M,K,N). The integration adds a SINGLE consult at the top of its own-GEMM branch:
       cfg = selected_config(M, K, N)   # the OP-60 launch-dict, from routea_selection.json / embedded table
       mode==MODE8    → launch wgmma_tf32_b14.cu MODE 8 (128x128, NST per dict)
       mode==MODE_t64 → see fallback (b): UNBUILT on Hopper → falls back to MODE 8
       swizzle        → never (SELECTABLE structurally excludes it; dict.swizzle always False)
   clm_prod.hexa itself does NOT change — it keeps calling forge_dispatch_matmul; the routing lives in
   the dispatcher the builtin already funnels through. The {mode,tile,NST} maps 1:1 to a b14.cu MODE.

(b) THE FALLBACK CONTRACT — never launch an unbuilt or out-of-range kernel:
================================================================================================
The dispatcher MUST fall back to MODE 8 (128x128, NST=3) — the measured 1.08x parity winner @D=2048
(F-OP45GPU-OCCUPANCY-SWEEP T5) — in EITHER case:
  1. Selector picks an UNBUILT mode. The only such pick is MODE_t64 (64x64 small-D tile, §8.1 GAP#1) —
     an UNBUILT SPEC on Hopper sm_90a (only consumer sm_120 64x64 measured, OP-54; wgmma MODE_t64 is a
     future GPU-lane build). If selected_config returns MODE_t64 and the b14.cu entry point is absent,
     the dispatcher MUST NOT attempt it → falls back to MODE 8.
  2. D (or M/N/K) outside the validated range (table covers D∈{256..8192} square; degenerate/highly
     non-square shapes the cost model was never anchored on) → falls back to MODE 8.
Rule:
    cfg = selected_config(M, K, N)
    if cfg.mode not in BUILT_MODES or shape_out_of_validated_range(M,K,N):
        cfg = MODE8_DEFAULT       # 128x128, NST=3 — the measured 1.08x parity winner
    launch(cfg)                   # guaranteed a BUILT, measured-safe kernel
BUILT_MODES = the kernels actually compiled into the deployed b14.cu object (today {MODE8} + the
OG16/OG17/MODE6 family sharing the 128x128 launch). SAFE BY CONSTRUCTION: production can NEVER launch an
unbuilt kernel — worst case degrades to the current measured-good MODE 8 path.

(c) THE BIT-EXACTNESS INVARIANT — routing changes the KERNEL, not the bits:
================================================================================================
flame's training guarantee is byte-eq/determinism (the clm_prod_*_eq.hexa oracle family + cross-platform
exact gate). INVARIANT: routing by shape may change WHICH kernel launches, but MUST NOT change the
accumulation order / result bits vs the current path. Every selectable mode is a 128x128 (or, once built,
64x64) descriptor-direct wgmma tile running the IDENTICAL per-K-slab FMA reduction
`for kk in 0..TKSW step TK: WG(d_sub,dA,dB)` — NO split-K, NO cross-CTA reduction (§8.1/§9 constraint).
The 64x64 sub-tile reduction is byte-identical to MODE 8's per-(band,N-half) d0 reduction by construction;
swizzle (a pure index permutation, bit-exact but measured-slower) is structurally excluded. So rel_rms
0.000e+00 dev-vs-dev holds for EVERY routed shape — the same gate the parity map certifies for MODE 8.
GATE THE NEXT SESSION RUNS: for each routed shape, compare the selector-routed own-GEMM result against the
FIXED-MODE-8 own-GEMM reference on the SAME device — require rel_rms 0.000e+00 (bit-identical, NOT a
tolerance). Any non-zero delta = a routed kernel changed the accumulation order → route REJECTED (g5: the
bit-exact invariant is a hard gate, never a speed-only claim). Stronger than the cuBLAS-vs-own TF32-tolerant
gate, because all routed kernels share one FMA order.
