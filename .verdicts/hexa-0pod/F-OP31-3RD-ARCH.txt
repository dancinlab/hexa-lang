  A plain feed-forward MLP (multi-layer perceptron):
      x[B·d0] → Linear(d0→h1) → GELU → Linear(h1→h2) → GELU → Linear(h2→dout)
  It shares NO operators with either prior arch:

  determinism surface in its PUREST form, which is exactly the OP-30 invariant's
  stress point. Activation = GELU (the production nn_lib _nn_gelu path:
  0.5·(1+erf(x/√2))·x), routed through dt_erf/dt_exp (already libm-free).
  Config tiny CPU-runnable: B=3 · d0=8 · h1=16 · h2=12 · dout=6.
  Deterministic init (fixed LCG seeds 1111/1212/1313/1414/1515/1616 params,
  9001 input; no RNG, no clock).

  3rd-arch model = the PRODUCTION nn_lib MLP primitives — nn_linear_fwd +
  nn_gelu_fwd + nn_linear_bwd + nn_gelu_bwd (stdlib/flame/nn_lib.hexa).

OP-30 MATMUL-PATH AUDIT (the risk, located before running)
  The production nn_lib::nn_linear_fwd computes
      y = forge_dispatch_matmul(x, B, D, W, C)
  which (FP64 path) bottoms out at the C `hexa_farr_matmul` kernel —
  tensor_lib.hexa L58 verbatim: "직접 RFC 032 CPU farr_matmul 호출 (ikj order,
  FMA-fused under clang -O2)". That is the EXACT OP-29 root-cause kernel: it
  contracts a*b+c into a single fused-multiply-add on arm64 but emits separate
  mul+add on x86 under clang -O2 → a sub-ULP ISA-dependent result. So the MLP's
  FORWARD projections ride the FMA-fused kernel = a REAL OP-30 hole on this 3rd
  arch. (nn_linear_bwd's dW/dx/db are ALREADY inline ascending reductions, no
  farr_matmul.) The GELU path is already libm-FREE in production (dt_erf/dt_exp).
