BUG-1 — f37015ac "multi-LINE arithmetic continuation drops trailing term"
════════════════════════════════════════════════════════════════════════════
REPRO (deployed `hexa run`, /tmp/op124/leadminus.hexa):
    let f = 1
        - 2
        + 10
    println("f=" + str(f))
  → f=1          ← WRONG (silently drops `- 2 + 10`; should be 9)

CONTROL (same binary):
    1 \n + 2 \n + 10   → 13   ✅ (leading-PLUS continues)
    1 - \n 2 + \n 10   → 9    ✅ (trailing-MINUS continues)
    1 \n - 2 \n + 10   → 1    ❌ (leading-MINUS dropped)

ROOT CAUSE (emitted C from hexat, /tmp/op124/leadminus.c):
    HexaVal f = ...hexa_int(1)...;
    hexa_add(hexa_sub(hexa_int(0), 2), 10);   ← `(-2)+10` computed & DISCARDED
    hexa_println(... f);                      ← f is just 1
  The newline after `1` terminated the `let` value; `- 2 + 10` became a
  separate discarded unary-minus expression statement. This is EXACTLY the
  reported silent miscompute (matches INBOX #1703 anima Gierer-Meinhardt PDE
  blow-up / rt_lgamma Stirling-series hits cited in the source comment).

THE FIX IS ALREADY IN SOURCE — commit 02616b75e (#1747, 2026-05-28)
  self/parser.hexa:3377 parse_addition newline-continuation whitelist:
    -  ... (p_peek_kind() == "Newline" && p_continue_bin_op(["Plus"])) ...
    +  ... (p_peek_kind() == "Newline" && p_continue_bin_op(["Plus","Minus"])) ...
  After a complete left operand is consumed, a leading Minus on the next line
  is unambiguously BINARY, so it is added to the continuation whitelist.
  Same logic mirrored in the native compiler parser
  (compiler/parse/parser.hexa:598-616 — additive loop covers Plus AND Minus).
  git merge-base --is-ancestor 02616b75e origin/main → TRUE.

SOURCE-MECHANISM PROOF (/tmp/op124/unit_continue.hexa, run via `hexa run`):
  executes the EXACT p_continue_bin_op decision (self/parser.hexa:740) on the
  token stream after `1`  =  [Newline, Minus, Number, Newline, Plus, Number]:
    leading-minus continues=true        ← CURRENT whitelist ["Plus","Minus"]
    pre-fix (Plus-only) continues=false  ← the stale-binary behavior
  i.e. current source CONTINUES the expression (1-2+10 = 9); the stale binary's
  Plus-only whitelist drops it (→ 1). The bug is a deployed-binary artifact.
