================================================================================
MOTIVE — the unguarded-inner-read bug class
================================================================================
Length-prefixed binary parsers walk a buffer reading a length field, then copy
that many following bytes. The OUTER loop typically bounds-checks the LENGTH
HEADER against len(buffer); the trap is the INNER copy loop reading the
length-many DATA bytes WITHOUT re-checking the buffer end. On a truncated or
malicious wire frame where the declared length overruns the actual buffer, the
inner loop reads past the array end — a runtime OOB fault (or, in a non-bounds-
checked runtime, memory disclosure). The correct pattern guards EVERY inner
byte read against len(buffer) (graceful short read). This is a distinct class
from the closed delimiter/index work.

================================================================================
🔴 REAL SHIPPING BUG — tls13_cert_authorities_at (stdlib/crypto/tls13_cert_authorities.hexa)
================================================================================
The inner DistinguishedName name-copy loop (line 82, pre-fix):
    while j < nl { name.push(ext_value[i + 2 + j]); j = j + 1 }
has NO bounds guard. The outer loop only validates the 2-byte nl HEADER:
    while i + 1 < end && i + 1 < len(ext_value) {
        let nl = ((ext_value[i] & 0xFF) << 8) | (ext_value[i + 1] & 0xFF)
        ...
i.e. it checks the header is in-range but NOT that the nl name bytes that follow
fit in the buffer — UNLIKE the sibling tls13_alpn_parse. On a truncated/
malformed extension where the declared `nl` overruns the buffer, the inner loop
reads ext_value[i+2+j] past the array end.

VERBATIM REPRO on the shipping VM (`hexa run` /Users/mini/.hx/bin/hexa) — the
pre-fix body run standalone on a truncated extension (inner list_len=7 claims a
2-byte header + 5-byte DN, entry nl=5, but only 2 name bytes present, len=6):
  input ext_value = [0, 7, 0, 5, 0xAA, 0xBB]
  $ hexa run op104_prefix_neg.hexa
    calling buggy _ca_at on truncated (len=6, will read index 6)...
    index 6 out of bounds (len 6)            <<<< OOB FAULT
The well-guarded sibling tls13_alpn_parse on an analogous truncated input
returns the short string SAFELY (no fault) — the contrast that proves the
missing guard is the defect, not the input.

================================================================================
FIX (minimal · 0 deletions · mirrors the safe sibling)
================================================================================
stdlib/crypto/tls13_cert_authorities.hexa, tls13_cert_authorities_at inner loop:
  - while j < nl { name.push(ext_value[i + 2 + j]); j = j + 1 }
  + while j < nl && i + 2 + j < len(ext_value) { name.push(ext_value[i + 2 + j]); j = j + 1 }
A truncated DN now yields a graceful SHORT name, never an OOB read — identical
in spirit to tls13_alpn_parse's `i + j < len(ext_value)` inner guard.
