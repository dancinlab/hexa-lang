GOAL
  OP-19 (#3002) closed the CE-bwd libm `exp` cross-platform hole by swapping to the
  deterministic `dt_exp` Taylor, but logged a MEASURED LATENT residual: the GELU
  `erf` path — forward GELU(x) = x·0.5·(1 + erf(x/√2)) and its backward derivative
  GELU'(x) = Φ(x) + x·φ(x), Φ = 0.5·(1+erf(x/√2)), φ = exp(−x²/2)/√(2π) — still
  called libm `erf` (fwd) and libm `erf`+`exp` (bwd). Same class of hole. OP-19b
  replaces that with a PURE-FP deterministic erf (no libm, no other transcendental)
  and proves the GELU is now machine-independent byte-exact.

────────────────────────────────────────────────────────────────────────────────
 1. THE PURE-FP DETERMINISTIC erf (dt_erf)  ·  NO-LIBM: YES
────────────────────────────────────────────────────────────────────────────────
  Form (flame_math.hexa pub fn dt_erf) — Abramowitz & Stegun 7.1.26 rational with
  the single transcendental routed through OP-19's deterministic dt_exp Taylor:

      erf(z) = 1 − (a₁t + a₂t² + a₃t³ + a₄t⁴ + a₅t⁵)·exp(−z²),   t = 1/(1 + p·z)
        p  = 0.3275911
        a1 = 0.254829592   a2 = −0.284496736   a3 = 1.421413741
        a4 = −1.453152027  a5 = 1.061405429
      exp(−z²) := dt_exp(−z²)   (12-term scaled Taylor, range-reduce by halving)
      odd symmetry: erf(−z) = −erf(z)  (sign folded out at z=0, restored)

  hexa source (verbatim):
    pub fn dt_erf(x: float) -> float {
        let mut sign = 1.0
        let mut z = x
        if z < 0.0 { sign = 0.0 - 1.0; z = 0.0 - z }
        let t = 1.0 / (1.0 + 0.3275911 * z)
        let a1 = 0.254829592
        let a2 = 0.0 - 0.284496736
        let a3 = 1.421413741
        let a4 = 0.0 - 1.453152027
        let a5 = 1.061405429
        let poly = ((((a5 * t + a4) * t + a3) * t + a2) * t + a1) * t
        return sign * (1.0 - poly * dt_exp(0.0 - z * z))
    }

  NO-LIBM proof: every operation is +, −, *, / on fp64 plus dt_exp; dt_exp is
  itself +, −, *, / only (no libm). There is NO call to libm erf/exp/pow/etc. and
  NO floating-point library transcendental anywhere on the path. The grep for
  `erf(`/`exp(` on the wired GELU path is clean (only dt_erf/dt_exp remain).

  BRANCHLESS (load-bearing): dt_erf has NO value-dependent branch — the only
  conditional is the z=0 odd-symmetry sign flip, which is exact. This is REQUIRED
  for byte-eq: a FIRST cut used a Maclaurin series (2/√π·Σ(−1)ⁿz^(2n+1)/(n!(2n+1)))
  with a hard clamp to ±1 at |z|≥4. That piecewise form measured 1.54e-8 vs libm
  BUT broke the fused-vs-unfused GN-GELU byte-eq (max|Δ| = 2.5e-7, NOT 0): the GELU
  argument z = y·(1/√2) straddles the clamp/series boundary differently when y is
  consumed in-register (fused) vs stored-then-reloaded (unfused), so one arm clamps
  and the other runs the series. A series+rational-tail hybrid had the SAME defect
  at its z=3 seam (2.6e-7 jump). The unconditional A&S form has NO boundary to
  straddle → byte-eq restored (see §4). The Maclaurin series ALSO diverges
  catastrophically beyond z≈5 (alternating-term cancellation: erf(7)≈1191 in fp64),
  so it could not simply extend its range.

  This is ≤ the GELU training tolerance (the task budget is ~1e-7 abs; the W14-style

  libm erf bit-for-bit — it trades "matches libm erf" for "matches across ALL
  platforms" (the reproducibility identity). The change is training-equivalent.

  C host-fallback accuracy (clang -O2, FP_CONTRACT OFF): identical 1.38e-7.
