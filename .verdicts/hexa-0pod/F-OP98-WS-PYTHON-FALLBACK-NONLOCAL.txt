🔴 REAL SHIPPING BUG FOUND + FIXED — stdlib/websocket.hexa python3 fallback
  WHAT: _ws_python_helper_source emits a top-level Python script. Inside the
  nested `def take(n):` it declared `nonlocal pre`, but `pre` is assigned at
  module / `try`-block scope (the helper runs as `python3 helper.py`, so take's
  ENCLOSING scope is the MODULE, not a function). `nonlocal` requires an
  enclosing FUNCTION binding → Python raises a COMPILE-TIME

      SyntaxError: no binding for nonlocal 'pre' found   (at the take() line)

  This aborts the ENTIRE helper before any line executes — the script emits NO
  JSON on stdout, so ws_request_response's python3 path ALWAYS returns
  ok=false, error="python helper: no JSON in stdout". The python3 fallback —
  the universally-available backend on hosts without websocat — was 100% dead.

  VERBATIM REPRO (helper reconstructed from the hexa string literals, run as the
  wrapper does):
    $ echo '{"url":"ws://127.0.0.1:1/x","msg":"hi","timeout":1}' | python3 helper.py
      File ".../ws_helper.py", line 58
          nonlocal pre
          ^^^^^^^^^^^^
      SyntaxError: no binding for nonlocal 'pre' found
    exit=1   (NO JSON on stdout)

  RFC/REFERENCE CROSS-CHECK: the bug is purely the Python scoping keyword; the
  frame-codec LOGIC in the helper is RFC-6455-correct (verified independently
  below). Fix is the minimal keyword swap.

  FIX (minimal, 0 deletions):  s = s + "        nonlocal pre\n"
                            →  s = s + "        global pre\n"
  (`pre` is a module global; take() reads+reassigns it → `global pre` is correct.)

  POST-FIX PROOF — LIVE LOOPBACK (hermetic, local python3 echo server + the fixed
  emitted helper as client, full handshake + masked client frame + server-frame
  decode + masked close):
    STDOUT: {"ok": 1, "reply": "ECHO:hello-boundary", "error": ""}
    PARSED ok=1 reply='ECHO:hello-boundary'  → LOOPBACK PASS
  NEGATIVE CONTROL (flip back to nonlocal): SyntaxError, empty stdout, FAIL —
  NOT a tautology.
