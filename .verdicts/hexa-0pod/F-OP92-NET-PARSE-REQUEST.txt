🔴 BUG (parse_request) — DIFFERENTIAL vs an RFC-7230 message-framing reference
--------------------------------------------------------------------------------
UNFIXED body (origin/main stdlib/net/http_request.hexa:26-31):
    let parts = raw.split("\r\n\r\n")     // splits on EVERY blank line
    let header_block = parts[0]
    if len(parts) > 1 { body = parts[1] } // keeps ONLY the first body segment

RFC 7230 §3 framing: the FIRST empty line (CRLFCRLF) terminates the header block;
EVERYTHING after it — embedded blank lines included — is the message body. The
unfixed code splits on EVERY "\r\n\r\n" and discards parts[2..], TRUNCATING any body
that contains a blank line (multipart/form-data, nested HTTP, base64 with CRLF wrapping,
plain text with paragraph breaks — all routine).

VERBATIM differential (faithful Python port of the UNFIXED body vs an RFC reference that
splits on the FIRST separator only):
    case                       hexa(unfixed) body      ref body                   match
    'GET /api/ping ..\r\n\r\n' ''                      ''                         OK
    'GET /a?b=1&c=2 ..'        ''                      ''                         OK
    'POST /x ..\r\n\r\nhi\r\n\r\nbye'  'hi'            'hi\r\n\r\nbye'            MISMATCH <-- BUG
    'GET / ..\r\nDate: Mon, 01 Jan: 2020\r\n\r\n'  (header) OK                    OK
    ':weird' / 'X-Empty:' / dup-header / Host:port / no-path  ............        OK (all)

So method / path / query / header parsing are all CORRECT (split-on-SP, "?", and
split-on-first-":" with trim+lowercase all behave per reference across the leading-colon,
colon-in-value, empty-value, duplicate-header, host:port, and no-path edges). The SINGLE
divergence is body truncation.

ROOT CAUSE: the same "split-on-every-delimiter, keep one segment" index bug class as
OP-91's parse_query — here `raw.split("\r\n\r\n")` shatters the message on EVERY blank
line and `parts[1]` keeps only the first body segment, dropping parts[2..].

--------------------------------------------------------------------------------
FIX (minimal, provably-correct — matches RFC-7230 first-separator framing; 0 deletions)
--------------------------------------------------------------------------------
    let sep = raw.index_of("\r\n\r\n")      // FIRST separator only -> closes the bug
    let mut header_block = raw
    if sep >= 0 {
        header_block = raw.substring(0, sep)
        body = raw.substring(sep + 4, len(raw))   // whole remainder, CRLFs included
    }
Post-fix Python port = 9/9 OK vs the RFC reference (was 8/9). The header-parsing loop
below it is unchanged.
