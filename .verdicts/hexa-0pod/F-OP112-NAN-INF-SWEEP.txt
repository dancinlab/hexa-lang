FILE: stdlib/kernels/solar/solar_kernel.hexa  (pub fn ephemeris; the public
      solar_elevation / solar_zenith / apparent_zenith all build on it)

PRE-FIX:
    let sun_el = degrees(asin(
        cos(lat_r) * cos(dec_r) * cos(hr_angle_r)
        + sin(lat_r) * sin(dec_r)))

The argument is sin(elevation) = cosφcosδcosH + sinφsinδ. At H=0 it equals
cos(φ−δ) and is ≤ 1 by Cauchy–Schwarz, so the intended result is finite. But the
floating-point sum-of-products overshoots 1 by ~1e-16 (1 ULP) for plausible
inputs — latitude ≈ declination, i.e. the sun directly overhead at solar noon.
The libm `asin` builtin (unlike rt_asin, which clamps |x|>1→±π/2) returns a
SILENT NaN, which propagates into the returned elevation AND into
zenith = 90 − elevation. No crash — a corrupted finite-API result.

VERBATIM REPRO (hexa run, /tmp/solar_repro3.hexa + /tmp/clamp_mini.hexa):

  UNGUARDED asin(>1) NaN count = 35        ← 35/900 plausible inputs → silent NaN
  // the exact 1-ULP overshoot:
  asin(1.0000000000000002) is_nan = true   ← the silent NaN
  asin(clamp)              is_nan = false  val~pi/2 = 1.5708   ← fix → correct π/2
