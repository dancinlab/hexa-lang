CONTRACT
  a == b  ⟹  key(a) == key(b)      (equal values MUST address the same map slot)
  IEEE `-0.0 == 0.0` is TRUE ⟹ m[0.0] and m[-0.0] MUST be the SAME key.
  Mirror Python EXACTLY: str(-0.0) == "-0.0"  YET  hash(-0.0) == hash(0.0).

ROOT CAUSE (the C-runtime root OP-134 deferred)
  The bare native map (#{} · m[k]=v · has_key · keys) keys on a C char*: the
  key is produced by hexa_to_cstring(key) — FNV-1a hashed + strcmp-compared
  (internally consistent by construction). hexa_to_cstring has TWO float
  branches (Val-struct fast path + HexaVal fast path) that snprintf the key:
      whole-valued float → snprintf("%.1f", f)
      otherwise          → __hexa_format_float_mode(f, ...)
  `%.1f` of -0.0 emits "-0.0" ≠ "0.0", so m[-0.0] hashes to a DIFFERENT key
  than m[0.0] → lost key / silent duplicate. hexa_to_cstring is KEY-ONLY:
  its only callers are hexa_map_get_v / hexa_map_set_v + the m[k] get/set
  codegen sites. DISPLAY uses a SEPARATE function (hexa_to_string /
  _hexa_to_string_rec / __hexa_format_float_for_print) — not touched here.
