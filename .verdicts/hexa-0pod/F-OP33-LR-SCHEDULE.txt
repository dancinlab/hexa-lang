CONTEXT — the question OP-23b sidestepped
-----------------------------------------

dt_exp/dt_erf/dt_ln + Newton sqrt — F-OP19/19b/29). But the LR SCHEDULE is a
SEPARATE per-step float surface feeding `lr` into AdamW. The standard

AdamW update differs → weights diverge → the machine-independence claim
breaks the moment anyone uses a libm-cos schedule. OP-23b's drift harness

[LOCK] the canonical machine-independent scheduler (new primitive)
------------------------------------------------------------------
stdlib/flame/optim_lib.hexa  pub fn opt_lr_warmup_cosine(base_lr, floor_frac,
                                                          t, n_steps, warmup)
  t in [1..n_steps] (1-based, matching AdamW t):
    t <= warmup : lr = base · t/warmup                 (linear ramp 0→base)
    else        : prog = (t−warmup)/(n_steps−warmup)
                  cosf = 0.5·(1 + d5_cos(π·prog))      (1..0)
                  lr   = base · (floor + (1−floor)·cosf)
  cos = d5_cos (flame_math: mod-2π reduce + 14-term Taylor — the F-OP29 RoPE
  primitive; pure + − × ÷ IEEE-754 double) · π = d5_pi() exact double ·
  fold order PINNED (see optim_lib header CANONICAL ORDER block).
  Same formula as the OP-23b harness lr_at() with cos routed through d5_cos.
