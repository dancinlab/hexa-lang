IDENTITY LOCKED  (the INPUT path — the embedding-gather backward)

  The flame CLMConvMoE trainer's token-embedding backward (nn_lib.hexa
  nn_embedding_bwd_scatter) scatter-adds each position's gradient into its
  token's table row, IN PLACE, iterating positions i = 0..T-1 ASCENDING:

      for i in 0..T:                       # position / time, i-ASCENDING
          tok = ids[i]
          for c in 0..d:
              dtable[tok*d + c] += dX[i*d + c]

  When MULTIPLE positions share a token (repeated tokens — the common case in
  real corpora), the gradients of those positions ACCUMULATE into the SAME row.
  Float addition is non-associative, so the ACCUMULATION ORDER is load-bearing:
  it is part of the trainer's determinism contract. The production order is
  POSITION-ASCENDING (i = 0,1,…,T-1). This is the canonical SSOT.

  OP-13 LOCKS that order with three forms over a fixture built WITH repeated
  tokens (max-repeat up to 12 positions sharing one row — the trap is exercised):

    REF       = exact mirror of nn_embedding_bwd_scatter: i-ASCENDING in-place
                scatter-add. The production path / byte SSOT. Also pre-seeded
                with a deterministic "tied-head" term so the oracle covers the
                d5_grad ACCUMULATE-onto-existing case, not just zero-init.

    GROUPED+  = a per-vocab-ROW reformulation: for each row v, sum the dX of
                every position with ids[i]==v in POSITION-ASCENDING order into a
                fresh table. Same products, SAME per-row order as REF.
                GATE  ⇒  REF == GROUPED+,  max|Δ| = 0  (true reorder identity).

    GROUPED-  = the SAME grouping but summing each row's positions in
                POSITION-DESCENDING order. HONEST (g5) determinism PROBE — NOT
                the production order; FP non-associativity makes it diverge by a
                tiny eps on any row with ≥2 repeated tokens. Measured + documented.

  positions' gradients in POSITION-ASCENDING order (i = 0,1,…,T-1), matching the
  in-place scatter loop of nn_embedding_bwd_scatter. A future refactor to a
  "gather-then-grouped-sum" embedding backward (or a GPU atomic-scatter kernel)
  MUST preserve this i-ascending per-row order to stay bit-exact.
