================================================================================
DATE   : 2026-06-13
LANE   : 2 (0-pod correctness / security). CWE-190 -> CWE-125/787 chain: a parser
         reads a length/count FIELD from untrusted bytes then does ARITHMETIC on

STEP 1 — INT-SEMANTICS PROBE (GATES the sub-class)  [verbatim `hexa run`]
================================================================================
Probe program (/tmp/op118_probe.hexa) output, verbatim:
  imax=9223372036854775807
  imax+1=-9223372036854775808              <- 64-bit SIGNED wrap (NOT bignum)
  a*b=-2446744073709551616                 <- 4e9 * 4e9 overflows to NEGATIVE
  neg<cap PASSED bound (neg=-5)            <- a negative length PASSES `< cap`
  total=-9223372036854775716 total<x?=true <- `a+b` wrap makes total<x (bypass)

FINDING: hexa `int` is 64-bit SIGNED (i63 effective in the interp), confirming
OP-108's model. ALL FOUR OP-118 sub-classes are REAL and reachable:
  (a) accumulate-overflow: a big-endian width built by `v = v*256 + byte` or
      `v = (v<<8)|byte` over >=8 bytes wraps past i63 -> negative/garbage.
  (b) negative-length-as-span / bypassed `< cap`: a negative length passes an
      upper-bound check and is then used as a span/offset.
  (c) `a+b` wrap below `a`: a derived `start + len` regresses below `start`.
  (d) multiply-overflow: `count * stride`. (No reachable parser site found that
      multiplies an untrusted count by a stride to size an alloc — see census.)
The bug surface is therefore the VARIABLE / WIDE (>=8-byte) length decoders;
narrow fixed-width fields (<=4 bytes => max 2^32-1 << i63) are wrap-IMMUNE.

STEP 3/4 — 🔴 #1: ASN.1 DER long-form length overflow (crypto/asn1_der.hexa)
================================================================================
INTENDED SEMANTICS (X.690 §8.1.3 + file header, verbatim):
  "long form (high bit 1) → low 7 bits = number of subsequent length bytes
   (big-endian)."  der_value_len returns a DER value length used by der_next
  (next-sibling offset) and as n_len/e_len/r_len/s_len in X.509 parsing.
PRE-FIX: `nbytes = n & 0x7F` (up to 127) then `v = (v << 8) | byte` with NO cap.
For nbytes >= 9 (or an 8-byte form with the high bit set) v shifts/accumulates
past i63 and WRAPS to a negative value. Then der_next = der_value_start + v
REGRESSES below der_value_start (TLV iteration loops/regresses backward), and
the negative n_len/e_len/r_len/s_len feed x509_{min,rsa,p256,validity} reads as
a huge unsigned span.

VERBATIM REPRO (`hexa run`, inlined der_value_len; pad so OP-105 co-bound passes):
  9-byte: prefix=-1 fixed=0          <- 9x0xFF long-form WRAPS to -1
  8-byte-FF: prefix=-1 fixed=0       <- 8x0xFF (high bit set) WRAPS to -1
  der_next: pre=10 (start=11) fixed=11   <- pre-fix der_next(10) < value_start(11) = BACKWARD

FIX (minimal, net-additive): in der_value_len, reject the overflow class up front
  `if nbytes > 8 { return 0 }`  (a length needing >8 bytes can't fit non-neg i63)
  `if v < 0 { return 0 }`       (the 8-byte form can still set the high bit)
returning 0 = empty value, the same graceful short-read result a truncated buffer
already yields. ALL valid <=8-byte non-negative lengths preserved.

LOCK (stdlib/crypto/asn1_der_len_overflow_test.hexa — verbatim-inlined leaf):
  __HEXA_OP118_DER_LEN_OVERFLOW__ PASS 7/7
  (valid 10/128/256/2147483647 preserved · 9-byte + 8-byte-FF rejected ·
   der_next regression pre=10<start=11 -> fixed=11)

STEP 3/4 — 🔴 #2: websocket 64-bit length top-bit (net/websocket_native.hexa)
================================================================================
INTENDED SEMANTICS (RFC 6455 §5.2, verbatim in-code comment):
  "64-bit big-endian; hexa int is 64-bit. Top bit must be 0 (RFC)."
PRE-FIX: the 127-form length `val = val * 256 + lb[k]` over 8 bytes never
enforced the RFC MSB=0 rule. A frame with the high bit set wraps plen NEGATIVE.
(In ws_recv_native a negative plen happens to degrade to empty payload — graceful
— but the documented RFC invariant is UNENFORCED and a wrapped plen falls through
the parser; this hardens it to an explicit reject.)

VERBATIM REPRO (`hexa run`, inlined decode64):
  top-bit-set: prefix=-9223372036854775808 fixed=-1
  (all-FF -> prefix=-1, fixed=-1)

FIX (minimal): after the 8-byte accumulate, `if val < 0 { return "" }` — enforce
the RFC top-bit-0 invariant the comment already documents.
