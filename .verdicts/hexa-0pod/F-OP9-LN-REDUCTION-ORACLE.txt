WHICH REDUCTION IS LOCKED
  The flame CLMConvMoE trunk block is conv → GroupNorm → GELU. GroupNorm needs
  per-GROUP statistics over the FULL conv output, so it cannot stream — the conv
  finishes, then a "valley" reduction normalizes (this is the HEXA_FUSE_VALLEY /
  HEXA_FUSE_GN_GELU fused hot path; clm_prod.hexa _groupnorm / _groupnorm_gelu →
  gn_lib.hexa nn_groupnorm_fwd / nn_gn_gelu_fused).

  The PRODUCTION reduction is a TWO-PASS mean/variance (NOT Welford), per group g
  (cg = C/G channels, m = cg·T elements):
      pass 1: sum = Σ_{c∈g, t} X[t,c]              → mu  = sum / m
      pass 2: vs  = Σ_{c∈g, t} (X[t,c] - mu)²       → var = vs  / m
              inv = 1 / _gn_sqrt(var + eps)        (eps = 1e-5, PyTorch GN default)
      xhat[t,c] = (X[t,c]-mu)·inv ; Y = gamma·xhat + beta ; A = GELU(Y)
  BOTH reduction passes iterate in (t-OUTER, c-INNER) order — SEQUENTIAL, NO tree
  re-assoc. _gn_sqrt is a 40-iter Newton-Raphson (libm-free); GELU is the erf-
  based normal CDF GELU(x)=x·0.5·(1+erf(x·(1/√2))) (`erf` = libm codegen builtin).

CANONICAL ORDER (the determinism contract this locks — device kernel = SSOT)
  mean   : Σ over (t-OUTER, c-INNER), sequential; mu = sum / (cg·T).
  var    : Σ (x-mu)² over the SAME (t-OUTER, c-INNER) order; var = vs / (cg·T).
           TWO-PASS (mean-then-var), NOT a streaming Welford.
  inv-std: 1 / _gn_sqrt(var + eps), eps = 1e-5, _gn_sqrt = 40-iter Newton seed x.
  affine : Y[t,c] = gamma[c]·xhat[t,c] + beta[c].
  gelu   : A = Y · 0.5·(1 + erf(Y · 1/√2)) (erf libm builtin, NOT hand-Taylor).
  The forge_dispatch_groupnorm_gelu megakernel replays THIS exact order; gn_lib's
  nn_gn_gelu_fused_off is documented "character-for-character identical to
  nn_groupnorm_fwd_off (same sum/var reduction order, same _gn_sqrt)".

IDENTITY PROVEN
  OP-9 proves the trainer's UN-FUSED form (nn_groupnorm_fwd shape: the two-pass
  mean/var reduction, a SEPARATE affine sweep writing Y, THEN a SEPARATE GELU
  sweep re-reading Y → A — two elementwise passes over [T·C]) is BIT-FOR-BIT
  identical to the FUSED VALLEY form (nn_gn_gelu_fused shape: the SAME two-pass
  mean/var reduction, but the GN-affine value is GELU'd the instant it is

  the post-GN [T·C] tensor touched ONCE, NO Y read+write round-trip — the
  megakernel shape):
      max(|ΔY|, |ΔA|) = 0.0, all shapes.

  This is a true FUSION / ordering identity, NOT an associativity case — no
  tolerance. Both forms (a) sum the mean over the SAME (t-outer,c-inner) order,
  (b) subtract the SAME mu and sum the variance over the SAME order, (c) use the
  SAME _gn_sqrt(var+eps), (d) apply the SAME gamma·xhat+beta affine, and (e) apply
  the SAME erf-based GELU to the SAME value ⇒ every float op is identical. A future
  refactor that tree-reduces the mean/var sum (warp-shuffle), switches to a
  Welford streaming mean/var, drops the max/eps handling, or reorders the (t,c)
  axes would break determinism — this oracle catches it.
