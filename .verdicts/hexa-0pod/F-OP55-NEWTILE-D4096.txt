WHY (g5 interpretation, anchored to OP-45 T2 + the C7515 ptxas evidence):
================================================================================================
The OP-53 design hypothesis was: a 256-N single-pass tile amortizes the per-CTA prologue/K-drain
over 2x the output columns, capturing some of cuBLAS's +24.6% large-D scheduling win, IF it can be
made register-economical enough to stay 2 CTA/SM. The register economy SUCCEEDED (90 regs, 2 CTA/
SM measured). But it succeeded by processing the 256-N as TWO SEQUENTIAL 128-N halves sharing 2
accumulators — and that is EXACTLY what kills it:
  1. C7515 SERIALIZATION (ptxas, verbatim above): zeroing d0/d1 between the two halves is a "non-
     wgmma instruction defining accumulator registers", which forces ptxas to SERIALIZE the wgmma
     async pipeline at the half boundary. The tensor pipe stalls where MODE 8 (single 128-N pass)
     never does.
  2. DOUBLED K-DRAIN: each half re-walks the entire K-loop with its own per-slab commit_group +
     wait_group + __syncthreads(). One 256-N CTA pays the K-drain TWICE (once per half) — so per
     output element the drain overhead is the SAME as MODE 8, but the per-CTA prologue (the only
     thing a bigger tile could amortize) is NOT halved, it is re-paid per half. The "bigger tile
     amortizes the prologue" benefit is structurally cancelled by the sequential-halves schedule.
  3. This is fully consistent with OP-45 T2 (D=4096 is COMPUTE/SCHEDULING-bound, AI 682 >> 104):
     a schedule that ADDS serialization points (the half boundary) can only make a compute-bound
     kernel slower. The larger N-tile gave no DRAM-reuse win to offset the added serialization.
The ONLY bit-exact way to get a true single-pass 256-N tile (4 simultaneous live accumulators, no
half boundary, no serialization) is MODE 5 t256 — which is the 154-reg / 1-CTA/SM trap OP-45
already measured closed-neg (264.9 @4096 < MODE 8 283.9). So both bit-exact 256-N options are now
measured closed-neg: (a) 4 live accumulators = 1 CTA/SM (t256), (b) 2 live accumulators via
sequential halves = 2 CTA/SM but serialized (this OP-55). There is no bit-exact 256-N schedule
that is BOTH 2 CTA/SM AND non-serialized on sm_90a — that is the settled boundary.
