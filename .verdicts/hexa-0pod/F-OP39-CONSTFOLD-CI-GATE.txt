────────────────────────────────────────────────────────────────────────────
THE BUGS THIS GATE GUARDS (silent — no crash, just subtly wrong float bytes)
────────────────────────────────────────────────────────────────────────────
OP-37  (#3069) — `let a = 0.0 - <float literal>` was const-folded through
       `to_string`/%g (6-significant-digit lossy serialize) → corrupt low
       mantissa, max|Δ|=2.027e-6 on the A&S erf coefficients. Fixed by
       preserving the operand's EXACT source text for the additive-identity
       idioms (0.0-X, X-0.0, 0.0+X, X+0.0) — BYTE-EXACT.
OP-37b (#3073) — computed folds (`<lit> * <lit>`, `<lit> + <lit>`) re-parsed
       operands via the naive hxlcl_atof accumulator (≤1 ULP/operand, MAX 3 ULP
       compounded). Fixed by routing the operand parse through the correctly-
       rounded strtod path (str.parse_float()) — operands now byte-exact.

These do NOT crash; they emit subtly wrong float bytes. A future codegen
refactor could silently reintroduce either. The IEEE-754 bit pattern of a
double is PORTABLE (identical on every arch/OS iff the float bits are), so a
byte-eq assertion on the emitted const-fold bits is a valid MACHINE-INDEPENDENT
tripwire — the same goldens hold on arm64-macos, x86_64-linux, arm64-linux,
musl. This is exactly why a byte-eq gate is the right shape here.

DESIGN — EXTEND, not duplicate (Occam g0/g4)
────────────────────────────────────────────────────────────────────────────
The established campaign pattern is `tool/*_gate.sh` SSOT script + a thin
`.github/workflows/*.yml` step that runs it on the built ./hexa (OP-34's

    fold-gate step. Same built ./hexa, <1 s CPU run, no GPU, no new job/workflow.

WHY a new oracle (not an inline arg in fold_ci_gate's oracles): the bug lives in
self/codegen.hexa's comptime_eval const-folder, which only fires + inlines a
folded literal for a plain immutable `let` binding (codegen.hexa:3105,
_register_comptime_const). A BARE inline call arg `_bits(L, 0.0 - X)` is NOT
const-registered → emitted full-precision → clang folds it correctly → MASKS the
bug. So the oracle BINDS `let nN = 0.0 - X` then REFERENCES nN — the use-site
inlines the comptime-folded literal, exercising the exact serialize/parse path.
