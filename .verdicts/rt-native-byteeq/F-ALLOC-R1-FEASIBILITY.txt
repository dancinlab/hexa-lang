3. CIRCULARITY VERDICT — NON-CIRCULAR (decisive, like the B1 nanbox finding)
================================================================================
A hexa-source bump arena over a pre-mmap'd region recurses into NO heap. The
arena state (base ptr, cursor, addresses) lives entirely in int64/pointer space
— mmap returns a raw address as an INT HexaVal, the cursor is int arithmetic,
cells are addressed by __hx_ptr_store64/load64. NO string literal, NO array temp,
NO HexaVal boxing is created inside the allocator body ⇒ no recursion into
hexa_array/hexa_map.

PROOF (RAN on aiden x86_64, build/aprime_m4):
  PoC scripts/scratch/rt_native/bump_arena_linux_poc.hexa — Linux x86_64 flavor
  (mmap=9, MAP_PRIVATE|ANON=0x22, munmap=11):
    arena_new(8192) = __hx_syscall6(9,0,size,3,34,-1,0)  → raw mmap slab

4. CLASSIFICATION (c16 taxonomy) + NAMED r2
================================================================================
VERDICT: GO + NON-CIRCULAR (with a partial gate on the construct-half).

  · ARENA FLOOR (bump alloc/reset/release over mmap) = GO, intrinsics 100%
    covered, non-circular. The arm64 native runtime ALREADY emits this in
    hexa-source (runtime_arm64.hexa rt_arena_*); the x86_64 equivalent is a
    bounded codegen mirror, NOT a missing intrinsic.
  · MALLOC/CALLOC/REALLOC shim over the arena = GO for the FIXED-size +
    bump-from-arena cases (calloc = mmap-zeroed bump; the kernel zero-fills
    fresh anon mmap pages, so a fresh-page bump IS calloc). REALLOC of an
    order array = alloc-new + ptr-copy (covered by __hx_ptr_*). General free()
    of an arbitrary malloc'd block stays the libc floor (bump arenas free in
    bulk, not per-object — same trade-off Go/Rust make above the syscall).
  · HexaVal-RETURNING families (map_get/keys/.../set/remove, to_string_*, array
    push) = GATED-on-make_val. Their alloc-half is feasible over the arena, but
    they CONSTRUCT a HexaVal result ({.tag=TAG_MAP}+HX_SET_MAP_*) — that half is
    the CONSTRUCT-WALL the array lane's __hx_make_val (#3488) unlocks. Sequence
    AFTER the array lane lands make_val on main.

  NAMED r2 (post-array-lane-merge):
    "Port hexa_arena_alloc / the bump-from-arena calloc to a hexa-source body
     over __hx_syscall6 mmap + __hx_ptr_* (mirror runtime_arm64.hexa's rt_arena_*
     into the x86_64 native runtime + the runtime_core_emit standalone path),
     proving the FIRST ALLOC-WALLED family's allocator-HALF is C-free. The
     HexaVal-returning families (map_*) chain behind __hx_make_val (#3488)."

5. HONEST RESIDUAL (c9)
================================================================================
  · This is FEASIBILITY evidence, NOT runtime integration. The PoC proves the
    mechanism (mmap→bump→roundtrip, non-circular, zero C alloc); wiring it into
    runtime_core's hexa_arena_alloc + flipping the map _impl allocator is the r2+
    port work, gated on __hx_make_val for the construct-half.
  · free() of arbitrary blocks + the libc hxlcl_malloc general allocator are NOT
    claimed reducible here — bump arenas (like Go/Rust's mmap allocators) do bulk
    reset, not per-object free. The general-purpose malloc/free of long-lived
    non-arena objects is a real residual above the syscall floor (an ACCOUNTING
    floor, re-assessable, NOT a hard ceiling — same status the ARCHITECTURE
    documents for the irreducible syscall+libm floor).
  · No compiler edit landed this round (docs + PoC only) ⇒ no CI gate trip; the
    PoC reuses the already-shipped __hx_syscall6/__hx_ptr_* intrinsics.

CONCLUSION: ALLOC floor is REDUCIBLE. The genuine irreducible floor is the
syscall instruction (already wrapped) + libm — NOT the allocator logic. r1 = GO.
