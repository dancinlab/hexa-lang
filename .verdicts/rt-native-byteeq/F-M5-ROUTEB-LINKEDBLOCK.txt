1. THE FINDING (c9 — runtime_core_emit.hexa:3937-3953 read, decisive)
================================================================================
The C arena's mark ABI:
    typedef struct HexaArenaBlock { struct HexaArenaBlock* next; size_t cap;
                                    size_t used; char data[]; } HexaArenaBlock;
    typedef struct { HexaArenaBlock* block; size_t used; } HexaArenaMark;  // 16B
    HexaArenaMark hexa_arena_mark(void);
    void          hexa_arena_rewind(HexaArenaMark m);
HexaArenaMark is a 16-byte struct carrying a HexaArenaBlock* (a pointer INTO the
C linked-block chain) + a size_t used. Every C caller of arena_mark/rewind passes
this struct by value (SysV: returned in rax:rdx, passed in rdi:rsi).

The b2 seed (self/rt/alloc.hexa) is a RAW-MEM POOL TABLE: arena state is a fixed
mmap'd table of {base,size,used} pool slots, and its mark is a SINGLE int
(pool_idx * (PAGE+1) + used). There is NO HexaArenaBlock — no per-block `next`
chain, no `block*` to put in a HexaArenaMark. So:
  · seed hexa_arena_mark() -> int   (1 word, rax)
  · C   hexa_arena_mark() -> HexaArenaMark {block*, used}  (2 words, rax:rdx)
ABI-INCOMPATIBLE at the call boundary, AND the mark's `block*` field has no
meaning in the pool-table model. A C caller that does `m.block` on a seed-produced
mark reads garbage.

⇒ To make the seed a drop-in for the C arena (so the C `#else` can drop), the seed
  must adopt the C DATA STRUCTURE: a HexaArenaBlock linked chain, with mark =
  {block*, used}. The b2 pool-table work (b1/b2 de-circularization) does not carry
  forward to the C-ABI half — Route B is a LINKED-BLOCK REWRITE.

================================================================================
2. CLASSIFICATION (c16) — Route B is a rewrite, not an extension
================================================================================
Honest correction to the prior framing ("extend self/rt/alloc.hexa to full
feature"): the EXTEND is actually a REWRITE of the allocation data structure
(pool-table → linked-block) to match the C-ABI HexaArenaMark. What carries forward
from b1/b2/envelope:
  · KEEP: the mmap-over-__hx_syscall floor (block backing memory), the envelope
    half (#3524, __env_extend over each mmap), the syscall.hexa leaf port.
  · REWRITE: arena alloc/mark/rewind/reset onto a HexaArenaBlock {next,cap,used,
    data[]} chain, with HexaArenaMark = {block*, used} (16-byte struct return —
    the hexa fn must emit the SysV 2-register struct ABI, or be called through a
    thin C shim that boxes the two words).
  · ADD: the block-reuse-on-rewind walk (C arena keeps rewound tail blocks),
    new-block append, frame_clean/slot_dirty (RSS) if measurement shows the
    self-compile needs them.
The hexa↔C struct-return ABI (HexaArenaMark by value) is the open question: does
the native backend emit a 16-byte struct return in rax:rdx? If not, the seed
exposes two int accessors (mark_block/mark_used) and a C shim assembles the
struct. DEPLETION TEST (aiden): seed-built runtime.a → byteeq-real + faithful
3-target + miscompile-zero + RSS-OOM bounded.
