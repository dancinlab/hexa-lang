1. WHAT LANDED (the root-cause fix, c1)
================================================================================
The lower already marks a write to a module-global with a sentinel: `Stmt.dst` is
a Local with `arena_id == -999` (id = global_id) — hir_to_mir.hexa:1534-1548
"the backend recognises this sentinel and emits a `.data` global store instead of
a stack-slot store." The x86_64 backend did NOT recognise it: `_x86_emit_dst_
writeback` was spill-only, so the write fell through to a stack slot (lost on
return) → the global stayed `.data`-zero → near-null deref (F-M5-GSLOT-VAL-
GLOBALWRITE: 17 g0 reads, 0 writes in the asm).

FIX (compiler/codegen/x86_64_linux.hexa):
  · `_x86_emit_dst_writeback(buf, rm, id, arena_id)` — new arena_id param; when
    `arena_id == -999`, emit `mov [rip+g<id>], <payload home reg>` (mirrors the
    READ side _x86_op_resolve which loads `[rip+g<id>]`). Else the prior spill path.
  · `_x86_hv_store_leaf` / `_x86_hv_store_leaf_tagreg` — thread arena_id to the
    writeback.
  · all ~35 call sites pass `s.dst.arena_id` (cont.local_id sites pass 0 = local).
