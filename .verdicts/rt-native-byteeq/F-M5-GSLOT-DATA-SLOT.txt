1. WHAT LANDED (the root-cause fix, c1)
================================================================================
ROOT CAUSE (RAN): compiler/codegen/x86_64_linux.hexa:2493 returned `globals: []`
while the same backend REFERENCES module-globals as `g<id>` (_x86_op_resolve,
line 732/1054). arm64_darwin.hexa:3217 already builds `gnames` (line 3188:
`"g"+id`). So x86_64 emitted `g<id>` references with NO defining slot → a
standalone single-module emit had `.s` with 17 `g0` refs and ZERO `.data` slot →
link "undefined reference to g0". The whole-program compiler build hides this
(its data section is supplied differently); the read-half lane never hit it (no
module-global state). alloc.hexa's `__arena_tbl` is the first.

FIX: mirror arm64 — build `gnames` (bare `g<id>` for ELF) from module.globals and
return `globals: gnames`. emit_asm (asm.hexa:653) then emits `.data` +
`g<id>: .quad 0 .quad 0` per global.
