================================================================================
1. THE FINDING (RAN — read self/rt/alloc.hexa, the M5 endpoint module)
================================================================================
self/rt/mod.hexa is the runtime-replacement index (P7-7); it `use`s
self::rt::alloc as the hexa-source replacement for runtime.c's malloc/free/
realloc + arena. M5 = native-compile that tree → rt_*.o → link into the
standalone build → the C `#else` bodies become droppable (the array READ-half
lane #3494 proved this mechanism: a native .s seed DEFINES the symbol, then the
#else is excised → byte-DECREASE).

For M5 to compile self/rt/alloc.hexa into a SELF-CONTAINED rt_*.o (the
non-circular property F-ALLOC-R1's PoC demonstrated), the arena body must touch
NO heap-allocating hexa surface. It does:

  self/rt/alloc.hexa:55   struct Arena { pools: [ArenaPool], ... }   // hexa array field
  self/rt/alloc.hexa:62   return Arena{ pools: [], ... }             // array literal alloc
  self/rt/alloc.hexa:77   new_pools.push(pool)                       // ARRAY PUSH ← the cycle
  self/rt/alloc.hexa:80   current: len(new_pools) - 1                // array len
  self/rt/alloc.hexa:140  let mut i = len(ar.pools) - 1              // array len
  self/rt/alloc.hexa:160  while i < len(a.pools)                     // array len

  THE CYCLE:
    arena_grow()  --.push(pool)-->  hexa_array_push
    hexa_array_push  --grow beyond cap-->  hexa_array_arena_alloc_items / arena
    arena  --pool overflow-->  arena_grow()        ◀── closes the loop

  This is exactly the recursion F-ALLOC-R1-FEASIBILITY's PoC AVOIDED: that PoC
  (scripts/scratch/rt_native/bump_arena_linux_poc.hexa) addressed cells with raw
  __hx_ptr_store64/load64 over a mmap'd region — ZERO hexa array, ZERO push,
  ZERO HexaVal boxing in the allocator body ⇒ non-circular (nm witness: only
  `syscall`×2 = mmap+munmap, no malloc/calloc/realloc referenced). The shipped
  P7-7 skeleton, by contrast, holds its pool table in a `[ArenaPool]` hexa array
  and grows it with `.push()` ⇒ circular. The skeleton is a CORRECTNESS-of-shape
  draft, NOT a non-circular substrate.

2. SCOPE BOUNDING (RAN — array_ops.hexa + map_ops.hexa are WRAPPERS, not bodies)
================================================================================
The other two self/rt write-family modules do NOT carry the alloc body — they
delegate the low-level alloc primitive to the host (runtime.c) and only wrap the
higher-order pure ops:

  self/rt/array_ops.hexa:1-7  "Runtime.c kept the low-level HeapDescriptor
    primitives (new / get / set / len / reserve); everything else here runs in
    pure hexa." → rt_array_* = thin wrappers over *_pure.hexa. NO alloc body.
  self/rt/map_ops.hexa:1-7   "Low-level allocation (new / set / get via the
    host) stays in the host primitive." rt_map_set is a FUNCTIONAL copy (keys()
    loop + out[k]=v), NOT the hmap_grow allocator. NO alloc body.

  ⇒ The genuine write/alloc C body that must be ported for ls-reduction lives in
    self/runtime_core_emit.hexa (hexa_array_push: HeapDescriptor + realloc +
    arena-resident vs heap-promote vs geometric-grow vs mark-stack/heapify), and
    its allocator floor is self/rt/alloc.hexa's arena. The arena is the root: fix
    its circularity first, then the push body can route grow through a
    non-circular native arena.
