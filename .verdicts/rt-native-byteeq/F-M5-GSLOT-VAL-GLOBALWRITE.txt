1. ROOT CAUSE (c2 — aiden RAN, /tmp/ab2.s asm read)
================================================================================
grep `g0` in the gate's emitted asm:
  · `mov r10, [rip+g0]   # load global value: g0`  ×17  (READS)
  · `mov [rip+g0], …`                                ×0  (WRITES — NONE)
The global is only ever READ, never WRITTEN. rt_init's `__arena_tbl = sys_mmap(…)`
produces no store to `[rip+g0]`, so g0 stays at its `.data` zero-init. Every
`hexa_ptr_alloc` then loads `__arena_tbl == 0`, computes `__hx_ptr_load64(0, …)`
→ near-null deref → SIGSEGV.

CONFIRMING the codegen gap: `_x86_emit_dst_writeback` (x86_64_linux.hexa:1120) is
  fn _x86_emit_dst_writeback(buf, rm, id) {
    if _x86_is_spilled(rm, id) { out = _x86_store_spill(out, rm, id, "r10") }
    return out
  }
— it writes back ONLY to a spill stack slot; there is NO `o.kind == "global"`
branch that stores to `[rip+g<id>]`. The READ side DOES handle globals
(_x86_op_resolve, lines 672/731/1053: load `[rip+g<id>]` + tag-slot), but the
WRITE side was never implemented. arm64 may or may not have the same gap (not yet
exercised — b2 arm64 RUN not run). read-half never hit this: its accessors carry
no module-global STATE (every value is an arg/return), so nothing ever wrote a
global. alloc.hexa's `__arena_tbl` is the first module-global the native backend
must WRITE.
