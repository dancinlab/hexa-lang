REGIME (the M5d change vs M5b/M5c):
  per-GPU batch B_perGPU = 64 FIXED.  B_global(N) = B_perGPU * N.
    N=1 -> B_global=64 ;  N=2 -> 128 ;  N=4 -> 256.
  Each GPU always forwards/backwards 64 samples (constant per-rank work), so
  the per-step wall stays ~flat while N processes N x more samples per step.
  Metric = THROUGHPUT (samples/sec = B_global * 1000 / wall_ms), NOT per-step
  latency. Model = MLP 64->H->H->64 (ReLU,ReLU,linear), FP64. Median of 30
  reps (5 warmup discarded), per-step wall = fwd+bwd+all-reduce+sync.

EXPLICIT CONTRAST vs M5b/M5c (per-step latency) — why throughput is the metric:
  · M5b (#2897) / M5c (#2901) FIXED the global batch B=64 and SPLIT it across N
    ranks (16 rows/rank at N=4). They measured PER-STEP wall and found it NEVER
    beats 1-GPU: 2-GPU 0.99x asymptote, 4-GPU 0.974x — EVEN on real NVLink.
    Root cause (M5c): splitting a fixed batch only shards the BATCH dimension,
    but an H->H step is the H^2 WEIGHT-BOUND GEMM, so 64->16 rows barely cuts
    per-rank FLOPs. small-batch data-parallel per-step wall is STRUCTURALLY
    capped at 1.0x (any transport). M5c explicitly named the cure: the
    BATCH-BOUND regime — fix per-GPU batch, scale the global batch with N.
  · M5d MEASURES that exact regime. Same model, same ring, same byte-eq gate;
    the ONLY change is per-GPU batch FIXED + global batch ∝ N, metric = samples/sec.
    Result: throughput scales 1 -> ~2 -> ~4 (4-GPU 3.918x = 97.9% at H=3072),
    monotonically approaching ideal as the model grows. This is the OPPOSITE of
    the per-step <1x: in DDP's design regime (throughput), multi-GPU FINALLY WINS.

HONEST (g5/g83):
  · eff < 100% as expected (comm tax — the grad all-reduce is a real ring), but
    UNLIKE per-step latency, throughput scales UP with N, and the gap to the
    ideal N x SHRINKS with model size (97.9% at H=3072). Not a surprise-failure
    — the predicted DDP-design-regime behavior, now measured on real NVLink.
  · This is single-step, wide 3-layer MLP, FP64, on a host-staged-free NVLink
    node. The ring carries an NPARAM-length grad vector regardless of model
    architecture, so the throughput algebra (constant per-rank compute, N x
    samples/step) holds at any scale; the efficiency is set by the
    compute/comm ratio, which the H sweep shows improving with model size.

VERDICT: GREEN — DDP throughput scaling on real NVLink 4-GPU is near-ideal
(4-GPU 3.918x / 97.9% eff at H=3072), with N=4 byte-eq max|delta|=0. Throughput
IS the metric where DDP finally beats 1-GPU — the regime it is designed for —
in direct contrast to the per-step latency M5b/M5c proved is structurally <1x.
