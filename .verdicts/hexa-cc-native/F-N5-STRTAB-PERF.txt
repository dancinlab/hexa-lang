STATEMENT (falsifier)
---------------------
_build_merged_strtab is O(n²) over ~3600 self-compiler symbols (3252 .LCstr
+ 344 g<id> + 41 .LCflt): _str_in linear dedup + _sort_rev_desc insertion
sort + _index_of_str linear result lookup ≈ 13M string ops. Full-flat native
self-emit took ~60min / ~8.85GB RSS → env/OOM-killed before writing the obj;
same slowness fails linux-arm64 faithful-nobaseline CI (exit 143 SIGTERM).
FALSIFIER: the rewrite MUST be byte-identical (clang reversed-desc suffix-merge
ordering) — if small-obj strtab bytes / symbol order differ, it is wrong.

METHOD
------
- dedup  → hash-set map (has_key/seen[name]=true)           O(n)
- sort   → top-down merge sort _msort_rev_desc/_merge_rev_desc
           reusing the EXACT _rev_str_gt comparator          O(n log n)
- result → off_of name→offset map (no _index_of_str scan)    O(n)
Byte-identity: deduped inputs distinct + _rev_str_gt strict total order ⇒
merge sort == insertion sort output; suffix-merge offset assignment unchanged.
