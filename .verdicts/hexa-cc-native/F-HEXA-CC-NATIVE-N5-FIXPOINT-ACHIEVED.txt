WHAT UNBLOCKED IT (this session — all prior "blockers" were stale artifacts)
----------------------------------------------------------------------------
1. "gen2 startup SIGSEGV" = a STALE LINKER. The cc-native/n5-byteeq-fixpoint
   branch's tool/hexa_ld.hexa was 293 lines behind main; main's hexa_ld already
   lays out __literal8/__literal16 + __DATA,__const pointer tables. Relinking with
   a main-built hld_bin makes gen2 start clean. (NOT the believed "16-byte HexaVal
   runtime port".)
2. "missing SOURCE.hexa" is NOT a bug — compiler/main.hexa::_normalize_argv assumes
   the interpreted `hexa run compiler/main.hexa SOURCE` shape and skips the first
   `*.hexa` token; a standalone native compiler needs a dummy first `.hexa` token
   (the canonical `_drv.hexa` placeholder). argv plumbing is correct (lldb verified
   x0=argc at hexa_set_args entry).
3. "ENCODE-MISS: STP/LDP mem-parse-fail mem=#0" = a PRE-A-4 STALE OBJECT. cc-prc2.o
   was built from a branch forked 2026-06-02 00:56, before the A-4 fix (#2509,
   2026-06-02 14:24, `_lr_ctx_clear` fresh-arrays-per-function). A fresh aprime
   built from main (with A-4) emits clean objects. (NOT a live codegen bug.)
4. typeof→type_of: main's self/rt/*.hexa use `typeof()` but the builtin is
   `type_of` (bind.hexa allowlist) — 1 HX2001 on the flattened compiler. Resolved
   in the flat (sed) for this proof; the proper fix is PR #3020 (typeof builtin
   alias) or renaming the self/rt uses.
5. PERF: serialize's per-reloc/per-symbol byte-emit helpers (`_emit_reloc_info`,
   `_emit_nlist64`, `_u32/16/64_le`) each triggered a per-call `__hexa_fn_arena_return
   -> hexa_val_heapify` of the whole growing `out` buffer = O(n^2). Inlined into
   serialize's loops (output-preserving) to cut that. pack_lir retains additional
   O(n^2) (per-instruction buffer growth + `_str_in` linear dedup) — the native
   compiler is fast ENOUGH (~6 min) without fixing it, but it remains a perf
   follow-up to make the C-transpiled aprime emit fast too.
