## DEFECT_FOUND — state/hexa-own/l5-borrow-next-rung-plan.md — HX3052 E0505/E0504 capture-move-while-borrowed, compiler/lower/hir_to_mir.hexa (gated HEXA_BORROWCK, default-OFF), branch feat/axis3-r7-packout-lineage

**Defects:** The plan's central claim — "the single clean, guaranteed-x0-FP parity gap" — is FALSE. HX3052's added gate is the flow-insensitive loan scan _bck_ref_find_write_through(nm) (hir_to_mir.hexa:1200-1210), whose OWN docstring (hir_to_mir.hexa:1196-1199) declares a documented false-positive class: "a loan stays live from its `let` to end-of-fn... so `let r = &x; <use r>; x = 5;` ALSO fires." This registry is NOT covered by the M4 NLL last-use pass (that pass only serves the group-based _bck_check_use/HX3014 lane, catalog note hir_to_mir.hexa:505-526); no NLL kills a dead loan here.

Concrete FP (rustc ACCEPTS, HX3052 REJECTS):
  fn hz() { let xs=[1,2,3]; let r=&xs; println(len(r)); let f=fn(n:i64){ sink(xs) }; f(1) }
Here r's last use is the println BEFORE the closure. Modern rustc/NLL ends r's borrow at that point, so moving xs into the closure is legal — no E0505. But _bck_ref_find_write_through("xs") end-scans newest-per-name (hir_to_mir.hexa:1200-1210, no last-use) and returns >=0 because r's loan (origin "xs", recorded at :5317) is still "live" to end-of-fn → HX3052 FIRES. False positive against the E0505 parity target.

The plan's control fixture fp_clo_capture_move_no_loan only removes the `&xs` loan entirely; it never tests the dead-loan (NLL last-use) case, so it does NOT prove x0-FP. Reborrow/ref-param passthrough do NOT add a distinct FP: a bare ref-param (fn hz(xs:&[i64])) registers no loan row, and a reborrow `let r=&xs` records origin "xs" like any loan — the only FP vector is the shared flow-insensitive liveness above.

**Byteeq risk:** OFF/default path proven neutral. _bck_on default false (hir_to_mir.hexa:527); per-fn setup sets _bck_active=false unless HEXA_BORROWCK set (:7982-7985). The scanner call at :7236-7238 is guarded by `if _bck_active`, so with the flag unset (shipping) it never runs — identical diag stream, identical .text. Edit (2) new emitter is dead code when OFF; edit (3) catalog DiagSpec is consulted only when an HX3052 diag is emitted (none when OFF). gen3=gen4 holds. Same posture as shipped HX3037/HX3040. No byte-changing risk on the shipping path.

**Recommendation:** Do NOT merge with the "guaranteed-x0-FP" framing — it is inaccurate. Before merge: (1) relabel the rung honestly as inheriting HX3040's documented flow-insensitive loan-liveness FP class (dead-loan / no-NLL-last-use), not zero-FP; the parity target should be pre-NLL E0505, or the claim must be softened to conservative-loud-over-quiet consistent with E2/E3/E4. Per-fn expressibility is SOUND (loan registry live at the closure-lower site, per-fn reset). Byteeq is SOUND (default-OFF, scanner behind _bck_active). Parity codes E0505/E0504 are real, not bespoke.
