Surveyed origin/main (f0810d165) via two fan-out explorers + the campaign state docs. TL;DR: **L4 = stamp checker-grade call-result types into HIR so the already-default-ON native unbox gates fire (the inference→codegen plumbing gap is the measured residual). L5 = run the Lane-B B1 corpus census and flip `HEXA_BORROWCK` to a default-ON warning band (B3) — the roadmap's one open gate; the arena-reclaim EMIT alternative is rejected on a 3-day-old measured-terminal verdict.**

## L4 static-typing → unboxing

**1. NEXT ROUND: `HEXA_UNBOX_HIR_CALLTYPE` — call/builtin-method result-type stamping in `ast_to_hir`.**
The survey found the inference is **three parallel, unplumbed systems**: the checker (`compiler/check/types.hexa`, near-total after #4688) returns *diagnostics only* — `compiler/main.hexa:720` runs `type_check` but `:773` lowers the **raw AST** with no TypeEnv; `ast_to_hir` re-does its own shallow inference and leaves every fn/builtin-method call result as `"?"` → MIR `type_id 0`; gen2 does a third scan. Meanwhile the native backend's unbox gates are **already default-ON and already measured** (r5b/r6: k1 0.338, k4 0.241, k5 0.436 ON/OFF, magic-div reference-matched) but `_x86_operand_provably_int` (`compiler/codegen/x86_64_linux.hexa:1613-1618`) only accepts `type_id==1`, so any operand touched by a call result re-boxes the whole expression (`:1593-1597`). Closing this plumbing gap is the smallest step that makes existing measured levers fire on more code — no new emit machinery. It beats: another parity rung (adds zero perf); the 16B→8B layout (measured wall 🧱, #4119+#4123 — i64 truncation + un-flaggable ABI redesign; do not reopen); measuring `HEXA_UNBOX_INFER` R1 (merged #4011 with all 5 gates still PENDING-POOL — but it lives on the gen2 C-transpile lane axis-① is retiring); and the user-fn 16B pair call-ABI (k5's 4.6× residual — the real next campaign, for which trustworthy MIR types are a prerequisite anyway). Inference is complete enough — the gap is delivery, not inference.

**2. FIRST LEVER:** in `compiler/lower/ast_to_hir.hexa`, when a call/method expression's type is `"?"`, consult a mirror of the checker's `_types_builtin_method_ret` table (#4688) and stamp the HIR `typ` (→ `_type_id_of` → MIR `type_id`) — gated `HEXA_UNBOX_HIR_CALLTYPE=1`, default-OFF, OFF-path byte-identical by construction. Include the mut-reassignment void guard (same class gen2's `_build_unbox_facts` implements). **Measurement (pool, aiden/summer, isolated):** new `k6_callres` kernel — hot loop with a builtin-method result as an int operand (e.g. `s = s + xs.len()*i`), native backend, taskset median-of-5, flag OFF vs ON, plus re-run k1–k5 as no-regression controls. Expected regime: same as r5b/r6 (ratio ~0.24–0.44, i.e. 2.3–4×) since the identical gates fire; also count emitted `hexa_add`/`hexa_mul` calls OFF→ON (lever proof independent of timing).

**3. VERIFY GATE (all captured):** ① flag-unset `.o` sha == origin/main + gen3≡gen4 byteeq 3-target GREEN; ② k6 boxed-call count drops ON (>0 → 0 on the certified ops); ③ k6 ratio < 1.0 captured (justifying number: anything in the r5b/r6 regime; ≥0.9 = CLOSED-NEG, report it); ④ output bit-identical OFF==ON on k1–k6 **and** a full test-corpus differential; ⑤ ship smoke 3-target under the flag. Merge default-OFF on ①④⑤; default-flip is a separate later decision on ②③ + 3-target+nvptx byteeq re-GREEN.

**4. RISK:** a wrong stamp is a silent miscompile — `type_id` also feeds tag resolution (the m12 pack-fuse `_x86_tag_resolve` incident was exactly this class), so a mismatched table entry turns a boxed f64 into native int arithmetic. Control: stamp only unambiguous table entries (conservative, no conditional-merge or reassigned bindings), and treat gate-④ full-corpus output parity — not LLM judgment — as the soundness verdict. Measurement artifact risk: back-to-back timing contamination — run isolated per the HEXA-UNBOX rule, and don't let the k6 kernel's loop get const-folded into nothing (verify the disasm window like r6 did).

## L5 memory management → borrow-check

**1. NEXT ROUND: Lane-B B1 corpus census → B3 `HEXA_BORROWCK` default-ON Warning band.**
The parity ladder is measured-exhausted (ARCHITECTURE.json records the REJECT frontier "FULLY-EXHAUSTED"; ~22 HX30xx codes all opt-in report-only), and the roadmap SSOT (`state/hexa-own/default_own_roadmap.md`) already names the one open gate: **B1 — the whole-corpus census has never been run** (B0 STRICT ✅ #4521, A1 `&T` surface ✅ #4517, A2 census *mode* ✅ #4520 — but zero recorded runs, no worklist file, and the pass's compile-time cost is entirely unmeasured). This beats a new parity rung (diminishing returns; HX3042 already covers the depth-1 partial-move residual and `@own` corpus adoption is ~0, so deeper E0382 parity fires on nothing real). It also beats the survey's other candidate — the loop-body arena-reclaim EMIT (~849× RSS on a synthetic push-loop bench) — which I am **rejecting against the measured-terminal verdict from 3 days ago**: rung-1 leaf-only reclaim fired on zero real churn loops and rung-2 callee no-escape summaries showed no win because the churn kernels *return* their allocs; the EMIT is explicitly not-to-be-built. Critically, the actual memory-safety payoff (PREREQ-X free-tree allocator flip) is itself gated on trusted borrowck ≥ B4 per the roadmap's mutual-dependency note — so B1→B3 **is** the critical path to GC-free memory management, not a detour.

**2. FIRST LEVER:** one pool run (aiden or summer) of the self-host compile (aprime_cc, ~1.11M LOC) + test corpus under `HEXA_BORROWCK=1 HEXA_BORROWCK_CENSUS=1`, capturing: per-HX30xx fire counts, the `[borrowck-census] would-move` worklist file (this simultaneously discharges Lane-A A2), and wall-clock ON vs OFF (first-ever cost number). Triage every fire: true hazards → fixed via normal PRs; FPs → classified per code. Then the B3 PR: flip the polarity at the flag read site (`compiler/lower/hir_to_mir.hexa:8492-8504`) to `_bck_on = env("HEXA_BORROWCK") != "0"` (opt-OUT), **Warning band only, and only for codes with census-FP = 0** — the documented noisy classes (HX3052's flow-insensitive dead-loan, whole-local granularity) stay opt-in. STRICT stays opt-in.

**3. VERIFY GATE:** census artifact committed to `state/hexa-own/` with captured counts — GO requires 0 unfixed true hazards, total fires O(dozens) (>100 = classification failure per the SSOT, NO-GO), and ON-vs-OFF self-host compile overhead captured and < ~5%. B3 flip PR gates (per the roadmap row): byteeq 3-target GREEN + faithful build + shipping smoke + gen2↔native parity, plus ON/OFF **binary** byte-identity (diagnostics are stderr-only — verify nothing leaks into artifacts). Revert-on-RED.

**4. RISK:** the census surfaces an FP swarm from the known flow-insensitive classes → a default-ON warn band that spams legal shipping idioms is a DX regression worse than the status quo. Control: the per-code zero-FP subset rule (flip is not all-or-nothing) and the >100 NO-GO threshold. Second risk: honesty — under the current bump-arena, borrow violations can't be use-after-free, so B3 ships as a *correctness lint*, not memory safety, until PREREQ-X; state that in the PR rather than overselling the safety claim. Cost risk: the NLL/dataflow fixpoints on 1.11M LOC are capped but unmeasured — the same census run produces the number before any flip decision.
