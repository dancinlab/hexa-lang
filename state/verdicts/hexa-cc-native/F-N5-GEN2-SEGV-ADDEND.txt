═══ FAULTING INSTRUCTION ═══
  PC = _hexa_str + 152 (0x1001654b8):
      ldr  x0, [x21, w26, uxtw #3]      ; x21 = NULL → EXC_BAD_ACCESS
  Backtrace: start → main → _normalize_argv → hexa_args → hexa_str
             (first hexa_intern() of the first CLI arg).
  x21 = __hexa_intern.buckets = NULL (the hash-table bucket array).
  (.ips reported @0x20-class near-null; lldb pins exact FAR=0x0, x21=0.)

═══ NULL POINTER ═══
  __hexa_intern.buckets (clang merges runtime file-scope statics into
  __MergedGlobals; __hexa_intern struct = __MergedGlobals+0x10, buckets
  field at struct+0x118 = __MergedGlobals+0x128).

═══ ROOT CAUSE ═══
  tool/hexa_ld.hexa:218 tested  `if r_type == 1`  for ARM64_RELOC_ADDEND.
  But kind 1 = ARM64_RELOC_SUBTRACTOR; ARM64_RELOC_ADDEND = kind 10
  (mach-o/arm64/reloc.h enum). The prefix ADDEND reloc was therefore never
  recognized, so EVERY PAGE21/PAGEOFF12 reloc against an extern-with-addend
  symbol lost its addend (have_addend never set → this_addend = 0).

  Effect on __hexa_intern (clang emits 3 distinct addends):
      init-check &buckets   addend 0x128   (folds to base+0x118)
      loop struct base      addend 0x010
      hashes ptr            addend 0x130
  All three COLLAPSED to one offset in linked gen2 (verified via otool):
      NO-FIX gen2:  init=[+0xb38]  base=+0xb38  hashes=[+0xb38]   (all same)
      FIXED  gen2:  init=[+0xc60]  base=+0xb48  hashes=[+0xc68]   (distinct ✓)
                    (base+0x118 = 0xb48+0x118 = 0xc60 = init ✓ consistent)

  Runtime consequence: lazy-init guard `if (!__hexa_intern.buckets)` read the
  WRONG word (struct[0]=count, nonzero) → skipped calloc → buckets stayed NULL
  → bucket probe dereferenced NULL → SIGSEGV at startup (any invocation incl
  --version/--help, before any compile work).

═══ FIX ═══
  tool/hexa_ld.hexa:218   `if r_type == 1`  →  `if r_type == 10`
  (+ 2 stale "kind 1" comments corrected to "kind 10"). 1-line logic change.
