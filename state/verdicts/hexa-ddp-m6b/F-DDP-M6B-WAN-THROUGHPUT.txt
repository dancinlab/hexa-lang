F-DDP-M6B-WAN-THROUGHPUT — perf envelope of the M6 cross-node ring all-reduce
=============================================================================
STATUS: 🟢 GREEN (perf characterization) — RTT + BW-vs-size curve measured on a
        REAL intercontinental WAN. NOT a correctness claim (M6 #2899/#2900 owns
        byte-eq); this is the THROUGHPUT envelope M6 explicitly deferred.

PRE-REGISTERED FALSIFIER / QUESTION (g5):
  M6 proved the 2-node TCP ring all-reduce crosses a real WAN node boundary
  byte-exact, but said NOTHING about speed. M6b measures it:
    (1) RTT floor (small-message ping-pong round trip),
    (2) achieved all-reduce bandwidth (GB/s) as payload sweeps 1KB..256MB,
    (3) the latency->bandwidth crossover size,
    (4) the effect of the TCP socket-buffer / window (BDP) on (2).
  HONEST prediction (g5): commodity WAN TCP between two rented pods is high-RTT
  (cross-country tens-to-hundreds of ms); small messages are latency-bound
  (terrible effective BW), large messages should approach link bandwidth. We
  report the REAL curve. NOT datacenter/RDMA. NOT a correctness claim.

METHOD:
  stdlib/ddp/m6b_throughput/ring_perf_m6b.c — the EXACT M1/M3/M5/M6 canonical
  ring schedule (2(N-1) steps, chunk_start partition, parity send/recv ordering
  for deadlock-free 2-cycle), host-memory FP64 ring over host-to-host TCP
  (sendall/recvall, TCP_NODELAY) — byte-for-byte the M6 transport, instrumented:
    * RTT_PING: rank0 sends a 1-byte token to succ, rank1 echoes it back; median
      of 50 round trips.
    * BW sweep: per payload size S (FP64 elems), reset x and run a full
      all-reduce R times, report MEDIAN wall. algo_GB/s = S*8 / median_wall;
      wire_GB/s = (bytes actually put on the wire by the 2(N-1) steps) / median.
      For N=2 both ~= S*8 (each rank sends ~S/2 and receives ~S/2 per phase, two
      phases reduce-scatter+all-gather).
    * --sockbuf BYTES sets SO_SNDBUF/SO_RCVBUF before connect/accept to probe
      the bandwidth-delay-product (TCP window) hypothesis for (4).

  FINDING (4): the 32 MB socket buffer curve is INDISTINGUISHABLE from the
  default-buffer curve (same ~0.6s floor for tiny S, same ~0.00002-0.00004 GB/s
  effective). => the bottleneck is NOT the TCP window / bandwidth-delay product.
  The ring's per-phase BLOCKING send-then-recv serialises a full RTT before the
  next byte moves, so throughput is RTT-dominated, not window-limited. A clean
  NEGATIVE: enlarging the socket buffer does not help this collective on WAN.

──────────────────────────────────────────────────────────────────────────────
(3) CROSSOVER + (2-cont) SATURATION / EFFECTIVE GB/s CEILING
──────────────────────────────────────────────────────────────────────────────
  * Small S (<= 16 KB payload): median ~ 0.6-1.0 s == ~2 RTT floor (pure
    latency). Effective BW < 0.00002 GB/s (~20 KB/s) — useless for tiny grads.
  * The "crossover" where transfer time begins to dominate the RTT floor sets
    in only around 32-256 KB payload (median climbs from the ~0.6s floor toward
    seconds), but the effective BW stays FLAT at ~0.00002-0.00004 GB/s
    (~20-40 KB/s) all the way to 1 MB — i.e. this WAN ring NEVER reaches a
    bandwidth-bound regime at any size we could practically measure.
  * EFFECTIVE GB/s CEILING (measured): ~3-4e-5 GB/s == ~30-40 KB/s sustained
    all-reduce throughput, PL<->CA, both default and 32MB-window TCP. The link's
    nominal capacity (~800 Mbit/s each pod) is two-to-three ORDERS of magnitude
    above this — the collective cannot fill it because of the serial-RTT phase
    structure over a 300ms path.
  * USABILITY: at ~30 KB/s effective, even a 1 MB gradient all-reduce costs ~31s.
    This WAN ring is byte-exact (M6) but perf-USELESS for synchronous DDP at any
    realistic gradient size — the cross-country RTT dwarfs everything. It becomes
    "useful" only if the per-all-reduce work is hidden behind >>seconds of
    compute, or if the schedule is restructured to pipeline (overlap) the two
    phases / many chunks so TCP can keep the pipe full instead of stalling a
    full RTT per phase.

──────────────────────────────────────────────────────────────────────────────
HONEST VERDICT (g5)
──────────────────────────────────────────────────────────────────────────────
  The M6 cross-node ring all-reduce is byte-exact over a real intercontinental
  WAN, but its THROUGHPUT envelope is RTT-bound and tiny: RTT ~300-320 ms,
  effective all-reduce ceiling ~30-40 KB/s (~3-4e-5 GB/s), flat across 1KB..1MB.
  It NEVER becomes bandwidth-bound at measurable sizes; a 32 MB TCP window does
  not change the curve (the limiter is the serial per-phase blocking RTT, not
  the socket buffer). This is a commodity-WAN-TCP perf reality, NOT an RDMA /
  datacenter number, and NOT a correctness claim. Practical takeaway: synchronous
  cross-country DDP over this transport is latency-dominated and only viable when
  compute >> communication or the collective is re-pipelined to overlap phases.
