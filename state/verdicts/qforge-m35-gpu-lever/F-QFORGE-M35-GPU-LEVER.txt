FINDING (d6 — honest, layout is the lever)
  • M27 bin-per-thread kernel (qforge_a2f_bzsum) = POOR lever: spawns only ng
    threads (64..1024) → 0.3% occupancy on 188 SMs → SLOWER than single-core CPU
    below ns=131072, peaks at 1.7×. This is a real negative on the naive layout.
  • 2D (sample-tile × bin) kernel (qforge_a2f_bzsum2d, atomic-add reduction) fills
    the SMs → 27–42× over single-core CPU for ns ≥ 4096, plateau ~138 GFLOP/s.
  • Roofline: plateau ≪ FP64 FMA peak because the kernel is TRANSCENDENTAL-bound —
    3 exp() per inner (i,j), each the #1215 ~30-flop polynomial → ~3.5 G exp/s
    sustained is the real roof (SFU/poly throughput, not FMA).
  • Crossover ~ns·ng ≳ 10⁵; below that launch overhead dominates even for 2D. A
    real per-q DFPT α²F assembly (ns ~ 10⁴–10⁶, ng ~ 10²–10³) sits firmly in the
    40× regime → the lever is worthwhile for the L3 assembler.
  • Distinct from #2706 (DFPT n_iter-dominant) — this assembler is a dense
    (sample×bin) histogram, parallelism-limited, not iteration-limited.
