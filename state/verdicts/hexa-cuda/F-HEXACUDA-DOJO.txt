  (11a) RECIPE (a) — canonical-atom own-GEMM (verdict F-FUSION-SM90-WGMMA-OG16,
        PR #2866). The TF32 own-GEMM was pinned 70.2 TFLOP/s / 6.09x off cuBLAS
        for 5 rungs (OG11-OG15) by a CONTRADICTION: a hand-rolled
        cuTensorMapEncodeTiled box landed an ATOM-MAJOR SWIZZLE_128B SMEM tile a
        descriptor-direct wgmma could not read bit-exact, forcing a 32KB software
        DECODE BAND in the hot loop — and that band ⊥ occupancy (blew the smem
        budget, could not also hold 2 CTA/SM). A 3200-cfg (LBO,SBO,base_offset,
        layout_type) sweep floored at rel-RMS 1.000. FIX inverts the question:
        instead of asking a fixed HW de-swizzle to match the box, PRE-LAY the
        operand in GLOBAL in the canonical CuTe Layout_K_SW128 / gmma-INTER (8x4
        core) order + use a NO-swizzle TMA, so the landed SMEM tile IS the
        wgmma-ready layout the descriptor addresses (layout_type_=0,
        descriptor-direct) — NO in-kernel decode band. Result (measured H100):
        single-tile rel-RMS 1.000 -> 0.000 (bit-exact), smem 96 -> 64 KB/CTA
        (2 CTA/SM held), own-GEMM 70.2 -> 264.7 TFLOP/s (3.77x), ratio vs
        cuBLAS-TF32 6.09x -> 1.37x (~85-90% of the gap closed). PARITY (<=1.3x)
        NOT quite reached (best 1.37x); the remaining ~5% is a perf-only frontier
        (OG17 warp-spec/larger-tile/ping-pong, now un-gated since the band is gone).

  (11b) RECIPE (b) — weight-reuse GEMM-conv MoE (verdict F-FUSION-MOE-CONV-PROD-
        KERNEL, PR #2867). The d=6208/H200 production MoE step (~74s/step, the
        f5e18a0f wall) is GPU-SATURATED (~92-96% util), so fusion-FILL LOSES there
        (the OG-FUSE-OPT closed-neg: tiled-fused 3997 ms vs ModuleList 3734 ms @
        d=6208 — no fill headroom, every weight touched once = no reuse). But the
        closed-neg named the RIGHT residual (weight bandwidth) + RIGHT cure (weight
        reuse). FIX: recast each expert's Conv1d as an IMPLICIT GEMM
        (Y[t,co]=Σ_k Σ_ci Xshift_k[t,ci]·W_k[ci,co]) + REGISTER-TILE it — a CTA
        owns BM=64 time-steps × BN=64 out-channels, stages a weight tile to smem
        ONCE + REUSES it across all BM time-rows -> weight HBM traffic cut ~BM-fold.
