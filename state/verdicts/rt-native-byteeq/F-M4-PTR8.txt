================================================================================
GOAL (RT-NATIVE-ZEROC M4 PTR8 micro-PR): add `__hx_ptr_store8` / `__hx_ptr_load8`
byte (8-bit) raw-mem leaf intrinsics to BOTH codegen backends, byte-correct.
Completes M2's raw-mem set — M1 landed ptr_load/store 64/32 (#3478); the 8-bit
byte ops were the one gap, needed for `hexa_strbuf_dup_n`'s byte-write in batch B3.

SHAPE (identical to ptr32, single byte):
  __hx_ptr_store8(addr, off, val)  writes the LOW BYTE of val to [addr+off];
                                   returns addr (chainable).
  __hx_ptr_load8(addr, off)        reads the byte at [addr+off] ZERO-EXTENDED.

                                      (ldrb byte-load = the encoding proven by

HONEST RESIDUAL (c9, PRE-EXISTING M1-wide boundary, NOT introduced by ptr8):
  The native x86_64 ELF object emitter (compiler/emit/elf_x86_64.hexa) does NOT
  parse the `byte ptr`/`dword ptr`/`qword ptr` size-prefix mem-operand form, so
  `--emit=obj` of a program using ptr8 (or the pre-existing str_byte/ptr32/ptr64,
  which emit `dword ptr`/`qword ptr` labels) would ENCODE-MISS. M1 validated its
  leaves only via `--emit=asm` → GNU `as` (the gate's semantic path does the
  same), so this gap predates ptr8 and is shared by all raw-mem x86 leaves. It
  does NOT affect: (1) the asm-text codegen (byte-correct vs GNU as — proven
  above), (2) the C-transpile path (self/codegen.hexa mirror), (3) the self-host
  fixpoint (compiler never emits these ops). Extending the ELF emitter's
  size-prefix mem-operand parser is a separate, M1-wide unit out of this micro-
  PR's surgical scope. arm64 is CLEAN: its codegen emits bracket-only operands
  (`[x1]`, no size prefix), and the Mach-O encoder's STRB/LDRB encode to native
  object directly — arm64 `--emit=obj` works for ptr8.
