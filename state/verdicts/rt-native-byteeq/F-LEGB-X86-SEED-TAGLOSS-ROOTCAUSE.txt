 4) 어셈블리 대조 (arm64 작동 vs x86_64 버그):
    arm64: `stp x0,x1,[sp] ; ingress param 0` → {tag,payload} 16B 쌍 통째 저장,
           `ldp x0,x1; bl hexa_len` → tag=3 보존 → 정상.
    x86_64: `mov rsi,rdi #payload; mov rdi,0 #tag; call hexa_len` →
           (a) ingress 가 param0 payload 를 rsi(reg1) 아닌 rdi(reg0=tag)에서 읽음

               operand-kind 에서 파생 → local=TAG_INT(0) 강제 → string local 의 tag 소실.
    hexa_len 은 tag-dispatch(`if HX_IS_STR(v)`) → tag=0 → 0 반환 → 루프 0회 →
    빈 배열 → join → empty/null. 모든 HexaVal-param native 함수에 동일.

ROOT CAUSE: x86_64 codegen 의 payload-only "raw-int model" 이 HexaVal tag 를 통째로
  잃는다. arm64 는 {tag,payload} 쌍을 spill-slot 에 통째 carry(stp/ldp)하여 tag 보존.
  + ingress 레지스터 매핑 버그(payload 를 홀수 reg 아닌 짝수 reg 에서 읽음).
  → self-emit byte-eq PASS(일관됨) + int-only RUNG PASS(tag=0=int 우연일치) 라서
    "x86_64 codegen graduated" 가 과대평가였음(assembles/byte-eq ≠ runtime ABI 정확성).

  {tag,payload} 16B 쌍으로 carry — ingress(쌍 저장)·operand resolve(쌍 로드)·
  call arg/result(쌍 box/unbox)·spill(16B slot)·binop. = x86_64 backend value-model 재작업.
