ENABLING ROOT-CAUSE FIX (c1, NOT a shim) — const_float payload materialization:
  The x86_64 backend had NO const_float payload path at all (the #3462 pair
  model carried int/str/bool only). A float LITERAL resolved to the `imm 0`
  fallback in _x86_op_resolve → every float leaf operating on a literal computed
  against 0.0. FIX: _x86_op_resolve + _x86_64_op_for_operand_st now materialize a
  const_float payload as `mov reg, float_to_bits(v)` (the compile-time runtime
  builtin, also used by macho_arm64.hexa float-pool emit; GNU as encodes the
  imm64 mov as `movabs`). This matches arm64's `.LCfltN: .double` pool value
  while staying surgical (no X86StrTab float-pool subsystem needed).

SCRATCH-DISCIPLINE BUGS FOUND + FIXED (during verify, c2 — caught by run, not
self-judged):
  1. __hx_to_double used hardcoded `r12` as the tag scratch — but r12 is in the
     ALLOCATABLE pool (rbx/r12-r15), so it clobbered a live value whose home was
     r12. In a chained `flt(to_double(a), to_double(b))` the 2nd to_double read
     a's tag as b's payload. → tag scratch moved to `rax` (caller-saved, never
     pooled).
  2. __hx_syscall6 staged args into pool regs r12-r15/rbx (same clobber class).
     → args now load DIRECTLY into the syscall ABI regs (rdi/rsi/rdx/r10/r8/r9),
     all caller-saved + disjoint from the pool, so no live-value clobber and no
     cross-arg aliasing.

HONEST RESIDUALS (c9 — NOT faked parity; PRE-EXISTING x86 gaps ORTHOGONAL to the
leaves, out of M1 scope):
  • const_str → LOCAL ASSIGN (`let s = "ABC"`) still materializes a bare-label
    absolute address instead of a RIP-relative lea, so the byte at a str LOCAL
    is wrong. The leaf itself is correct on a DIRECT literal (lea rip-relative);
    the str test uses the direct-literal form. The const_str-assign fix is the
    same class as the const_float fix and is a natural M2 follow-up.
  • The x86_64 backend has NO `unop`/`!` (logical-not) lowering — it emits a bare
    `nop` and leaves the branch-test reg uninitialized. Affects any `!expr`, not
    these leaves; the core test asserts FALSE cases positively (poison +100 in a
    skipped if-body) to avoid the unimplemented `!`. Separate codegen milestone.
