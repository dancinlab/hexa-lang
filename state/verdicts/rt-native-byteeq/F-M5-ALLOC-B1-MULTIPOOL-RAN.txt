2. CODEGEN GAP FOUND (c9 — the first attempt FAILED, recorded honestly)
================================================================================
The FIRST PoC used module-global mutable state (`let mut __tbl = 0`, `let mut
__np = 0`). It emitted (emit rc=0) but FAILED at LINK:
    /tmp/mp.o: in function `tbl_base': undefined reference to `g0'
The shipping x86_64 backend lowers a module-global `let mut` int to a `g<id>`
symbol (g0, g1, …) but does NOT emit the .bss/.data slot that DEFINES it in a
standalone single-module emit — it expects the slot to come from the whole-
program data section the full compiler build provides. This is WHY the read-half
lane never hit this wall: array/map accessors carry NO global state (every op
takes its container as an arg), so they never reference a g<id>.

SIDESTEP (not a compiler edit — c10/c18, no escape-hatch added): hold ALL arena
state IN the mmap'd table region itself (pool count at header word, pool headers
after), threaded by the single `tbl` int returned from arena_init and passed to
every op. ZERO module globals → ZERO g<id> refs → links clean. The runtime.c
glue can keep that one `tbl` int in a C global and call arena_alloc(tbl, n), so
the runtime.c surface (hexa_ptr_alloc(size)) is unaffected — the global lives on
the C side, the hexa arena body is global-free.

  This g<id>-slot-definition gap is a REAL, separately-named residual for the
  full M5 standalone-relink (when native rt_*.o must define its own data slots),
  but it is NOT on the critical path for the arena body, which is global-free.
