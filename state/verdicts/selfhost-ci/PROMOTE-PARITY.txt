OBJECTIVE
  Promote the PARITY GATE — the precondition that AUTHORIZES flipping the
  default `hx`/hexa toolchain to the self-hosted native compiler (gen3) — into a
  STANDING per-PR CI check, so the promotion precondition CANNOT silently rot. A
  codegen / linker / runtime edit that would break gen3≡shipped equivalence must
  FAIL the PR, not surface only at the next manual promotion.

  Milestone text: "promote parity-gate as CI — tool/selfhost_parity_gate.sh 5/5
  behaviour-match runs in CI (the promotion precondition can't rot)".

WHAT THE PARITY GATE PROVES (the N=5 behaviour-match + 42-smoke)
  For each of 5 representative corpus programs, the self-hosted gen3 compiles
  (--emit=asm --target=arm64-apple-darwin) → clang -arch arm64 -c → hexa_ld link
  with rt.o (--lc-main _main) → RUN; the observed exit code must EQUAL the
  program's pre-registered `// expect: N` exit. BEHAVIOUR is the load-bearing
  axis (same observable semantics). The 5 behaviours:
    1. arith   — `6 * 7`            -> exit 42  (integer multiply)  [+ 42-smoke]
    2. call    — `add(6, 7)`        -> exit 13  (function call + return + add)
    3. branch  — while-loop count   -> exit 7   (mutable locals + control flow)
    4. bitmask — `255 & 0x0f`       -> exit 15  (bitwise AND + hex literal)
    5. recurse — `fac(5)`           -> exit 120 (recursion + multiply chain)
  A PASS = behaviour-match on ALL 5 AND the 42-smoke -> "PARITY PASS — promotion
  AUTHORIZED". The optional asm-parity axis (gen3 --emit=asm vs the shipped
  reference, normalised) is INFORMATIONAL unless --strict; the gate is BEHAVIOUR.

RESULT
  5/5 behaviour-match PASS  (arith / call / branch / bitmask / recurse) + 42-smoke
  RESULT: PARITY PASS — promotion AUTHORIZED (gate exit 0)

    reference build; it is intentionally informational (the script's own doc).
