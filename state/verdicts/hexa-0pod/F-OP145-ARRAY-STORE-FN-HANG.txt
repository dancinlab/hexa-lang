 ROOT CAUSE (generated-C witness, frozen-seed hexat)
────────────────────────────────────────────────────────────────────────────────
  hexat transpile of `let i=0; while i<3 { i=i+1 }`:
      HexaVal i = hexa_int(0);
      while (HX_BOOL(hexa_cmp_lt(hexa_int(0), hexa_int(3)))) {   // i CONST-FOLDED
          i = hexa_add(i, hexa_int(1));                          // live i updated
      }
  vs `let mut i=0`:
      while (HX_BOOL(hexa_cmp_lt(i, hexa_int(3)))) {             // reads live i ✓

  The codegen const-folds `let x = <lit>` to its literal and inlines reads
  (self/codegen.hexa §"PROBE r11 B3", ~L3099). The fold is invalidated on a
  plain Ident reassignment (AssignStmt arm, ~L3225) — but the AssignStmt is
  emitted AFTER the loop condition, so the condition was already folded with the
  stale `0`. `i < 3` becomes `0 < 3` (always true) → non-terminating loop.

  hexa's `let` is REASSIGNABLE (no enforced immutability): `let i = 0; … i=i+1`
  appears 162× in shipped stdlib/self/compiler source (map_arr/filter/reduce/
  sort all use it), so this idiom MUST work — it is not a missing-`mut` lint.
