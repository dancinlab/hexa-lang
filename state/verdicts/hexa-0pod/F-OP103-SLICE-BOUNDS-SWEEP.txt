CLASS
-----
Code computes a slice / window / substring range (start,end) or an array index from
arithmetic (length, stride, k, n-1, center±radius, frame*hop, row*cols+col) and accesses
it WITHOUT clamping to [0,len], so a degenerate / boundary input (empty, len-1, k>len,
window past end, <2-node mesh) drives the index out of [0,len] → crash or garbage.

THE 🔴 FIX — bar1d FEM degenerate mesh out-of-range
---------------------------------------------------
FILE: stdlib/kernels/fem/bar1d_kernel.hexa
CONTRACT (docstring L157): nodes length n >= 2. The public bar1d_solve_fixed_free has NO
guard on n. For a degenerate mesh the reduced system has m=n-1<=0 unknowns, and the
private Thomas solver runs its forward sweep UNCONDITIONALLY:
    cp[0]=c[0]/d[0]   dp[0]=b[0]/d[0]   ...   u[m-1]=dp[m-1]
On an empty diagonal (m=0): c[0]/d[0]/u[-1] on a length-0 array → crash.

  n=0: thomas_tridiag([],[],[],[])
    stdout: n=0 -> thomas([],[],[],[]):index 0 out of bounds (len 0)
  root cause probe: `let e=[]; e[0]` → `len=0index 0 out of bounds (len 0)`
