CONTEXT (what OP-40 #3084 established, that OP-42 reflects)
────────────────────────────────────────────────────────────────────────────
OP-40 root-caused the OP-37b 1-ULP comptime-fold residual NOT to the multiply
(IEEE-correct) nor the parse (byte-exact post-OP-37b) but to the host's
hand-rolled %.17e fold SERIALIZE (rt_format_float_sci / hxlcl_vsnprintf — own
comment "Not bit-exact with libc's"), drifting 16/125 (≈13%) computed folds by
1 ULP. FIXED by serializing the folded double as a bit-exact C99 hex-float
literal (0x1.<mant>p<exp>, integer ops only) that clang re-parses with ZERO loss
→ MAX 0 ULP. OP-40's own DETERMINISM CONTRACT NOTE flagged that the contract MAY
gain a clause but explicitly deferred it ("out of OP-40's measure+fix scope;
defer to a docs milestone"). OP-42 IS that milestone.

WHAT THE CONTRACT GAINED (docs/flame-determinism-contract.md)
────────────────────────────────────────────────────────────────────────────
NEW subsection "compile-time constant folding — bit-exact hex-float serialize"
in §1 (right before "per-phase locked identities"), framed as a COMPILE-STEP
sibling of the 3 run-step layers:

(a) the compiler const-folds let-bound float-literal expressions at comptime
    (comptime_eval in self/codegen.hexa) and inlines the folded constant at every
    use-site as a literal the C backend re-parses;
(b) RULE block — the folded constant is serialized as a bit-exact C99 hex-float
    literal (0x1.<mant>p<exp>, built from IEEE-754 bits with integer ops only) so
    clang re-parses it to the EXACT double with ZERO precision loss; NOT via
    decimal %g/%e (a hand-rolled formatter is not correctly-rounded and drifts
    the bits) — cites F-OP40 + the tool/op39_constfold_gate.sh tripwire;
(c) WHY-for-determinism — a const-fold that drifts 1 ULP makes the SAME source
    compile to different float bytes depending on the host's printf, breaking
    machine-independence at the COMPILE step (before the program runs). Tied to
    the OP-37/OP-40 MEASURED evidence (bits-182 → "…117067" → bits-183 1-ULP
    round-trip; coarser 6-digit %g in OP-37) and to the existing 3-layer model
    (explicitly INDEPENDENT of the FMA layer — purely host-side serialization,
    cross-ISA -ffp-contract policy unaffected). Cross-linked to the CHECKPOINT
    phase (which reinterprets fp64 bit-patterns for the same "decimal text is
    lossy" reason).

Plus ONE bullet in the "what breaks the contract" checklist: "A lossy
COMPILE-TIME float const-fold serialize" (bake hex-float not %g/%e; F-OP40;
locked by the 18-fold gate). Terse, current-state framing (g3, elephant rule —
states the guarantee, not the bug history).
