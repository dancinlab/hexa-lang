THE BUG (🔴)
-----------
stdlib/codec/base64.hexa base64_decode():
  let m = len(idxs)               // count of NON-PADDING alphabet chars
  ...
  while j + 3 < m { ... emit 3 bytes per 4-char group ... j = j + 4 }
  let trim = if pad > 2 { 2 } else { pad }
  let final_len = len(out) - trim ; ... return out.slice(0, final_len)

The loop only processes FULL 4-char groups, then trims `pad` bytes. But a padded
message's non-pad char count m is NEVER a multiple of 4 — it is 2 or 3 (mod 4) exactly
when there is padding. So the TRAILING 2/3-char group is ALWAYS dropped, and the
`trim` step can never recover it. Result: encode∘decode is the identity ONLY for inputs
whose byte-length is a multiple of 3. RFC 4648 §10 trace (faithful port, verbatim):

  'f'       enc=Zg==     OLD_decode=[]                 want=[102]
  'fo'      enc=Zm8=     OLD_decode=[]                 want=[102, 111]
  'foo'     enc=Zm9v     OLD_decode=[102, 111, 111]    want=[102, 111, 111]      (ok)
  'foob'    enc=Zm9vYg== OLD_decode=[102]              want=[102, 111, 111, 98]
  'fooba'   enc=Zm9vYmE= OLD_decode=[102, 111]         want=[102, 111, 111, 98, 97]
  'foobar'  enc=Zm9vYmFy OLD_decode=[102,111,111,98,97,114]  want=same             (ok)

CO-LOCATED BUG (same module): base64.hexa called `bytes_to_str(out)` / `bytes_to_str(
base64_decode(s))`, but `bytes_to_str` is NOT a registered builtin and is NOT imported
(it is a hexa fn local to stdlib/ckpt/format.hexa). So the module does NOT COMPILE
standalone — verbatim, against the unmodified installed module:
  build/.../base64.hexa.c:99: error: use of undeclared identifier 'bytes_to_str'
This is why it had no test: it was unbuildable in isolation.

THE FIX (doc + source; no behavior beyond making the contract hold)
------------------------------------------------------------------
1. Decode: process full 4-char groups (while j + 4 <= m), THEN decode the trailing
   partial group from the char count alone — 2 idxs → 1 byte, 3 idxs → 2 bytes (a lone
   trailing idx, rem==1, is incomplete and dropped). This mirrors the proven streaming
   accumulator in self/runtime/base64_pure.hexa (emit a byte whenever vbits >= 8).
   The old `trim`-by-pad scheme is removed; padding is now tolerated but not
   load-bearing (the alphabet-char count carries the length).
2. Build: bytes_to_str(...) → bytes_to_str_raw(...) (the registered NUL-clean raw-byte
   constructor used across stdlib net/runtime), making the module self-contained.
3. Doc: the "padding required for canonical roundtrip" invariant corrected to the true
   "tolerated but not load-bearing; encode∘decode is the identity for any byte-length".
