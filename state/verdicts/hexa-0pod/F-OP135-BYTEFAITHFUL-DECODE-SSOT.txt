CLAIM
-----
The byte-faithful "raw bytes → UTF-8 string" decode — re-found as the SAME bug
class by OP-79/125/127/128/133 — now has a SINGLE source of truth: every
module-local reimplementation that is genuinely "raw bytes → string" CALLS the
canonical `bytes_to_str_raw` builtin instead of carrying its own loop. The next
fix lands once; the class cannot re-diverge through these sites.

ROOT CAUSE (the recurrence)
---------------------------
Two duplicated decode shapes proliferated as module-local helpers:
  A. `from_char_code(byte)` per byte → RE-UTF-8-ENCODES every byte ≥0x80 →
     mojibake ("안녕"→"ìëª"). THE BUG (OP-79/125/127/128/133 each re-found it).
  B. `chr(byte)` + `.join("")` → byte-faithful per byte (chr=hexa_chr_byte,
     N&0xFF) BUT the join derives length via the NUL-truncated C string, so any
     embedded 0x00 collapses the tail. Latent, not yet bitten in prod.
Both are eliminated by routing through `bytes_to_str_raw`, which assembles
NUL-clean via an explicit length header (hexa_strbuf_alloc) — the ONE builtin.
(See self/codegen.hexa:7196-7221 for the chr / from_char_code / bytes_to_str_raw
lowering contract.)

CROSS-TREE NOTE (accepted constraint)
-------------------------------------
stdlib/ and self/stdlib/ are TWIN trees (the self/ mirror exists because the
build_selfhost closure can't import the live stdlib). The hxc_a* codecs live
ONLY under self/stdlib/ (no stdlib/hxc_* twin), so there is no cross-tree
duplication to reconcile for them. safetensors HAS a twin (stdlib + self) — both
copies were already redirected by OP-125 and remain byte-identical. The builtin
`bytes_to_str_raw` IS visible in every self/ module (it lowers to the C
constructor hexa_bytes_to_str_raw in codegen, no stdlib import needed), so the
consolidation crosses the tree boundary cleanly — no residual cross-tree
duplication of the byte-faithful decode remains.
