COMPONENT 1 — AEAD per-record NONCE (RFC 8446 §5.3)      🟢 GREEN
  tls13_record_nonce(iv, seq): copies the 12-byte write_iv, then XORs seq as a
  64-bit big-endian counter into the LAST 8 bytes (positions 11..4 from the tail).
  RFC 8446 §5.3: "The per-record nonce ... is the sequence number ... padded to
  iv_length ... then XORed with the static client_write_iv/server_write_iv."
  iv = 5d313eb2671276ee13000b30 (RFC 8448 §3 server write_iv):
    seq=0           -> 5d313eb2671276ee13000b30   (== iv unchanged) ✓
    seq=1           -> 5d313eb2671276ee13000b31 ✓
    seq=2           -> 5d313eb2671276ee13000b32 ✓
    seq=255         -> 5d313eb2671276ee13000bcf ✓
    seq=256         -> 5d313eb2671276ee13000a30 ✓
    seq=2^32        -> 5d313eb2671276ef13000b30 ✓ (carries into byte 7-from-tail)
  - nonce(seq) == iv XOR pad12(seq) for ALL seqs (matches RFC §5.3 reference): YES
  - all 6 nonces DISTINCT (no reuse): YES
  - seq=0 leaves iv unchanged: YES
  SEQUENCE COUNTER: 64-bit `int`, caller-managed monotonic per-direction; send
  returns seq+1 (increment exactly once per record); recv bumps after a successful
  open; resets to 0 per key epoch (KeyUpdate = tls13_client_keyupdate.hexa, a new
  traffic secret + fresh seq). No path reuses or wraps a (key, nonce) pair.
  NO nonce-reuse bug.
