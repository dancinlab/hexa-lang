RESULT: a LOW-BLAST-RADIUS regression gate that locks the OP-19e (#3029) musl
env-capture fix. It asserts, on the OP-19e patch SOURCE
(tool/restore_frozen_seeds), that the priority-101 env-capture constructor it
injects into the restored self/runtime.c uses the musl-safe POSIX `environ`
form and NOT the glibc/Darwin-only constructor-args ABI. PASSES on the current
(OP-19e-fixed) tree; demonstrably CATCHES an injected args-ABI regression; can
NOT false-fail on unrelated code. PROVEN LOCALLY (0-GPU, pure grep, $0).

Honest framing: CI does NOT run under musl, so this is a STATIC source-pattern

source pattern the musl SIGSEGV depends on — the cheapest effective guard.

────────────────────────────────────────────────────────────────────────────
WHAT OP-19e FIXED (the regression target)
────────────────────────────────────────────────────────────────────────────
The frozen self/runtime.c captured the process environment via the GCC/Darwin
constructor-args ABI:
    hxlcl_capture_environ(int argc, char**argv, char**envp){ hxlcl_environ = envp; }
Receiving (argc,argv,envp) in a constructor is a glibc + Darwin/dyld extension,
NOT in the C/ELF standard. musl runs constructors with NO arguments, so `envp`
is a garbage register -> hxlcl_environ = garbage -> the first hxlcl_getenv
(driven by the priority-default arena init _hexa_init_mem_cap, which runs AFTER
this priority-101 ctor) walks a wild pointer -> SIGSEGV before main().

OP-19e rewrote the patch in tool/restore_frozen_seeds to emit instead:
    extern char **environ;
    static char **hxlcl_environ = 0;
    __attribute__((constructor(101)))
    static void hxlcl_capture_environ(void) { hxlcl_environ = environ; }
    #define environ hxlcl_environ
reading the POSIX `environ` global (defined by EVERY libc incl. musl). Behavior-
preserving on glibc/Darwin (same env vector), fixes musl.

REGRESSION RISK: a future runtime/seed edit, a manual revert, or a frozen-seed
regen drops this patch / re-adds the args-ABI capture form -> musl SIGSEGV
returns silently (CI doesn't run under musl). OP-26b gap G6 = "musl ctor-ABI
fix CI-gate (LOW)". THIS gate closes G6.

────────────────────────────────────────────────────────────────────────────
THE GATE MECHANISM (static grep guard — tool/musl_ctor_abi_gate.sh)
────────────────────────────────────────────────────────────────────────────
1. Reads ONE file: tool/restore_frozen_seeds (the OP-19e patch source).
2. Extracts ONLY the awk-EMITTED C code of the env-capture patch — the payload
   of each `print "..."` directive, then DROPS `//` C-comment payloads. What
   remains is exactly the real C the patch injects into runtime.c. The
   explanatory shell `#` prose and emitted `//` comments — which legitimately
   spell out the OLD bad `(argc,argv,envp)` signature — are STRUCTURALLY EXEMPT
   and can never trip the gate.
3. Within that narrow emitted-C scope:
   (1) MUST be present — the musl-safe POSIX-environ capture definition:
         hxlcl_capture_environ(void) { hxlcl_environ = environ; }
   (2) MUST be absent — either smoking gun of the args-ABI capture:
         hxlcl_capture_environ(int ...      (a signature taking ctor args), OR
         hxlcl_environ = envp               (capture from the ctor-arg envp)
   Either, if EMITTED into the runtime, re-introduces the musl SIGSEGV.
4. exit 0 = OP-19e form intact; exit 1 = args-ABI regressed / safe form missing.

Mirrors the OP-5b discipline (tool/forge_runtime_warn_gate.sh): guard ONLY the
clean thing, scoped so it can't false-fail on grandfathered/unrelated code.
CI wrapper: .github/workflows/musl-ctor-abi-gate.yml, paths-scoped to
tool/restore_frozen_seeds + tool/musl_ctor_abi_gate.sh + the workflow itself.
