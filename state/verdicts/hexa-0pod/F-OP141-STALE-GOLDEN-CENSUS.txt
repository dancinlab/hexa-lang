 2. WHY EACH NON-erf FLOAT SURFACE IS NOT STALE (the discriminating proofs)
────────────────────────────────────────────────────────────────────────────────
  (a) tool/op39_constfold_gate.sh — CLEAN BY CONSTRUCTION. It is the regression
      tripwire CREATED by OP-39/OP-42 (#3091, 2026-06-12 15:51) AFTER the fix.
      Its goldens ARE the fixed-compiler output: the NEG/SUB/ADD0 idioms are
      python struct.pack('<d',...) ground truth (byte-exact), the MUL_HF* are the
      hex-float-serialized correctly-rounded products (the very path OP-40 fixed).
      It cannot be stale — it asserts the post-fix invariant; a regression to the
      OLD %g/%.17e serialize is what it CATCHES.

  (b) dt_exp (GOLD_CEBWD 7679248634312321699) — UNAFFECTED. Its constants are
      0.25/1.0/2.0/12, which serialize bit-identically under the lossy AND the
      shortest-round-trip path (OP-138 already established this; confirmed here:
      dt_exp matched its golden on all 3 CI platforms while dt_erf drifted).

  (c) *_eq.hexa agreement/determinism oracles (op29 decoder-block,
      op33 LR-schedule, op72 d5-trig, op74 moe-exp, op76/op78 shape-contract,
      clm_prod_crossplatform_exact, op35 ckpt) — STRUCTURALLY MASKING-IMMUNE.
      Each computes TWO values at runtime and asserts a DELTA within tolerance
      (e.g. check_agree() returns a float deviation) — it NEVER compares to a
      pinned constant. An equality oracle cannot encode a stale golden, and it
      cannot "mask" via a stale recompute path because both sides are recomputed
      by the SAME current compiler each run (a real divergence would still fire).
      Additionally: NONE of these are wired into any CI gate with a pinned value
      (grep tool/ + .github/ = 0 references) — they are self-checking oracles.

  (d) op19b_crossplatform_erf.hexa — has NO internally-pinned numeric golden; it
      only prints f64_to_bytes bit-dumps for fold_ci_gate.sh to assert EXTERNALLY.
      The golden lives solely in fold_ci_gate.sh (re-pinned by OP-138). git diff
      of op19b vs its creation commit is empty — source unchanged; only the
      external golden was stale, and that is fixed.

  (e) JSON fixtures (fixtures/**/golden_*.json) — INTEGER / BYTE goldens
      ("expected": 72623859790382856 = 0x0102030405060708 BE-fold; hex/byte
      arrays; JSON-dump string snapshots). No float const-fold path. Pure
      arithmetic, host-independent. UNAFFECTED.

  (f) bench/snapshots/*.hexa — codegen-SHAPE snapshots (arg layout, builtin
      mangling, JSON helpers, string-method coverage). No pinned float values.

  (g) determinism_gate.sh / miscompile_zero_gate.sh — assert byte-IDENTITY
      (emit twice → cmp; clean ENCODE-MISS/udf). No pinned numeric value at all,
      so nothing to be stale. flame_steppath_{fma,libm}_gate.sh are purely
      LEXICAL grep tripwires (no number). dojo_rent_preflight thresholds are
      integer config (2^31, 3B params), not folds.

  (h) archive/fires/** — GPU PTX/CUDA/Metal perf baselines, dated, ARCHIVED, not
      a compile-time float-fold class and not an active CI gate. OUT-OF-SCOPE.

 4. MASKING CHECK (the "GREEN but stale" failure mode) — NONE FOUND
────────────────────────────────────────────────────────────────────────────────
  A masking golden = a test that "passes" because it recomputes the expected
  value via the SAME stale path instead of comparing to a fixed pinned constant.
  Audited every float surface:
   · fold_ci_gate.sh / op39_constfold_gate.sh compare against HARD-CODED string
     constants (GOLD_*) — they would go RED on drift, not mask. (fold_ci did go
     RED → OP-138; op39 is post-fix.)
   · the *_eq.hexa oracles compute both sides each run, but they assert a
     tolerance on a DELTA, not equality to a recomputed golden — a true
     divergence still trips them; they are determinism oracles, not pinned
     goldens, so "masking a stale value" is not applicable.
  Conclusion: no surface silently passes by recomputing a stale value.
