[1] HOW THE MATRIX WAS BUILT (g5)
---------------------------------
Stage 1 — static cross-ref: each of the 231 roster names vs (codegen-explicit ∪ runtime.h ∪
  runtime.c, with prefix variants). Names matching → provisional REAL; no match → candidate.
Stage 2 — EMPIRICAL probe (authoritative): `fn main(){ let _r = NAME(<correct args>); println
  ("OKMARK") }` compiled+run via the FRESH installed hexat (~/.hx/bin/hexa run → ~/.hx/bin/
  build/hexat → clang). REAL = prints OKMARK (or fails only with a TYPE error = symbol resolved);
  FALSIFIED = generated C contains "undeclared identifier/function 'NAME'".
  The installed binary roster is a SUPERSET (235 = baseline 231 + the 4 names OP-33c/d already
  removed) so every probe type-checks at the hexa level → any failure is a genuine runtime-impl
  falsification, not a binder rejection.
CAVEAT (recorded for reproducibility): a GENERIC-arg probe is UNRELIABLE. codegen-inline
  lowering is arg-COUNT/SHAPE gated (`if name=="matmul" && len(args)==5`, softmax 1-arg,
  layer_norm 3-arg, …); a wrong shape falls through to the undeclared-bare-name fallback and
  yields a FALSE "undeclared" for a REAL builtin (e.g. an initial generic probe mislabeled
  gelu/silu/randn/argmax/sum/keys as falsified). CORRECT per-builtin args are required. The
  symmetric hazard: the static cross-ref OVER-counts REAL (a name appearing as a substring of
  a runtime symbol, e.g. slice/embedding/reduce/to_upper, can still be AOT-falsified). Hence
  the boundary between REAL and FALSIFIED for arg-shape-gated names carries ± a few entries;
  the OPTIMIZER-FAMILY closure (§3) was pinned to the strict per-builtin g5 standard and is
  NOT subject to that uncertainty.
