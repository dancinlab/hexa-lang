GOAL
  OP-19d (#3027) proved 4-environment machine-independence (Darwin · glibc-x86 ·
  glibc-arm64 · musl-x86) of flame's deterministic dt_exp/dt_erf folds, but to run
  ANYTHING on native musl it needed a disclosed TEST-ONLY runtime shim — because it
  surfaced a REAL hexa-runtime↔musl portability bug: the priority-101 environ-capture
  constructor crashes before main() on musl. OP-19e is the durable fix for that bug.

────────────────────────────────────────────────────────────────────────────────
 1. THE BUG (verbatim root cause)
────────────────────────────────────────────────────────────────────────────────
  self/runtime.c (frozen seed 151c52c8…, "RUNTIME tail (cycle 85)") owns the environ
  global via a priority-101 constructor that runs BEFORE the default-priority arena
  init (_hexa_init_mem_cap → hxlcl_getenv):

      static char **hxlcl_environ = 0;
      __attribute__((constructor(101)))
      static void hxlcl_capture_environ(int argc, char **argv, char **envp) {
          (void)argc; (void)argv; hxlcl_environ = envp;
      }
      #define environ hxlcl_environ

  The `(int argc, char **argv, char **envp)` constructor signature is a glibc + Darwin/
  dyld EXTENSION, NOT in the C/ELF standard:
    · Darwin/dyld passes (argc, argv, envp, apple) to every __mod_init_func routine.
    · glibc's __libc_csu_init forwards (argc, argv, envp) to .init_array entries.
    · musl runs constructors with NO arguments (do_init_fini / __libc_start_init).
  So on musl `envp` is whatever garbage sits in the 3rd arg register at ctor time →
  hxlcl_environ = garbage → the FIRST hxlcl_getenv (driven by the arena init, which
  runs AFTER this priority-101 ctor) walks a wild pointer → SIGSEGV before main().
  OP-19d's gdb backtrace: SIGSEGV in hxlcl_getenv ← _hexa_init_mem_cap (constructor)
  ← musl do_init_fini / __libc_start_init.

────────────────────────────────────────────────────────────────────────────────
 2. THE FIX — POSIX `environ` global (musl-safe, behavior-preserving)
────────────────────────────────────────────────────────────────────────────────
  Read the POSIX global `extern char **environ` (defined by EVERY libc — glibc, musl,
  AND Darwin's crt1 for the main executable) instead of the constructor-args envp.
  The constructor STILL runs at priority 101 (before the arena init) and still snapshots
  into hxlcl_environ, so hxlcl_getenv downstream is byte-for-byte unchanged:

      extern char **environ;
      static char **hxlcl_environ = 0;
      __attribute__((constructor(101)))
      static void hxlcl_capture_environ(void) { hxlcl_environ = environ; }
      #define environ hxlcl_environ

  The `extern char **environ;` is emitted BEFORE the `#define environ hxlcl_environ`
  shadow, and the constructor body references `environ` on the line ABOVE the #define,
  so it binds to the LIBC symbol (not the macro). On glibc/Darwin the ctor-arg envp and
  the libc `environ` global point at the SAME process-environment vector at start, so
  the captured env is IDENTICAL → BEHAVIOR-PRESERVING. On musl it is a real pointer
  instead of a garbage register → FIXED. No more reliance on the non-standard ctor ABI.
