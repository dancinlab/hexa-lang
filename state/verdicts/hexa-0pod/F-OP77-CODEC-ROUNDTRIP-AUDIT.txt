THE BUG (🔴) — hex.hexa + utf8.hexa: un-imported ckpt bytes_to_str
-----------------------------------------------------------------
Both modules call bytes_to_str(out) to turn a byte array into a string:
  hex.hexa:43   _hex_encode_table  → return bytes_to_str(out)
  hex.hexa:98   hex_decode_str     → return bytes_to_str(hex_decode(s))
  utf8.hexa:142 utf8_from_codepoints→ return bytes_to_str(out)
bytes_to_str is defined ONLY in stdlib/ckpt/format.hexa (a `pub fn`, NOT a
registered codegen builtin) and is NEVER imported by hex.hexa / utf8.hexa. Every
sibling multibyte codec EXPLICITLY noted this and inlined its own converter to
dodge it (verbatim from euc_kr.hexa:12-13 / cp949.hexa:11 / gbk / big5 / shift_jis
/ unicode_normalize: "utf8 references bytes_to_str (defined in stdlib/ckpt/format)
without importing it, which only resolves in a full-stdlib build, not a standalone
codec build"). hex and utf8 did NOT — exactly the OP-75 co-located build bug.

TWO defects, both cured by switching to the REGISTERED builtin bytes_to_str_raw
(raw byte buffer; self/codegen.hexa:7209 `if name == "bytes_to_str_raw"`):
  (1) STANDALONE-BUILD FAILURE: `hexa build stdlib/codec/{hex,utf8}.hexa` cannot
      resolve bytes_to_str (it is only in scope in a full-stdlib closure).
  (2) utf8 DOUBLE-ENCODE (latent CORRECTNESS bug): utf8_from_codepoints assembles
      a RAW UTF-8 byte sequence in `out`. The ckpt/format bytes_to_str does
      `to_string(from_char_code(b & 0xFF))` per byte — i.e. it treats each RAW
      BYTE as a CODEPOINT and re-UTF-8-encodes it, double-encoding every byte
      >=0x80 into mojibake. Verbatim cross-check (faithful Python port):
        utf8_from_codepoints([0xD55C])  → raw bytes ED 95 9C
          via bytes_to_str_raw (raw buffer)      → '한'  CORRECT
          via bytes_to_str(ckpt, per-codepoint)  → 3 mojibake chars  WRONG
  hex output is pure ASCII (<0x80) so raw == per-codepoint there (encode result
  byte-identical); raw is ALSO the correct "bytes-as-string" semantics for
  hex_decode_str's high bytes.

THE FIX (source) — 3 call sites:
  hex.hexa:43,98  bytes_to_str → bytes_to_str_raw
  utf8.hexa:142   bytes_to_str → bytes_to_str_raw

NEW stdlib/codec/utf8_test.hexa (@sentinel __HEXA_CODEC_UTF8__)
matching the stdlib/codec/*_test.hexa convention (RFC golden vectors + boundary
