================================================================================
MOTIVE — the unguarded-inner-read bug class (security)
================================================================================
A length-prefixed binary parser reads a LENGTH field from untrusted wire bytes
then copies that many DATA bytes. The trap: the copy loop trusts the declared
length WITHOUT checking it fits the buffer. On a truncated/malicious frame the
loop reads past the array end — a runtime OOB fault (or, in a non-bounds-checked
runtime, memory disclosure). The correct pattern guards EVERY inner byte read
against len(buffer), yielding a graceful short/empty value. OP-104 fixed one
such site (cert_authorities). This round sweeps the entire family.

Note on the INNER continuation loop (der_oid_str): the base-128 OID arc loop
`while more == 1 { ... if (by & 0x80) == 0 { more = 0 } }` had NO buffer bound —
a truncated OID whose final byte still sets the continuation high bit runs the
inner loop past the buffer end. The fix bounds it: `while more == 1 && voff + i
< len(b)`.

================================================================================
FIX (minimal, net-additive — mirrors OP-104 / alpn)
================================================================================
Each inner copy/scan loop gains the buffer-end guard
  while i < declared && base + i < len(buf) { ... }
so a truncated/malicious declared length yields a graceful SHORT/empty value,
never an OOB read. Additional leading guards: der_oid_str gets
`if voff >= len(b) { return "" }` for its `first` byte; der_int gets
`voff < len(b)` on the sign-bit read; x509_rsa/x509_p256 add `start < len(...)`
to the strip-leading-zero scans. 9 source files touched, all closure-OUT.

POST-FIX CROSS-CHECK (shipping `hexa run`, fixed bodies):
  - tls13_ch_session_id on the truncated input → 0 bytes (graceful); on a
    well-formed 5-byte session_id → [100,101,102,103,104] exact.
  - der_value_len on [0x30,0x82,0x01] → 0x01 (partial, no fault); well-formed
    [0x30,0x82,0x01,0x00] → 256; short form [0x04,0x05] → 5.
  - der_oid_str on [0x2a,0x86] vlen=3 → no fault; well-formed RSA prefix
    [0x2a,0x86,0x48,0x86,0xf7,0x0d] → "1.2.840.113549" exact.
  - tls13_cr_context on [4,0xAA,0xBB] → [0xAA,0xBB] (graceful 2 bytes).
