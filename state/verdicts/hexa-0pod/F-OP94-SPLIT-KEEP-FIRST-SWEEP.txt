==============================================================================
MOTIVE
==============================================================================
The split-on-every-delimiter-keep-first bug class recurred in 5 prior ops:
  OP-91 parse_query, OP-92 parse_request, OP-75 base64, OP-90 argparse,
  OP-87 dirname.
Pattern: code does `x.split(SEP)` then uses a FIXED index ([0]/[1]/parts[1])
when the INTENT is "split on the FIRST (or LAST) delimiter only" — so any
input containing SEP more than once is silently truncated/corrupted.
This round did a high-leverage GREP CENSUS to find+classify+fix every
remaining LANE-2 instance at once.

==============================================================================

stdlib/http_sse.hexa, stdlib/websocket.hexa, stdlib/string.hexa,
stdlib/core/string.hexa.
EXCLUDED: stdlib data-structure/numeric/parser (= LANE-1 territory);
self/* (= self-host closure — flag only, do not fix).
Patterns grepped: `.split(` `.partition(` `.index_of(` `.last_index_of(`
`substring(` and fixed-index uses ([0]/[1]/parts[i]/kv[i]) of the result.
