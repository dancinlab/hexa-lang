================================================================================
MOTIVE — the unbounded-write bug class
================================================================================
A decoder / scatter / histogram / grid writer computes a destination index
from input-derived data (a token id, a parsed bond endpoint, a bin value, a
grid coordinate, a permutation entry) and writes into a buffer that was
pre-allocated to a FIXED size. The trap: if the index can exceed the dest
size and the write is unguarded, the store lands past the array end — an OOB
write that corrupts adjacent memory or faults. The correct pattern keeps the
write index in range by (a) using the LOOP COUNTER as the index (always
bounded by the loop condition), (b) CLAMPing the data-derived value to
[0, len-1] before the write, (c) GUARDing the write with an explicit
in-range conditional, or (d) sizing the dest to the maximum possible index.

NEW stdlib/info/oob_write_bound_op117_test.hexa — shipping `hexa run` →
  `OP117 oob-write-bound pass=20 fail=0` then `ALL GREEN`.
Re-derives the two representative protective patterns verbatim:
  Pattern A (clamp): a histogram-bin assembly into a fixed n_bins dest with
    the bin value clamped to [0,n_bins-1] (binning.hexa). Drives raws
    {-3,0,3,7,8,13} — values that UNCLAMPED would index -3..13 (OOB both
    directions) — and asserts every clamped write lands in [0,n_bins),
    dest length unchanged, total writes == #inputs (no neighbour corrupt).
  Pattern B (guard): a guarded scatter into a pre-sized rows*cols grid
    (hofstadter.hexa / core_kmeans.hexa). In-range (2,3) writes; OOB row
    (rows+7), OOB col (cols+2), and negative coords all return -1 -> caller
    skips -> NO OOB write; grid length unchanged, exactly one cell written.
  NEGATIVE CONTROL: asserts the UNPROTECTED indices (raw 13 >= n_bins=8;
    flat (rows+7)*cols = 55 >= 20) really do escape the dest range — so the
    clamp/guard is load-bearing, not a no-op.
