F-OP5B-WARN-GATE — forge-runtime warning-hygiene CI gate (LOCAL, 0-GPU)
=======================================================================
Goal: lock in the OP-5 (#2973) -Wcomment cleanup so the same defect class
cannot silently re-land in the forge/runtime header surface — WITHOUT a
repo-wide -Werror that would fail CI on grandfathered warnings elsewhere.

Option chosen: OPTION A (hard gate, fail-only-on-new-warning, scoped to the
already-clean files). Low blast radius by construction (see below).

GPU: NONE. Pure build-level syntax check (clang -fsyntax-only). No kernel run.

------------------------------------------------------------------------
WHAT IS GUARDED (explicit OP-5-clean allow-list)
------------------------------------------------------------------------
The gate compiles ONLY these files, each verified -Wcomment-clean on the
current tree before being added to the list:
  * self/runtime.h                 <- the file OP-5 (#2973) actually cleaned
  * self/forge/forge_tier_v1.h     <- forge tier header (sibling, clean)
  * self/native/lora_cuda.h        <- forge CUDA host header (sibling, clean)

OP-5 fixed a `-Wcomment` defect at self/runtime.h:422-423: a `native/*.c`
glob written inside a `/* ... */` block comment formed a nested `/*` token
that clang flags. This gate re-checks that exact class.

------------------------------------------------------------------------
GUARD MECHANISM
------------------------------------------------------------------------
Script (SSOT, locally runnable): tool/forge_runtime_warn_gate.sh
CI wrapper:                       .github/workflows/forge-runtime-warn-gate.yml
                                  (PR-on-main, paths-scoped to the guarded
                                  files + the script + the workflow itself;
                                  also workflow_dispatch)

For each allow-listed file:
  $ clang -fsyntax-only -Wcomment -Werror -x c <file>
  rc != 0  => a nested-comment regression -> gate FAILS (exit 1)
  rc == 0  => clean

Why it is genuinely low blast radius (a reviewer can see at a glance):
  1. Compiles ONLY the explicit allow-list. Nothing else in the tree is
     touched, so grandfathered warnings ANYWHERE else can never fail it.
  2. Enables ONLY -Wcomment (the exact class OP-5 cleaned). It is a purely
     LEXICAL check (nested `/*` inside a comment) — no CUDA toolchain, no
     project includes, no type definitions needed; each file is compiled
     stand-alone via `-x c`. (self/runtime.h also passes a full
     `clang -fsyntax-only -x c` with exit 0 — it is self-contained.)
  3. Adding a file requires confirming it exits 0 on the current tree first,
     so the gate is guaranteed to pass on a clean checkout (no false-positive
     CI break, including on this PR's own CI).
  4. Falls back clang -> gcc -> cc (all implement -Wcomment identically);
     resolves repo root via `git rev-parse`, so it runs from any CWD.
