GATE (g5) — byte-eq vs prior trainer dW:  HELD  ✅
  harness: stdlib/flame/clm_prod_transpose_elim_eq.hexa (CPU oracle, `hexa run`, 0-pod)
  F-OP2-TRANSPOSE-ELIM-BWD-EQ = 1
    dW max|Δ|  T8  C4   K3 d1 = 0.0
    dW max|Δ|  T8  C4   K3 d2 = 0.0
    dW max|Δ|  T16 C6   K3 d1 = 0.0
    dW max|Δ|  T12 C5x7 K4 d2 = 0.0
  PASS — im2col+matmul_t dW == im2col_t+matmul dW byte-eq (max|Δ|=0, all 4 cases).
  WHY bit-exact: xcolT[j,t] == xcol[t,j] (same gather value) and the contraction runs over
  the SAME t/m dimension in the SAME ascending order → term-for-term identical sum. On the
  GPU the cuBLAS OP_T Dgemm is an fp-accumulation-order variant of the OP_N Dgemm
  (rel-RMS ~1e-14, the documented identical-tolerance lane — NOT a regression).
  Verified via `hexa run` on the mac host (same CPU dispatch as aiden) — no GPU build needed,
  mirroring the established clm_prod_hostfeed_eq.hexa 0-pod methodology.
