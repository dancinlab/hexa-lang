🔴 FINDING — stdlib/ckpt/verifier.hexa  verify_pcc  (the .pcc proof-carrying
            checkpoint header parser): INTEGER-OVERFLOW WRAP bypasses the
            primary structural guard.

  THE PARSER
    .pcc layout = MAGIC + header{version,flags,chunk_size:u32,
    chunk_count:u64,cert_block_len:u32,payload_len:u64} + cert_block +
    (chunk_count × 20-byte dir entries) + payload + trailer. verify_pcc
    reads the header from an untrusted file and computes the layout via
    RAW MULTIPLICATION:
        dir_size       = chunk_count * pcc_dir_entry_size()   // *20
        upper          = chunk_count * chunk_size
        payload_end    = payload_start + payload_len
        expected_total = ... + pcc_trailer_size()
    then gates on the SINGLE primary structural guard
        if expected_total != total_bytes -> ERR_HEADER_CORRUPT.

  THE BUG (CWE-190 -> CWE-125/CWE-787 / DoS)
    A crafted chunk_count near 2^62 makes chunk_count*20 OVERFLOW the
    64-bit signed domain and WRAP, so `expected_total` is a WRAPPED sum.
    A SOLVED instance (Python oracle, s64 model):
        chunk_count = 4392081922311798020   (~2^62.4)
        chunk_size  = 1, cert_block_len = 0, payload_len = chunk_count
      => dir_size       = s64(chunk_count*20) = -6148914691236517072
         payload_start  = -6148914691236517036   (NONSENSE NEGATIVE)
         payload_end    = 176
         expected_total = 200   <-- a 200-byte crafted file PASSES the guard
    The primary defense is DEFEATED by the wrap. Downstream the wrapped
    payload_start/payload_end turn the per-chunk bounds checks
    (`declared_offset < payload_start`, `+len > payload_end`) into no-ops
    (any offset>=0 is < a negative payload_start), and the directory walk
    `while ci < chunk_count` (loop bound = the 4.4e18 chunk_count) can
    index `buf` out of bounds.

  RUNTIME OOB SEMANTICS (probed verbatim, `hexa run`)
    `buf[100]` on a len-3 array → HARD FAULT `index 100 out of bounds
    (len 3)` (process abort), NOT a silent garbage read. So the wrap
    yields a graceful-but-WRONG reject when downstream checks happen to
    catch the nonsense first, and an UNCONTROLLED RUNTIME ABORT (DoS —
    the verifier's whole contract is to return a tamper-code DICT, never
    crash) when a crafted dir/trailer alignment lets the walk advance to
    an out-of-bounds de_off. Either way the wrap-bypass of the structural
    guard is the load-bearing defect.

  THE FIX (defense-in-depth, fail-closed, surgical)
    Every declared region (cert block, chunk directory, payload) is a
    SUBSET of the file, so each field is individually <= total_bytes.
    Bound them BEFORE any multiplication — WRAP-FREE (division for the
    count cap):
        chunk_size      in (0, total_bytes]
        cert_block_len  in [0, total_bytes]
        chunk_count     in [0, total_bytes / DIR_ENTRY_SIZE]   (division)
        payload_len     in [0, total_bytes]
    Reject impossible declarations up front; every subsequent product is
    then bounded by ~total_bytes (and total_bytes^2/20 for upper), far
    under 2^62 for any realistically-sized checkpoint → the layout
    arithmetic CANNOT wrap and the structural guard is no longer
    bypassable.
