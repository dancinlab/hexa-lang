GOAL (g5): for every *_verify / *_validate / signature-check / MAC-check / AEAD-tag /
cert-chain / Finished verifier in the crypto surface, feed a FORGED / TAMPERED /
MALFORMED input and prove the verdict REJECTS it (a verify that ACCEPTS a forgery =

RESULT: 🟢 NO forgery-acceptance bug found. Every audited verifier REJECTS forged /
tampered / malformed input and ACCEPTS valid input. All secret compares are byte-COMPLETE
constant-time (no early-return short-circuit → no timing leak). RSA PKCS#1 v1.5 uses the
strict RIGHT-ANCHORED parse that defeats the BERserk/Bleichenbacher'06 forgery class.
One 🟠 robustness note (missing direct-call sig/pubkey length guard, covered by callers)
and one NON-security stale-compiler interop discrepancy logged honestly.

[6] rsa_pkcs1_sha256_verify (stdlib/crypto/rsa_pkcs1.hexa:167) — X.509 cert sig (RSA-2048)
    MUST reject: BERserk garbage-after-hash forgery, flipped hash, padding hole, wrong
    block-type, <8 FF pad, wrong hash length.
    The EMSA-PKCS1-v1_5 check is STRICT RIGHT-ANCHORED: sep = elen - (DigestInfo+32) - 1
    is FIXED, em[2..sep] must ALL be 0xFF, em[sep]=0x00, then DigestInfo+hash anchored at
    the very END. This is the secure construction (no left-anchored / variable-tail parse),
    so the classic forgeries cannot place a low-exponent perfect-cube garbage tail.
    FORGE (Python port of the EXACT parse + shipping `hexa run` hermetic lock):
      well-formed EM            → accept
      BERserk garbage-tail      → REJECT (hash not at end / sep FF region wrong)
      flipped hash byte         → REJECT
      padding hole (FF→00)      → REJECT
      wrong block-type (01→02)  → REJECT
    modexp uses small public e (square-and-multiply, top-bit search ≤31 bits → e=65537 ok).
    🟢

[7] ed25519_verify (stdlib/crypto/ed25519.hexa:383) — X.509 Ed25519 cert sig
    MUST reject: forged signature, signature over a different message, bad pubkey point.
    Equation is textbook-correct: k=H(R‖A‖M); checks pack(S·B + k·A) == R with A = -A
    (via _unpackneg, which returns [0]=fail on a non-canonical/off-curve pubkey → reject).
    A flipped sig byte changes R or S → the recomputed point ≠ sig[0:32] → reject. 🟢
    🟠 NOTE: ed25519_verify itself has NO `len(sig)==64 / len(pubk)==32` guard. All
    in-tree callers (x509_verify_self_ed25519 :96, x509_chain_verify_ed25519 :40,52) DO
    guard len before calling, so this is a defense-in-depth robustness gap (a direct
    attacker-length call could OOB-read), NOT a forgery-acceptance bug. Flagged for a
    LANE-1/OOB follow-up (OP-104/105 class), not fixed here to keep this round scoped.

[8] p256_verify (stdlib/crypto/p256.hexa:543) — ECDSA-P256 cert sig
    MUST reject: r or s out of [1,n-1], R==infinity, R.x mod n != r, forged (r,s).
    Verbatim checks: r==0→false, s==0→false, r>=n→false, s>=n→false; computes
    R=u1·G+u2·Q, rejects R==O, returns (R.x mod n)==r. Standard correct ECDSA verify. 🟢
    🟠 same direct-call length-guard note as [7] (callers guard).

[9] x509_verify_self_ed25519 (stdlib/crypto/x509_min.hexa:91) — self-signed cert
    MUST reject: wrong pubkey length, wrong sig length, sig not over the cert's TBS.
    Guards len(pk)==32 + len(sig)==64, then ed25519_verify(pk, TBS_bytes, sig) over the
    cert's OWN extracted TBSCertificate — a tampered TBS or substituted key fails. 🟢

[10] x509_chain_verify_ed25519 (stdlib/crypto/x509_chain.hexa:29) — chain to trust anchor
    MUST reject: any cert outside its validity window; any link whose sig does NOT verify
    under its ISSUER's pubkey (next cert up, or the trust anchor for the topmost).
    For each cert: x509_validity_contains(cert, now) must hold (expired → reject) AND
    ed25519_verify(issuer_pub, TBS, sig) must hold (len(issuer_pub)!=32 → reject;
    len(sig)!=64 → reject). The cryptographic binding (sig under issuer key) is the
    forgery gate — a forged intermediate has no valid sig under the real issuer key. 🟢
    NOTE (scope, not a bug): does not enforce issuer-DN == subject-DN name chaining
    (path-building / defense-in-depth); the sig-under-issuer-key check is the actual
    auth gate and is present.

[11] x509_validity_contains (stdlib/crypto/x509_validity.hexa:100) — expiry check
    MUST reject: now < notBefore, or now > notAfter (expired / not-yet-valid).
    Returns time_le(notBefore, now) && time_le(now, notAfter). An expired cert
    (now > notAfter) → second clause false → reject. UTCTime 2000/1950 pivot per RFC. 🟢

[12] hmac_sha256_bytes (stdlib/core/hash/hmac.hexa:158) — HMAC core under [4]
    FIPS 198-1 HMAC = H((K⊕opad)‖H((K⊕ipad)‖m)); SHA-256 core is FIPS 180-4. The
    module's own companion (hmac_test.hexa) cross-checks byte-equal to the runtime
    builtin on empty + "abc". Correct primitive → [4] rejects forged Finished. 🟢
