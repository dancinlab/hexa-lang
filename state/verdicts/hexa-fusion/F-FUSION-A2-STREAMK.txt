KERNEL DESIGN CHOSEN (self/native/hxqwen14b_cuda.cu)
---------------------------------------------------
Design (a) ATOMIC-FREE TWO-PASS (chosen over CUTLASS stream-K (b): the two-pass directly
isolates split-K's NAMED cost — the atomicAdd serialization — by removing the atomic while
keeping split-K's exact K-partition, so a TIE cleanly attributes the residual to a different
cause than the atomic; (b)'s fixed-MAC-tile assignment would conflate load-balance with the
atomic, muddying the attribution).
  PASS 1 _hx_k_sgemm_cm_streamk_partial: identical K-partition to split-K (G near-equal
    HXSK=16-aligned K-chunks, 16x16 output tile, shared-mem K-reuse), but each
    (output-tile, k-chunk) block writes its alpha*partial to a SEPARATE slice
    P[chunk*M*N + col*M + row] of a partials workspace — NO atomics, NO shared cache line
    between the G writers (each chunk's writes are M*N apart -> distinct cache lines).
  PASS 2 _hx_k_sgemm_cm_streamk_reduce: one thread/output element tree-sums its G partials in
    fp32 (contention-free) and folds beta in ONE store: C = sum_g P[g] + beta*C_old. (beta
    folds cleanly here, no pre-scale kernel — unlike split-K's separate betascale pass.)
  Workspace M*N*G floats, cudaMalloc cached & reused across calls (skinny shapes tiny:
  16*4096*16 = 4 MB). G = clamp(k/512,1,32), override HEXA_OWN_GEMM_STREAMK_G.
  Env gate HEXA_OWN_GEMM_STREAMK (NEW) + once-probe [OWN-SGEMM-STREAMK-FIRED]. Dispatch fires
  ONLY for skinny+large-K: (m<=64 || n<=64) && k>=1024, under HEXA_OWN_GEMM_WMMA2, takes
  PRIORITY over split-K when both env set. Gate OFF = byte-identical default (cuBLAS path
  untouched; the WMMA2/splitK paths untouched — stream-K is a new else-if branch ABOVE split-K).

[OWN-SGEMM-STREAMK-FIRED]: FIRED Y — every stream-K arm (gate, pergemm, util, conv, probe). Verbatim:
  "[OWN-SGEMM-STREAMK-FIRED] skinny GEMM -> _hx_k_sgemm_cm_streamk (atomic-free two-pass, G=16,
   m=16 n=8192 k=8192)"  (G varies with k per the clamp formula; G=8 at k=4096)

========================================================================================
§4  FINDING (honest CLOSED-NEGATIVE — a valid result per paper_negative_ok)
========================================================================================
FALSIFIER FALSIFIED (perf axis): the atomic-free two-pass stream-K does NOT close a
measurable further fraction of split-K's named residual. Correctness PASSES (rel-RMS <= 8.2e-7
on dA/dB, CE-descent bit-clean), the kernel FIRES, but per-GEMM dA/dB and full-step steps/s
TIE split-K within noise (-0.2% to -0.5%; +0.8% per-GEMM sum) at BOTH M8192 and M16384.

WHY (the negative RULES OUT one axis): split-K's NAMED residual-of-residual blamed the
atomicAdd SERIALIZATION into the tiny 16-wide output column. This experiment removes the
atomic entirely (each K-chunk -> a disjoint partials slice, no shared cache line) and the
per-GEMM time is UNCHANGED. Therefore the atomic contention was NOT the dominant cost of the
skinny split-K kernel. The two-pass trades atomic contention for an EQUIVALENT cost: an extra
global-memory round-trip (write G*M*N partials to global in pass 1 + read them back in the
pass-2 reduction) on the same tiny output. On these skinny shapes the dominant cost is the
un-vectorized 32-bit global load pattern of the 16x16-tiled partial kernel (cuBLAS uses
128-bit vectorized loads + a more cache-friendly K-partition), NOT the reduction method.
Atomic-reduction and two-pass-reduction are ~equivalent here because the output (m*n*G with
m or n = 16) is small enough that neither the atomic traffic nor the partials traffic
dominates — the MAC-issue + scalar-load bound does.

RULED-OUT AXIS (the disprovable claim this closes): "removing split-K's output-column
atomicAdd recovers a measurable fraction of the per-GEMM gap" — DISPROVEN. The next separable
step for these skinny GEMMs is NOT the reduction strategy (split-K, stream-K, two-pass all
tie) but the PARTIAL-KERNEL INNER LOOP: 128-bit vectorized (float4) global loads + a wider
register-blocked K-tile, i.e. matching cuBLAS's load width — a distinct kernel-engineering
axis, orthogonal to K-partitioning.

ZERO DEFAULT CHANGE: env-gated (HEXA_OWN_GEMM_STREAMK); OFF = cuBLAS byte-identical, and the
existing WMMA2/split-K paths are untouched (stream-K is a new else-if branch above split-K).

VERDICT: 🔴 CLOSED-NEGATIVE. Atomic-free two-pass stream-K TIES split-K (0% further residual
closed; -0.2%/-0.5% steps/s, +0.8% per-GEMM sum) at rel-RMS <= 8.2e-7 PASS, [STREAMK-FIRED] Y.
The split-K named residual-of-residual ("atomicAdd serializes the G writers") is DISPROVEN as
the dominant skinny-GEMM cost — removing the atomic changes nothing. The cost is the
un-vectorized scalar-load inner loop; the next axis is 128-bit vectorized loads, NOT the
K-reduction method. A valid negative result that deterministically rules out the reduction-
strategy axis. Default unchanged (env-gated).
