THE WALL (handoff): the flame CLMConvMoE backward glue
------------------------------------------------------------------------------------------------
A CLMConvMoE MoE block = ModuleList of E ConvExpert, each causal nn.Conv1d(d,d,K). The
backward computes gX (input grad), gW (weight grad), gb (bias grad). The input gradient
  gX[p,ci] = Σ_e Σ_co Σ_{k : t = p + dil*(K-1-k), 0<=t<T}  gY_e[t,co] · W_e[co,ci,k]
in the naive bwd is computed by a SCATTER:  gX[p,ci] += gY_e[t,co]·W_e[co,ci,k]  with
atomicAdd over (e,t,co,k) — many (e,t,co,k) collide on the same (p,ci). That scatter is
(1) serialized on the atomic unit + memory-bound and (2) NON-DETERMINISTIC in accumulation
order → NOT FP64 byte-exact across runs. This is the exact wall FF-VALLEY + MEGASTEP inherit.

------------------------------------------------------------------------------------------------
THE FLASH-MAXSIM CURE (arXiv 2605.29517) — forward-index reuse, destination-owned reduction
------------------------------------------------------------------------------------------------
Reuse the FORWARD index structure to make the backward a DESTINATION-OWNED gather:
  forward read:    p = t - dil*(K-1-k)            (given t,k → p)
  inverse (gather): t = p + dil*(K-1-k),  for each k in [0,K),  valid iff 0<=t<T
A destination-owned gX kernel: thread owns ONE (p,ci); loops e (asc), co (asc), k (asc);
for each k computes t=p+dil*(K-1-k); if 0<=t<T accumulates gY_e[t,co]·W_e[co,ci,k]. FIXED
order (e,co,k) → DETERMINISTIC, ATOMIC-FREE. gW/gb are already destination-owned (one
thread owns one (e,co,ci,k) resp. (e,co) and reduces over t) → no atomics, deterministic.
The inverse-grid index mapping (the named hard part) was the deliverable; it is correct
for multi-tap spans (dil>1) and causal boundaries (validated dil=1 AND dil=2 on CPU first).
