§FINDING (honest, shape-dependent — PARTIAL CONFIRM)
----------------------------------------------------
The falsifier is CONFIRMED for the two shapes where op(A)'s output-row
dimension is large + contiguous (the float4 path actually fires):
  • dA (skinny-N, M=4096): 1.110x scalar->vec → closes 16.0% of the scalar gap.
  • square (2048^3):       1.993x scalar->vec → closes 62.3% of the scalar gap.
Float4 (128-bit) loads DO close a measurable, often large, fraction of the
scalar-load gap A2 named — strongest on the square GEMM (nearly 2x over scalar
split-K, 62% of the way to cuBLAS), at bit-clean rel-RMS (~5e-7, fp32-exact-
class, FAR inside the 3e-3 TF32 bar).

NEGATIVE / RULED-OUT axis (the honest counter):
  • dB (skinny-M, M=16): vec is 0.685x — SLOWER, -89.8% (a regression).
    Root cause: VECW=4 register-blocks ACROSS the output-ROW dim (M). When M=16
    the float4 path can almost never fire (needs row0+3 < M; with only 16 rows
    and 4-row strips it is all boundary/tail) AND the 4-row register blocking
    collapses the already-tiny M-occupancy further. The lever is keyed to a
    LARGE CONTIGUOUS A-row extent; the skinny-M transpose case is the wrong
    regime for it. => Shape-dispatch is required: apply VEC only when m >= a
    threshold (e.g. m >= 64); fall back to scalar split-K for skinny-M.

RULED OUT: "float4 row-blocking is a universal skinny-GEMM win." It is NOT —
it is a win for skinny-N / square (large contiguous M), a LOSS for skinny-M.
The A2 lever is REAL but shape-gated, not unconditional.
