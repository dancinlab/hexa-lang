KERNEL (self/native/hxqwen14b_cuda.cu)
--------------------------------------
_hx_k_sgemm_cm_splitk(tA,tB,M,N,K,alpha,A,lda,B,ldb,C,ldc,G) — col-major cublasSgemm
faithful (C[i+j*ldc] = alpha*sum_l op(A)*op(B) + beta*C). grid.z = G; block (16x16) owns
output tile (blockIdx.x,blockIdx.y); blockIdx.z = which K-chunk. Each block computes a
partial dot over its HXSK-aligned K-slice (shared-mem 16x16 tile, same K-reuse as the
tiled fallback) then atomicAdd(alpha*partial) into C. BETA via a pre-kernel
_hx_k_sgemm_cm_betascale (C = beta*C, or 0 when beta==0) run BEFORE the split blocks —
the simplest correct beta+atomic composition (folding beta into "the first partial" is
racy under out-of-order chunk completion). Summation order differs from sequential -> NOT
bit-identical, but within TF32 tol (verified below). G = clamp(k/512,1,32) by default
(MEASURED Blackwell sweet spot: k=4096->G=8, k=8192->G=16; saturates ~16-32), override
HEXA_OWN_GEMM_SPLITK_G. Env gate HEXA_OWN_GEMM_SPLITK (NEW) + once-probe
[OWN-SGEMM-SPLITK-FIRED]. Dispatch fires ONLY for skinny+large-K: (m<=64 || n<=64) && k>=1024,
and only under HEXA_OWN_GEMM_WMMA2 (the recommended own arm). Gate OFF = byte-identical
default (cuBLAS path unchanged; verified by the default-arm gate run untouched).

[OWN-SGEMM-SPLITK-FIRED]: FIRED in every split-K arm (pergemm, util, gate, conv). Verbatim:
  "[OWN-SGEMM-SPLITK-FIRED] skinny GEMM -> _hx_k_sgemm_cm_splitk (split-K atomicAdd, G=16,
   m=16 n=8192 k=8192)"  (G varies with k per the clamp formula)

§4  FINDING (honest scope)
========================================================================================
CONFIRMED: the named residual WAS the skinny dA/dB (and the K=4096 skinny trio) running a
single sequential K-reduction in the 16x16 tiled fallback -> the GPU is under-occupied
(too few output tiles, each grinding 4096-8192-long K serially). Split-K (partition K into
G chunks, G x more blocks, atomicAdd partials) fills the SMs: per-GEMM dA 0.438->0.238,
dB 0.432->0.252 (each ~-44%), and the full LoRA step ratio improves 1.67x->1.24x @M8192
(1.58x->1.20x @M16384) = 64-66% of the named residual 0.67x gap CLOSED, with correctness
PASS (rel-RMS <= 3e-4 << 3e-3; CE descent matches cuBLAS to ~1e-6) and ZERO default
behavior change (env-gated; OFF = cuBLAS byte-identical).

NOT FULL PARITY (honest residual-of-residual): WMMA2-TUNED+SPLITK is still ~1.20-1.24x
slower steps/s. The remaining ~0.22-0.24x is:
  (a) Per-GEMM, split-K is ~2x off cuBLAS on the skinny shapes (0.24 vs 0.12 ms). cuBLAS's
      skinny path uses vectorized (128-bit) loads, a more cache-friendly K-partition, and
      a reduction with no global atomic contention (our atomicAdd into a tiny 16-wide
      output column serializes G writers on the same cache lines). A two-pass split-K
      (partials buffer + a tree reduction kernel) or stream-K (load-balanced, atomic-free)
      would recover more — a further separable kernel step, NOT a tuning knob.
  (b) The square WMMA2 GEMMs and glue are already at/under cuBLAS, so the residual is now
      ENTIRELY the per-GEMM skinny efficiency, not occupancy. The occupancy axis (which
      split-K targets) is largely EXHAUSTED by G~16.

VERDICT: 🟢 64-66% of the named thru-parity residual 0.67x gap CLOSED by a split-K skinny
own-GEMM. Per-GEMM dA/dB each ~-44%. Full step 1.67x->1.24x @M8192. rel-RMS <= 3e-4 PASS,
CE-descent bit-clean, env-gated (default unchanged). Residual-of-residual NAMED: per-GEMM
skinny efficiency (vectorized loads / atomic-free two-pass or stream-K reduction), ~2x off
cuBLAS on the skinny shapes — a further separable kernel-engineering step.
