F-FUSION-P1D-LLM-SGEMM — HEXA-FUSION Phase 1d: LLM (hxqwen14b) FP32 own-GEMM
================================================================================
Goal: own the cuBLAS Sgemm in the hxqwen14b LoRA fwd/bwd path so the LLM
workload is 100% device-owned (no cuBLAS GEMM), mirroring clm Phase 1a/1c
(FP64 own-GEMM, F-FUSION-P1-OWN-GEMM-CORRECTNESS). Bar = within fp32 tolerance
vs cuBLAS oracle (NOT bit-exact). g5-HONEST: measured numbers verbatim.

WHAT WAS AUTHORED (env-gated HEXA_OWN_GEMM; OFF == byte-identical fallthrough)
-----------------------------------------------------------------------------
- self/native/hxqwen14b_cuda.cu (nvcc TU): general col-major FP32 kernel
    __global__ _hx_k_sgemm_cm_v54(tA,tB,M,N,K,alpha,A,lda,B,ldb,beta,C,ldc)
    faithful to cublasSgemm (C[i+j*ldc]=alpha*Sum_l opA*opB + beta*C), + an
    extern "C" host launcher _hx_own_sgemm_cm_launch(...) (the <<<>>> launch),
    + base-path shim hxqwen_sgemm_base over g_cublas_handle. Both
    _sgemm_rowmajor_xwt / _xw frozen-base wrappers routed through it.
- self/native/hxqwen14b_emit.hexa (emits hxqwen14b.c, gcc TU): host dispatch
    shim hxqwen_sgemm(...) calling the extern launcher when HEXA_OWN_GEMM set,
    else cublasSgemm(g_cublas). ALL 7 LoRA fwd/bwd cublasSgemm(g_cublas,...)
    sites + the base_gemm site mechanically renamed to hxqwen_sgemm(...) (8
    call sites; the only residual cublasSgemm is the shim fallthrough).
  NOTE: the kernel/<<<>>> live in the .cu (nvcc) because hxqwen14b.c is a gcc
  TU (host control flow only) -> a kernel launch there is a hard gcc parse
  error; the gcc shim calls the extern "C" launcher. [OWN-SGEMM-FIRED] probe.
