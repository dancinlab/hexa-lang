HONEST FINDING (d6) — #1215 f64 exp() underflow garbage, kernel-side guard
  The emitted f64 exp() is accurate to ~1e-15 rel down to x≈−700, but for
  x < ~−745 (f64 underflow boundary) its 2^k bit-pattern path (k+1023 → negative,
  shl.b64 corruption) returns GARBAGE (~±1e292) where libm returns 0. Measured:
    exp(-700) gpu=9.86e-305 (rel 0)  vs  exp(-746) gpu=-3.36e+292 (ref 0).
  A Gaussian δ_σ exponent −0.5·z² routinely reaches −1000s (far δ-tail). FIX:
  kernel guards `if exponent > -700 { exp() } else { 0 }` — physically correct
  (a δ-tail that far out IS zero) and matches the CPU-ref libm. This is the
  right numerics regardless; the codegen-intrinsic gap is filed to
  inbox/patches/nvptx-expf64-underflow-clamp.md for the upstream exp() fix.
