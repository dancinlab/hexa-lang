2) ROOT CAUSE  (asm-confirmed — the escape lattice is UNSOUND for aliasing)
--------------------------------------------------------------------------------
A typed-prim [i64]/[i32] array lowers to TWO MIR locals that SHARE one buffer:
  T = storage  (STMT_ASSIGN op="array_lit")            <- the HexaArr* buffer
  X = handle   (STMT_ASSIGN op="let"  X = T)           <- a HexaVal copy of T
The whole-function escape scan (compiler/codegen/x86_64_linux.hexa ~L797-829)
marks T and X packed TOGETHER, but then CLEARS the packed bit PER-LOCAL,
INDEPENDENTLY, and its "safe use" set at arg-position-0 includes op=="let".
Consequences (both measured, both the SAME class):

  kc_alias (ⓒ):  `let ys = xs`  — xs (the handle X) appears as args[0] of a
    `let`, which the scan treats as SAFE, so xs STAYS PACKED. The alias ys is
    NOT marked packed (its let_src is a handle, not an array_lit dst) -> ys is
    BOXED. Emit (kc_alias.on.s): xs read via packed `arrpk get` (L100-108),
    ys read via BOXED `hexa_index_get` (L94, L135) ON THE SAME packed buffer ->
    stride-16/tagged read of a stride-8/untagged buffer -> HexaVal tag
    corruption -> println prints "<value>999064" instead of 2126.

  ka_arg_escape (ⓐ):  `sumarr(xs, N)` — the handle X escapes via the call, so X
    is cleared (boxed), but the STORAGE T it aliases is used only in the safe
    `let X=T` and is NOT cleared -> T emits packed `hexa_arr_i64_new`
    (ka_arg_escape.on.s L104). sumarr() reads its param via BOXED
    `hexa_index_get` (L46). So a packed buffer is read boxed inside the callee
    -> miscompile (sum 4096 -> 4095).

INVARIANT VIOLATED: a packed array and a boxed alias/handle/param of the SAME
underlying buffer must never coexist. The current scan can leave one member of
an aliasing pair packed while the other is boxed (it clears T and X — and any
`let`-copy alias — independently, and counts `let` as a non-escaping use).

Why k0/kb/kd/ke/kf pass: k0 has no escape/alias (coherent pack, fast path is
bit-correct — 4544==4544, the lever itself is sound when no aliasing occurs);
kb's escaping local is voided AND its receiver is a call-result (never packed);
kd is a global (separate id space, never packed); ke is untyped (type_id 0, not
101/102, never packed); kf re-binds via array_lit (stays self-consistent).
